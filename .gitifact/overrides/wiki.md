## 운영 지침

### 구성

위키는 다음 세 부분으로 고정한다. 새 최상위 폴더나 루트 페이지는 만들지 않는다. 제품 소개(무엇이고 누구를 위한 것인지, 원칙, 범위 밖, 용어)는 위키가 아니라 저장소 루트 README.md에 있고 원본은 `packages/intro`다. 위키에 README.md를 두지 않는다.

| 경로 | 역할 |
| --- | --- |
| `ARCHITECTURE.md` | 아키텍처 안내. 시스템 전체의 목표·제약·구성 요소·런타임 흐름·품질 기준을 한 문서로 정의하는 최상위 지침. 세부는 references와 adr을 단일 원본으로 가리킨다 |
| `references/` | 참고 표준. 코드 스타일, 계약, 문구, 저장 규약, 화면 규칙처럼 여러 기능에 걸치는 횡단 관심사를 주제 하나당 한 페이지로 둔다. 프론트·백엔드 같은 영역 폴더는 필요할 때만 만든다 |
| `adr/` | 아키텍처 결정 기록. `NNNN-slug.md`, 네 자리 일련번호는 늘리기만 한다 |

### ARCHITECTURE.md

절 구성은 소개와 목표 / 제약 / 컨텍스트와 범위 / 솔루션 전략 / 구성 요소와 의존성 / 런타임 흐름 / 배포와 운영 / 공통 개념과 참고 표준 / 아키텍처 결정 / 품질 기준과 검증이다. 필요 없는 절은 뺀다. 각 절은 결론만 적고 세부 규칙은 references 페이지로 링크한다. 같은 내용을 두 곳에 쓰지 않는다.

### references

한 페이지는 한 주제만 다룬다. 첫 문단에 이 페이지가 무엇을 정하는지 쓰고, 규칙마다 이유를 붙인다. ARCHITECTURE.md의 "공통 개념과 참고 표준" 표에 링크를 올려야 페이지로 인정한다. 표에 없는 페이지는 만들지 않는다.

### adr

ADR의 대상은 ARCHITECTURE.md와 references 두 곳이다. 그 내용이 달라지거나, 두 곳이 아직 다루지 않는 설계가 새로 들어오면 해당 페이지를 고치거나 만들고 같은 저장에서 ADR을 하나 추가한다. ADR은 "왜 그렇게 정했는가"를, 페이지는 "지금 무엇을 따르는가"를 담는다. 기존 ADR은 고치지 않고 새 ADR이 이전 것을 대체한다고 적는다. 형식은 다음과 같다.

```markdown
# 결정 NNNN. 제목

상태: 채택 | 제안 | 대체됨(→ NNNN) · YYYY-MM-DD

## 맥락
어떤 문제와 제약이 있었는가.

## 결정
무엇을 어떻게 하기로 했는가.

## 결과
얻는 것과 감수하는 것, 기각한 대안과 이유.
```

ADR을 쓰는 기준은 ARCHITECTURE.md나 references에 반영될 만큼 여러 기능에 걸치는 선택이다. 한 기능 안에서만 유효한 구현 선택은 그 기능의 design.md에 두고 ADR을 만들지 않는다.

### 에이전트 행동

- 요구사항·설계를 쓰기 전에 루트 README.md와 ARCHITECTURE.md를 읽고, 작업 영역의 references 페이지를 읽는다.
- 대화에서 기준이 새로 생기거나 바뀌면 ARCHITECTURE.md 또는 references 페이지를 고치자고 제안하고, 그 변경에 맞는 ADR 추가를 함께 제안한다. 동의를 받으면 `spec save`로 저장하고 커밋 때 이유를 붙인다.
- references 안에 페이지를 더하는 것은 진행하고 알린다. 구성 표를 벗어나는 변경은 이 파일을 먼저 고칠지 사용자와 정한다.
- 요청이 루트 README.md의 범위 밖이거나 원칙과 어긋나면 진행 전에 알린다.

### 톤앤매너

- 짧고 담백하게 쓴다. 목적과 동작을 먼저 쓰고 근거와 대가를 뒤에 붙인다.
- 문장은 평서형 "~다"로 끝낸다. 명령·권유·감탄을 쓰지 않는다.
- 과장된 확신, 반복 강조, 구호를 쓰지 않는다. "반드시", "절대", "완벽"은 실제 제약일 때만 쓴다.
- 확정된 내용과 제안·미결을 구분한다. 구현되지 않은 것은 계획이라고 표시한다.
- 날짜별 작업 기록은 두지 않는다. 그것은 docs/와 Git 이력의 몫이다.
- 용어는 루트 README.md와 기존 페이지에서 쓰는 이름을 따르고 같은 것을 다른 이름으로 부르지 않는다.
- 표는 비교할 것이 있을 때만 쓰고, 목록은 항목이 서로 대등할 때만 쓴다.
