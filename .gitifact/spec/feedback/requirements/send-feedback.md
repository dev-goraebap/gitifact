Gitifact를 쓰는 사용자로서, GitHub 이슈 양식을 따로 찾아 쓰지 않고도 도구의 버그와 개선 제안을 개발자에게 전하기 위해 대화에서 부탁하면 에이전트가 이슈를 대신 남겨 주기를 바란다.

### 범위와 제약

이슈는 외부로 나가는 글이다. 에이전트는 제목과 본문 초안을 사용자에게 보여 주고 확인받은 뒤에만 보낸다. CLI는 본문 끝에 Gitifact 버전, 운영체제, Node 버전, 저장 규약 버전만 덧붙이고, 프로젝트 파일이나 문서 내용을 자동으로 넣지 않는다. GitHub 토큰을 받거나 보관하지 않는다.

### 수용 조건

1. 조건: 사용자가 Gitifact의 버그나 개선을 남겨 달라고 부탁합니다.
   기대 동작: 에이전트가 종류(버그·개선)와 제목·본문 초안을 보여 주고, 사용자가 확인한 뒤에만 보냅니다.
2. 조건: GitHub CLI(`gh`)가 설치되어 로그인되어 있습니다.
   기대 동작: 사용자 계정으로 Gitifact 저장소에 이슈가 만들어지고 이슈 주소가 출력됩니다.
3. 조건: `gh`가 없거나 로그인되어 있지 않습니다.
   기대 동작: 제목과 본문을 채운 새 이슈 작성 페이지 주소가 출력되고, 사용자가 브라우저에서 제출합니다. 본문이 길어 주소에 다 담기지 않으면 잘렸다는 사실과 전체 본문을 함께 알립니다.
4. 조건: 보내기 전에 미리 봅니다.
   기대 동작: 보낼 방법과 제목, 환경 정보를 붙인 본문을 보이고 아무것도 보내지 않습니다.
5. 조건: 종류가 버그·개선이 아니거나 제목이 비었거나 여러 줄입니다.
   기대 동작: 보내지 않고 입력 오류로 알립니다.
