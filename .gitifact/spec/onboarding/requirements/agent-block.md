에이전트와 제품을 만드는 사용자로서, 매 세션마다 기록 방법을 다시 설명하지 않기 위해 현재 세션과 이후 세션 모두에서 프로젝트 지침 파일의 GITIFACT 블록에 따라 요구사항을 정리하고 싶다. 프로젝트에 새로 참여한 팀원도 같은 방식으로 일하도록, CLI가 없는 환경에서 설치로 이어지기를 원한다.

### 범위와 제약

- 블록은 `GITIFACT:START`와 `GITIFACT:END` 마커 사이에 쓰고, 마커 바깥의 사용자 내용은 보존한다.
- 블록은 규칙의 요약이고, 상세 형식은 `gitifact guide show <topic>`이 준다. 별도 스킬 파일은 설치하지 않는다.
- 블록은 Markdown으로 렌더링해도 제목·목록·표·구분선이 그대로 읽히고, 줄이 한 문단으로 합쳐지지 않는다.
- 블록에는 버전을 적지 않는다. 프로젝트가 기준으로 삼는 CLI 버전과 블록 언어는 프로젝트 설정에 둔다.
- 원본은 AGENTS.md 하나이고, 같은 블록을 두 파일에 복제하지 않는다.
- 에이전트는 사용자에게 설치를 떠넘기지 않는다. 설치 허용을 물을 때는 정확한 명령을 담는다(에이전트 도구의 자동 권한 검사는 구체적인 명령을 허용한 경우에만 통과시킨다).
- 도입 프롬프트는 전역 설치 뒤 `init`을 실행하도록 안내한다.

### 기본 흐름

1. 에이전트가 `gitifact init`을 실행한다.
2. 시스템은 AGENTS.md·CLAUDE.md·.cursorrules 같은 지침 파일이 있으면 그 파일에, 없으면 새 AGENTS.md에 블록을 쓴다. 다른 지침 파일을 가져오기만 하는 파일에는 쓰지 않는다.
3. 블록을 AGENTS.md에 썼는데 Claude용 지침 파일이 없으면, 시스템은 AGENTS.md를 가져오는 루트 CLAUDE.md를 함께 만든다.
4. 시스템은 프로젝트 설정에 실행 중인 CLI 버전과 블록 언어를 적는다.
5. 에이전트는 그 블록을 현재 세션에서 읽고 따른다.
6. 이후 세션의 에이전트는 도구가 자동으로 읽는 지침 파일에서 블록을 읽고, 전역 `gitifact`로 같은 방식으로 기록한다.

### 대체 흐름

- **A1. 다시 실행하거나 CLI를 업데이트함** (1단계에서)
  1. 시스템은 마커 사이만 교체하고 바깥 내용은 그대로 둔다.
- **A2. 마커 짝이 맞지 않음** (2단계에서)
  1. 시스템은 아무 파일도 쓰지 않고 거부한다.
- **A3. 블록을 제거함** (1단계에서, `--remove-agents`)
  1. 시스템은 마커 사이를 지우고 사용자 내용은 남긴다.
  2. 그래서 AGENTS.md가 지워지면, `init`이 만든 그대로인 CLAUDE.md도 함께 지운다. 사용자가 내용을 더한 CLAUDE.md는 남긴다.
- **A4. Claude용 지침 파일이 이미 있음** (3단계에서)
  1. CLAUDE.md나 .claude/CLAUDE.md가 있으면 새로 만들지 않고 기존 파일을 보존한다.
- **A5. 팀원의 환경에 `gitifact`가 없음** (6단계에서)
  1. 에이전트는 설정에 적힌 버전의 전역 설치 명령(`npm install -g gitifact@<버전>`)을 그대로 보여 주며 실행해도 되는지 묻는다.
  2. 사용자가 "네"처럼 짧게 허용해도 에이전트가 직접 설치한다.
  3. 에이전트 도구가 실행을 막으면 그 도구의 승인 창이나 권한 설정으로 승인을 요청한다. 문서 ID 발급·검사·커밋을 대신하거나 완료했다고 보고하지 않는다.
- **A6. Windows PowerShell이 스크립트 실행을 막음** (A5에서)
  1. 에이전트는 `npm.cmd`·`gitifact.cmd`로 실행한다. 시작하기도 사람에게 같은 방법을 안내한다.
- **A7. 전역 `gitifact`가 설정의 버전과 다름** (6단계에서)
  1. 명령마다 두 버전을 알리는 안내가 나오고, 에이전트는 사용자에게 업데이트 여부를 묻는다.
- **A8. 이전 버전의 CLI로 초기화함** (4단계에서)
  1. 초기화 결과가 새 버전이 있다는 사실과 설치 명령을 알린다. 새 버전을 확인하지 못해도 초기화는 이어간다.
- **A9. 팀원마다 CLI 표시 언어가 다름** (A1에서)
  1. 블록은 설정에 적힌 언어로 유지된다. `--lang`을 지정한 경우에만 그 언어로 바뀌고 설정도 함께 바뀐다.
- **A10. 프로젝트가 별도 실행 방법을 지정함** (6단계에서)
  1. 에이전트는 프로젝트 지침의 실행 방법을 우선한다. 프로젝트 의존성 추가나 전역 설치를 기본 도입의 필수 단계로 요구하지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 사용자가 도입 프롬프트를 전달하고 에이전트가 `gitifact init`을 실행합니다.
   기대 동작: 기존 지침 파일이 있으면 그 파일에, 없으면 새 AGENTS.md에 블록을 쓰고, 가져오기만 하는 파일에는 쓰지 않습니다. 에이전트는 그 블록을 현재 세션에서도 읽습니다.
2. 경로: 기본 흐름
   조건: AGENTS.md로 도입한 프로젝트에 Claude Code를 쓰는 팀원이 참여합니다.
   기대 동작: `init`이 함께 만든 CLAUDE.md를 통해 Claude Code도 AGENTS.md의 블록과 프로젝트 지침을 읽습니다.
3. 경로: 기본 흐름, A1
   조건: CLI를 업데이트한 뒤 `init`을 다시 실행합니다.
   기대 동작: 마커 사이만 바뀌고 사용자가 쓴 내용은 그대로입니다.
4. 경로: 기본 흐름, A2
   조건: 지침 파일의 마커 짝이 맞지 않습니다.
   기대 동작: 아무 파일도 쓰지 않고 거부합니다.
5. 경로: A3
   조건: `--remove-agents`로 블록을 제거해 AGENTS.md가 삭제됩니다.
   기대 동작: `init`이 만든 그대로인 CLAUDE.md도 함께 삭제하고, 사용자가 내용을 더한 CLAUDE.md나 AGENTS.md가 남으면 CLAUDE.md를 그대로 둡니다.
6. 경로: 기본 흐름, A4
   조건: CLAUDE.md나 .claude/CLAUDE.md가 이미 있습니다.
   기대 동작: 새로 만들지 않고 기존 파일을 보존합니다.
7. 경로: 기본 흐름, A5
   조건: 블록이 있는 프로젝트에 참여한 팀원의 환경에 `gitifact` 명령이 없습니다.
   기대 동작: 에이전트가 정확한 설치 명령을 보여 주며 묻고, 짧은 허용에도 직접 설치합니다. 도구가 막으면 그 도구의 승인을 요청하고, ID 발급·검사·커밋을 대신하거나 완료로 보고하지 않습니다.
8. 경로: 기본 흐름, A5, A6
   조건: Windows PowerShell에서 스크립트 실행이 막혀 npm이나 gitifact가 로드되지 않습니다.
   기대 동작: 에이전트는 `npm.cmd`·`gitifact.cmd`로 실행합니다.
9. 경로: 기본 흐름, A7
   조건: 전역 `gitifact`가 설정에 적힌 버전과 다릅니다.
   기대 동작: 명령마다 두 버전을 알리는 안내가 나오고, 에이전트가 업데이트 여부를 묻습니다.
10. 경로: 기본 흐름, A8
   조건: 에이전트가 이미 설치된 이전 버전으로 초기화합니다.
   기대 동작: 새 버전과 설치 명령을 알리고, 확인하지 못해도 초기화합니다. 설정에 실행 중인 CLI 버전과 블록 언어를 적습니다.
11. 경로: 기본 흐름, A1, A9
   조건: 표시 언어가 다른 팀원이 `update`나 `init`을 다시 실행합니다.
   기대 동작: 블록은 설정의 언어로 유지되고, `--lang`을 지정한 경우에만 바뀌며 설정도 함께 바뀝니다.
12. 경로: 기본 흐름, A10
   조건: 프로젝트 지침이 로컬 설치본이나 전역 명령 등 별도 실행 방법을 지정합니다.
   기대 동작: 에이전트는 프로젝트 지침을 우선하고, 의존성 추가나 전역 설치를 필수로 요구하지 않습니다.
