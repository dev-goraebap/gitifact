기존 또는 새 프로젝트의 사용자로서, 현재 작업을 보존하면서 이후의 기록을 쌓기 위해 Git 저장소에 도입 기준선을 설정하고 Gitifact 사용을 시작하고 싶다.

### 범위와 제약

- 관리 단위는 Git 저장소 하나다. 여러 저장소를 묶는 것은 범위 밖이다.
- 초기화는 설정, 도입 기준선, `.gitifact` 안의 줄바꿈 규칙만 만든다.
- 기존 작업·브랜치·worktree와 staging을 건드리지 않고, 초기화로 커밋하지 않는다.
- 사용자의 루트 `.gitattributes`와 `.gitifact` 밖 파일은 건드리지 않는다.

### 사전 조건

- 사용자가 Git 저장소에서 작업하고, 그 저장소에 Gitifact 설정이 없다.

### 기본 흐름

1. 사용자가 에이전트에게 Gitifact 도입을 부탁한다.
2. 에이전트가 `gitifact init`을 실행한다.
3. 시스템은 설정(`.gitifact/config.json`)을 만들고, 지금 HEAD 커밋을 도입 기준선으로 적는다.
4. 시스템은 `.gitifact` 안의 문서를 LF로 두는 줄바꿈 규칙(`.gitifact/.gitattributes`)을 만든다.
5. 시스템은 에이전트 지침 블록을 설치하고(현재 세션과 이후 세션의 지침 연결), 만든 것을 알린다.

### 대체 흐름

- **A1. 첫 커밋이 없음** (3단계에서)
  1. 시스템은 기준선을 빈 이력으로 적고 초기화를 이어간다.
- **A2. 이미 초기화된 프로젝트** (3단계에서)
  1. 기존 설정과 명시적 전환을 따른다.

### 사후 조건

- 작업 폴더의 기존 변경과 staging은 그대로이고, 새 커밋은 생기지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 변경과 staging이 있는 Git 저장소에 처음 도입합니다.
   기대 동작: 설정과 도입 기준선, 줄바꿈 규칙이 생기고, 기존 변경과 staging은 그대로이며 커밋하지 않습니다.
2. 경로: 기본 흐름, A1
   조건: 커밋이 하나도 없는 새 저장소에 도입합니다.
   기대 동작: 기준선을 빈 이력으로 두고 초기화합니다.
3. 경로: 기본 흐름
   조건: 도입 뒤 Windows와 Mac 사용자가 같은 문서를 고칩니다.
   기대 동작: 문서는 어느 OS에서든 LF로 저장되고 꺼내져, 줄바꿈만 바뀐 변경이 이력에 섞이지 않습니다. 루트 `.gitattributes`는 바뀌지 않습니다.
