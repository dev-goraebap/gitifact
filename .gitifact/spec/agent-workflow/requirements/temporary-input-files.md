에이전트와 제품을 만드는 사용자로서, 에이전트가 남긴 파일 중 무엇을 지워도 되는지 직접 가려내지 않기 위해 커밋에 쓴 입력 파일이 프로젝트에 쌓이지 않고 저절로 정리되기를 원한다.

### 범위와 제약

- 입력 파일의 위치는 CLI가 정해 `changes list` 결과로 알려 준다.
- 기본은 프로젝트 밖의 운영체제 임시 폴더이고, 그곳에 쓸 수 없는 환경에서는 Git이 무시하는 `.gitifact/tmp/`를 쓴다.
- CLI는 자신이 알려 준 폴더 안의 파일만 지운다.
- 빌드·테스트 로그처럼 gitifact 명령과 무관한 에이전트 산출물은 범위에 넣지 않는다.

### 기본 흐름

1. 에이전트가 `changes list`를 실행한다.
2. CLI가 입력 파일 폴더를 준비하고, 7일 넘게 지난 파일을 정리한 뒤, 결과에 커밋 입력 파일 경로를 알린다.
3. 에이전트가 그 경로에 커밋 입력을 쓴다.
4. 에이전트가 `changes commit --file <경로>`를 실행한다.
5. 커밋이 성공하면 CLI가 입력 파일을 지우고 결과에 삭제 여부를 표시한다.

### 대체 흐름

- **A1. 운영체제 임시 폴더에 쓸 수 없음** (2단계에서)
  1. CLI가 `.gitifact/tmp/`를 경로로 알린다. Git이 무시하므로 Git 상태에 새 파일이 나타나지 않는다.
- **A2. 커밋이 실패했거나 dry-run이거나 결과가 불확실함** (5단계에서)
  1. CLI는 입력 파일을 남긴다.
  2. 에이전트가 원인을 고친 뒤 같은 입력으로 4단계를 다시 실행한다.
- **A3. 입력 파일이 알려 준 폴더 밖에 있음** (4단계에서)
  1. 커밋이 성공해도 CLI는 그 파일을 지우지 않는다.
- **A4. 커밋 입력이 짧음** (3단계에서)
  1. 에이전트가 파일을 쓰지 않고 표준 입력으로 넘긴다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 에이전트가 `changes list`를 실행합니다.
   기대 동작: 결과에 커밋 입력 파일 경로가 포함되고 그 폴더가 준비됩니다.
2. 경로: 기본 흐름
   조건: 알려 준 폴더에 7일 넘게 지난 파일이 있습니다.
   기대 동작: 다음 `changes list` 때 그 파일을 정리합니다.
3. 경로: 기본 흐름
   조건: 알려 준 경로의 입력으로 커밋이 성공합니다.
   기대 동작: CLI가 입력 파일을 지우고 결과에 삭제 여부를 표시합니다.
4. 경로: 기본 흐름, A1
   조건: 운영체제 임시 폴더에 쓸 수 없는 환경입니다.
   기대 동작: `.gitifact/tmp/`를 경로로 알려 주며 Git 상태에 새 파일이 나타나지 않습니다.
5. 경로: 기본 흐름, A2
   조건: 커밋이 실패했거나 dry-run이거나 결과가 불확실한 커밋입니다.
   기대 동작: 입력 파일을 남겨 원인을 고친 뒤 같은 입력으로 다시 실행할 수 있게 합니다.
6. 경로: 기본 흐름, A3
   조건: 입력 파일이 알려 준 폴더 밖에 있습니다.
   기대 동작: 명령이 성공해도 그 파일을 지우지 않습니다.
7. 경로: A4
   조건: 커밋 입력이 짧습니다.
   기대 동작: 파일 대신 표준 입력으로도 넘길 수 있습니다.
