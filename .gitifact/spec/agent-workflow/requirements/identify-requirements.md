에이전트와 제품을 만드는 사용자로서, 별도의 기록 방법을 배우지 않고 개발에 집중하기 위해 대화에서 드러난 요구사항을 에이전트가 정리해 주기를 원한다.

### 범위와 제약

- 사용자는 방법론이나 기록 명령을 배우지 않고 제품 개발에 집중한다.
- 에이전트가 대화에서 제품 동작과 제약을 식별해 기록한다. CLI는 다른 앱의 대화를 감시하지 않는다.
- 함수 이름 변경 같은 구현 변경과 푸시 같은 작업 지시는 요구사항이 아니다.

### 기본 흐름

1. 사용자가 대화에서 기능이나 제품 제약을 요청한다.
2. 에이전트가 기존 명세를 읽고 충돌하는지 확인한다.
3. 에이전트가 요청을 요구사항으로 정리하고, 새 기능이면 요구사항을 바탕으로 구현 설계도 함께 쓴다.
4. 에이전트가 기존 문서 중 필요한 부분을 갱신하고 `check`로 확인한다.

### 대체 흐름

- **A1. 요청이 구현 변경이나 작업 지시임** (1단계에서)
  1. 에이전트는 요구사항으로 등록하지 않고 작업만 수행한다.
- **A2. 사용자가 요구사항만 요청함** (3단계에서)
  1. 에이전트는 설계를 쓰지 않고 요구사항만 정리한다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 사용자가 기능이나 제품 제약을 요청합니다.
   기대 동작: 에이전트는 관련 명세를 정리하고, 새 기능이면 설계도 함께 씁니다.
2. 경로: 기본 흐름, A1
   조건: 사용자가 함수 이름 변경이나 푸시를 요청합니다.
   기대 동작: 제품 요구사항으로 등록하지 않습니다.
3. 경로: 기본 흐름, A2
   조건: 사용자가 새 기능의 요구사항만 정리해 달라고 합니다.
   기대 동작: 에이전트는 요구사항만 쓰고 설계는 쓰지 않습니다.
