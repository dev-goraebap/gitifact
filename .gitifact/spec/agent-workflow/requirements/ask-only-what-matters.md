에이전트와 제품을 만드는 사용자로서, 개발 흐름을 이어 가면서 의도를 정확히 전달하기 위해 필요한 질문에만 답하고 작업하는 영역부터 요구사항을 구체화하고 싶다.

### 범위와 제약

- 초기 대화에서 대상 사용자·목적·핵심 흐름·실패 조건을 파악한다.
- 이미 설명한 내용을 반복 질문하지 않는다.
- 기록 승인 절차를 강제하지 않는다.

### 기본 흐름

1. 사용자가 작업을 요청한다.
2. 에이전트가 대화와 기존 명세에서 대상 사용자·목적·핵심 흐름·실패 조건을 파악한다.
3. 에이전트가 변경하는 영역의 요구사항부터 정리하고 작업한다.

### 대체 흐름

- **A1. 제품 의미가 모호함** (2단계에서)
  1. 에이전트가 결정에 필요한 질문만 한다.
  2. 답을 기다리는 동안 그 결정에 의존하지 않는 작업은 진행한다.
  3. 답을 받으면 3단계로 이어 간다.
- **A2. 이미 설명한 내용임** (2단계에서)
  1. 에이전트는 다시 묻지 않고 대화와 문서에서 읽은 내용으로 진행한다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 일반 유지보수 작업을 요청합니다.
   기대 동작: 에이전트는 프로젝트 전체가 아니라 변경하는 영역부터 요구사항을 정리합니다.
2. 경로: 기본 흐름, A1
   조건: 제품 의미가 모호합니다.
   기대 동작: 결정에 필요한 질문을 하고 독립적인 작업은 진행합니다.
3. 경로: 기본 흐름, A2
   조건: 사용자가 앞서 설명한 내용과 관련된 작업을 요청합니다.
   기대 동작: 같은 내용을 다시 묻지 않습니다.
