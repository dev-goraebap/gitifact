프로젝트 참여자로서, 작업할 기능의 요구사항과 구현 방향을 함께 이해하기 위해 관련 명세를 기능별 Markdown 문서로 읽고 관리하고 싶다.

### 범위와 제약

- 관련 요구사항을 응집된 기능 폴더로 묶는다.
- 기능 소개는 `index.md`에, 요구사항은 하나를 파일 하나로 `requirements/` 아래에 둔다.
- 구현 설계는 같은 기능의 `design/` 아래에 둔다. 작업 문서는 관리하지 않는다.
- 코드 모듈이나 DDD 계층을 강제하지 않는다.
- 같은 요구사항의 원본을 다른 곳에 따로 두지 않는다.

### 기본 흐름

1. 에이전트가 새 요구사항을 정리한다.
2. 에이전트가 `specs list`로 기존 기능을 보고, 요구사항이 들어맞는 기능 폴더를 고른다.
3. 에이전트가 `specs new`로 그 폴더의 `requirements/` 아래에 요구사항 파일을 더한다.

### 대체 흐름

- **A1. 들어맞는 기능이 없음** (2단계에서)
  1. 에이전트가 `specs new`로 새 기능 폴더와 `index.md`를 만든다.
  2. 3단계로 돌아가 그 폴더에 요구사항을 더한다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 기존 기능과 관련된 요구사항이 추가됩니다.
   기대 동작: 그 기능 폴더에 요구사항 파일을 더하고, 같은 요구사항의 원본을 다른 곳에 따로 두지 않습니다.
2. 경로: 기본 흐름, A1
   조건: 기존 기능과 별개인 요구사항이 추가됩니다.
   기대 동작: 새 기능 폴더를 만들고 그 아래에 요구사항 파일을 둡니다.
