프로젝트 참여자로서, 문서가 재구성돼도 같은 요구사항의 맥락을 잃지 않기 위해 제목이나 소속 기능이 바뀐 요구사항을 동일한 식별자로 추적하고 싶다.

### 범위와 제약

- 기능은 S-, 요구사항은 R-, 설계는 D-, 지침은 I- 뒤에 난수를 붙여 식별한다. 0.8.0 이전의 위키 페이지는 W-다.
- 난수는 소문자 base32 10자다.
- ID는 CLI만 발급하고 파일의 프론트매터에 둔다.
- 기능 이름을 요구사항 ID에 포함하지 않는다.

### 기본 흐름

1. 에이전트가 `specs new`로 문서를 만든다.
2. CLI가 ID를 발급해 프론트매터에 쓴다.
3. 에이전트가 문서의 제목이나 파일 이름을 바꾸거나, 파일을 다른 기능 폴더로 옮긴다.
4. Gitifact가 같은 ID의 문서를 같은 요구사항으로 추적한다.

### 대체 흐름

- **A1. 요구사항을 지움** (3단계에서)
  1. 지운 요구사항의 ID는 이력에 남고, 다른 요구사항에 다시 쓰지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 같은 요구사항의 제목이나 파일 이름이 바뀌거나 파일이 다른 기능 폴더로 옮겨집니다.
   기대 동작: R-ID를 유지하고 새 위치에서도 같은 요구사항으로 추적합니다.
2. 경로: 기본 흐름, A1
   조건: 요구사항을 지운 뒤 새 요구사항을 만듭니다.
   기대 동작: 새 요구사항은 새 ID를 받고, 지운 요구사항의 ID를 재사용하지 않습니다.
