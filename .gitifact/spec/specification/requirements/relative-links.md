문서를 쓰는 사용자로서, 에디터와 GitHub에서 쓰던 파일 링크 방식을 바꾸지 않고도 브라우저에서 문서 사이를 오가기 위해 저장소 상대 경로 링크를 그대로 쓰고 싶다.

### 범위와 제약

- 요구사항·설계·지침 본문의 링크는 그 파일 기준 상대 경로다.
- CLI는 원문을 바꾸지 않고, 브라우저가 링크를 그릴 때 대상을 해석한다.
- 대상이 없는 링크는 저장·커밋을 막지 않고 경고한다.

### 기본 흐름

1. 사용자가 문서 본문에 다른 문서나 에셋으로 가는 상대 경로 링크를 쓴다.
2. 에이전트가 `check`로 확인하고, 대상이 있으므로 경고가 없다.
3. 참여자가 브라우저에서 링크를 누르면 대상 문서나 에셋으로 간다.

### 대체 흐름

- **A1. 링크 대상이 저장소에 없음** (2단계에서)
  1. `check`가 문서 경로와 링크를 담은 경고를 내고, `changes list`가 경고 수를 알린다.
  2. 저장과 커밋은 막지 않는다.
- **A2. 에셋이나 문서의 파일 이름을 바꿈** (1단계 뒤)
  1. 옛 이름을 가리키던 링크가 A1의 경고로 드러난다.
  2. 사용자가 문서의 링크를 고쳐 해소한다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 문서가 다른 문서를 상대 경로로 가리킵니다.
   기대 동작: 원문은 그대로이고, 브라우저에서 링크를 누르면 대상 문서의 화면으로 갑니다.
2. 경로: 기본 흐름, A1
   조건: 링크 대상이 저장소에 없습니다.
   기대 동작: `check`가 문서 경로·링크를 담은 경고를 내고, `changes list`가 경고 수를 알립니다.
3. 경로: A2, A1
   조건: 에셋 파일 이름을 바꿉니다.
   기대 동작: 참조하던 링크가 경고로 드러나고, 사용자는 문서를 고쳐 해소합니다.
