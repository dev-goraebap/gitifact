프로젝트 참여자로서, 반복 편집 중의 초안과 영구 기록을 구분하기 위해 Git에 커밋된 최종 명세를 기준으로 변경 이력을 확인하고 싶다.

### 범위와 제약

- 작업 중 대화와 반복 수정은 초안 편집이고, 영구 이력은 Git에 커밋된 최종 버전이다.
- 별도의 승인 묶음이나 note를 두지 않는다.
- 설계는 파일 하나 전체가 변경 단위다.

### 기본 흐름

1. 에이전트가 대화하며 요구사항과 설계를 여러 번 고친다.
2. 에이전트가 `changes list`를 실행한다.
3. 시스템은 마지막 커밋과 지금 파일을 비교해, 바뀐 문서마다 추가·변경·이동·삭제로 보인다.
4. 에이전트가 문서를 커밋한다(커밋 권한과 관련 파일 범위).
5. 시스템은 커밋된 최종 문서로 이력을 남기고, 이력 화면은 커밋마다 마지막 커밋 대비 최종 차이를 보인다.

### 대체 흐름

- **A1. 고쳤다가 되돌림** (3단계에서)
  1. 마지막 커밋과 같아진 문서는 바뀐 문서로 보지 않고, 결정기록도 요구하지 않는다.
- **A2. 설계만 바뀜** (3단계에서)
  1. 설계 문서의 변경으로만 보이고, 요구사항 변경으로 만들지 않는다.
- **A3. 문서를 옮김** (3단계에서)
  1. 같은 ID의 문서는 경로가 바뀌어도 한 문서의 이동으로 보이고, 이력이 이어진다.

### 사후 조건

- 커밋하지 않은 편집은 이력에 남지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 요구사항을 여러 번 고친 뒤 커밋합니다.
   기대 동작: 이력에는 그 커밋의 마지막 커밋 대비 최종 차이 하나만 남습니다.
2. 경로: 기본 흐름, A1
   조건: 요구사항을 고쳤다가 원래대로 되돌립니다.
   기대 동작: `changes list`에 바뀐 문서로 나오지 않고, 결정기록을 요구하지 않습니다.
3. 경로: 기본 흐름, A2
   조건: 설계 파일만 고칩니다.
   기대 동작: 설계의 변경으로만 보이고 요구사항은 바뀌지 않은 것으로 남습니다.
4. 경로: 기본 흐름, A3
   조건: 요구사항 파일을 다른 기능 폴더로 옮깁니다.
   기대 동작: 같은 ID의 이동 한 건으로 보이고, 옮기기 전 이력과 이어집니다.
