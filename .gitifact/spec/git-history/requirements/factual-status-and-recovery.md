프로젝트 참여자로서, 작업 결과를 정확히 판단하고 실패에 대응하기 위해 저장·커밋·구현·검증의 실제 상태와 복구에 필요한 정보를 구분해 확인하고 싶다.

### 범위와 제약

- 파일 저장, 커밋 참조, 구현 완료, 테스트 통과는 각각 다른 사실이다. 하나가 있다고 다른 것을 완료로 보지 않는다.
- 실패한 Git 실행 뒤에는 실제 HEAD와 index를 확인한다.

### 기본 흐름

1. 에이전트가 작업을 마치고 결과를 보고하려 한다.
2. 에이전트가 파일 저장, 커밋, 구현, 검증을 각각 실제로 확인한다.
3. 에이전트는 확인한 것과 하지 못한 것을 나누어 사용자에게 보고한다.

### 대체 흐름

- **A1. 검증을 실행하지 못함** (2단계에서)
  1. 에이전트는 실행하지 못한 검증을 미실행으로 알리고, 통과로 쓰지 않는다.
- **A2. 커밋이 실행 전에 실패함** (2단계에서)
  1. `changes commit`은 오류만 알리고, 자기 잠금 폴더와 격리 index를 지운다. 작업 폴더의 파일과 실제 index는 실행 전 그대로다.
  2. 에이전트는 원인을 고쳐 같은 입력으로 다시 실행한다.
- **A3. 커밋 결과가 불확실함** (2단계에서)
  1. HEAD가 바뀌었을 수 있는데 결과를 확인하지 못하면, 시스템은 잠금 폴더·복구 자료·격리 index를 남기고 멈춘다.
  2. 에이전트는 다시 실행하지 않고 HEAD와 복구 자료를 확인해 알린다. 커밋을 reset하거나 잠금을 지우지 않는다.
- **A4. 다른 커밋이 진행 중임** (2단계에서)
  1. 잠금 폴더가 있으면 시스템은 거부하고, 에이전트는 그 잠금을 지우지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 코드와 테스트를 고치고 테스트를 돌린 뒤 보고합니다.
   기대 동작: 보고에 커밋 여부와 테스트 결과가 따로 적힙니다.
2. 경로: 기본 흐름, A1
   조건: 일부 검증을 실행하지 못했습니다.
   기대 동작: 그 검증을 미실행으로 알리고 완료로 단정하지 않습니다.
3. 경로: 기본 흐름, A2
   조건: 훅이 커밋을 거부해 HEAD가 그대로입니다.
   기대 동작: 실제 index와 파일이 실행 전 상태로 남고, 같은 입력으로 다시 실행할 수 있습니다.
4. 경로: 기본 흐름, A3
   조건: 커밋 뒤 결과를 확인하지 못했습니다.
   기대 동작: 복구 자료를 남기고 멈추며, 커밋을 자동으로 reset하거나 잠금을 지우지 않습니다.
5. 경로: 기본 흐름, A4
   조건: 다른 커밋이 잠금 폴더를 쥐고 있습니다.
   기대 동작: 커밋을 거부하고 잠금을 지우지 않습니다.
