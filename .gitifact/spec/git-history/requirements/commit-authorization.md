에이전트와 제품을 만드는 사용자로서, 내 작업과 커밋 의도를 지키기 위해 허용한 시점과 범위 안에서 관련 명세·이유·코드·테스트를 커밋하고 싶다.

### 범위와 제약

- 자동 기록은 자동 커밋 권한이 아니다. 커밋은 사용자 요청이나 명시적 프로젝트 정책이 있을 때만 한다.
- 결정 하나의 결정기록·문서·코드·테스트를 한 커밋에 담는 것이 기본이다.
- 기존 staging과 이번 작업과 무관한 변경은 건드리지 않는다.
- 푸시는 커밋과 따로 허락받는다.

### 사전 조건

- 사용자가 커밋을 요청했거나 프로젝트 정책이 허용한다.

### 기본 흐름

1. 사용자가 커밋을 요청한다.
2. 에이전트가 `changes list`로 바뀐 문서, 커밋하지 않은 결정기록, 입력 파일 경로를 본다.
3. 에이전트가 결정 하나의 기록·문서·코드·테스트를 골라, 경로와 메시지와 권한 근거를 입력 파일에 쓴다.
4. 에이전트가 `changes commit`을 실행한다.
5. 시스템은 문서를 검사하고 고른 파일만 커밋하며, 실제 문서 ID로 트레일러를 붙인다. 훅과 서명은 그대로 돈다.
6. 시스템은 커밋 결과를 확인하고 입력 파일을 지운다. 푸시하지 않는다.

### 대체 흐름

- **A1. 권한 근거가 없음** (4단계에서)
  1. 입력에 권한 근거(사용자 요청 또는 프로젝트 정책)가 없으면 시스템은 거부한다.
- **A2. 기존 staging이 있음** (4단계에서)
  1. 시스템은 거부하고, staging과 파일을 그대로 둔다.
- **A3. 검사에 문제가 있음** (5단계에서)
  1. 초안 기록이나 형식 문제가 있으면 시스템은 문제 목록을 보이고 커밋하지 않으며, 입력 파일을 남긴다.
  2. 에이전트가 고친 뒤 4단계부터 다시 한다.
- **A4. 이동한 문서의 한쪽 경로만 고름** (5단계에서)
  1. 시스템은 옛 경로와 새 경로를 함께 고르라고 거부한다.
- **A5. 실행 중에 파일이나 HEAD가 바뀜** (5단계에서)
  1. 시스템은 커밋하지 않고 알린다. 에이전트가 상태를 확인한 뒤 다시 실행한다.
- **A6. 기록 없이 기존 문서를 바꿈** (5단계에서)
  1. 시스템은 결정기록 없는 수정을 알리되 커밋은 막지 않는다.
- **A7. 메시지에 트레일러를 직접 씀** (4단계에서)
  1. 메시지에 `Gitifact-`로 시작하는 줄이 있으면 시스템은 거부한다.
- **A8. 프로젝트가 문서와 코드를 나눠 커밋함** (3단계에서)
  1. 에이전트는 문서와 기록을 먼저 커밋하고, 이어지는 코드 커밋의 메시지에서 관련 문서를 설명한다.

### 사후 조건

- 고른 파일만 커밋되고, 고르지 않은 파일은 작업 폴더에 그대로 남는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 사용자가 요청해 결정기록과 그 문서, 코드를 골라 커밋합니다.
   기대 동작: 커밋 하나가 생기고 실제 문서 ID의 트레일러가 붙습니다. 고르지 않은 파일은 남고 푸시하지 않습니다.
2. 경로: 기본 흐름, A1
   조건: 권한 근거 없이 커밋을 실행합니다.
   기대 동작: 커밋하지 않고 거부합니다.
3. 경로: 기본 흐름, A2
   조건: 실행 전에 staging된 파일이 있습니다.
   기대 동작: 커밋하지 않고, staging과 파일을 그대로 둡니다.
4. 경로: 기본 흐름, A3
   조건: `draft: true`가 남은 결정기록을 담습니다.
   기대 동작: 문제 목록을 보이고 커밋하지 않으며, 입력 파일을 남깁니다.
5. 경로: 기본 흐름, A4
   조건: 옮긴 문서의 새 경로만 고릅니다.
   기대 동작: 커밋하지 않고 두 경로를 함께 고르라고 알립니다.
6. 경로: 기본 흐름, A5
   조건: 커밋이 진행되는 동안 고른 파일이 바뀝니다.
   기대 동작: 커밋하지 않고 바뀐 파일을 알립니다.
7. 경로: 기본 흐름, A6
   조건: 결정기록 없이 기존 요구사항을 고쳐 커밋합니다.
   기대 동작: 결정기록 없는 수정을 알리고 커밋합니다.
8. 경로: 기본 흐름, A7
   조건: 메시지에 `Gitifact-Req:` 줄을 직접 씁니다.
   기대 동작: 커밋하지 않고 거부합니다.
9. 경로: 기본 흐름, A8
   조건: 프로젝트 정책이 문서와 코드를 나눠 커밋하라고 정했습니다.
   기대 동작: 문서·기록 커밋이 먼저 생기고, 코드 커밋의 메시지가 관련 문서를 설명합니다.
