에이전트와 제품을 만드는 사용자로서, 긴 지침을 매 세션 싣지 않으면서도 에이전트가 알맞은 순간에 따르게 하기 위해 AGENTS.md에는 언제 무엇을 읽을지만 짧게 두고 지침 본문은 그때 읽게 하고 싶다.

### 범위와 제약

- AGENTS.md는 늘 읽히는 상시 지침이자 작업별 지침의 색인이다.
- 작업과 지침을 짝지은 짧은 규칙(예: "CLI 코드를 고치기 전에 cli-architecture 지침을 읽는다")은 프로젝트가 GITIFACT 블록 밖에 쓰고, gitifact가 대신 만들지 않는다.
- 지침을 읽는지는 에이전트에게 달려 있고 gitifact가 강제하지 않는다. 반드시 지켜야 하는 형식은 CLI 검사가 맡는다.

### 기본 흐름

1. 에이전트가 세션을 시작하며 AGENTS.md를 읽고, `instructions list --all`로 지침 목록을 본다.
2. 에이전트가 작업을 시작하기 전에, 색인에서 그 작업에 짝지은 지침을 찾는다.
3. 에이전트가 그 지침의 `index.md`를 읽고, 필요하면 링크된 하위 파일을 이어 읽는다.
4. 에이전트가 지침을 따라 작업한다.

### 대체 흐름

- **A1. 이번 작업에 짝지은 지침이 없음** (2단계에서)
  1. 에이전트는 다른 작업의 지침 본문을 읽지 않고 진행한다.
- **A2. 작업별 지침이 아직 없음** (2단계에서)
  1. 에이전트는 없다고 보고 진행한다.
  2. 사용자가 원하면, 대화에서 파악한 내용으로 지침을 만들고 AGENTS.md에 언제 읽을지 적자고 제안한다.
- **A3. 대화에서 구현 기준이 새로 생기거나 바뀜** (4단계에서)
  1. 에이전트는 해당 지침을 고치자고 제안하고, 동의를 받으면 저장한다.
  2. 새 지침을 만들면 AGENTS.md의 색인도 함께 고친다.

### 수용 조건

1. 경로: 기본 흐름
   조건: AGENTS.md가 CLI 코드를 고치기 전에 읽을 지침을 가리키고, 에이전트가 CLI 코드를 고칩니다.
   기대 동작: 에이전트는 고치기 전에 그 지침을 읽고 따릅니다.
2. 경로: 기본 흐름, A1
   조건: 에이전트가 CLI와 관계없는 문서만 고칩니다.
   기대 동작: CLI 지침의 본문을 읽지 않고 진행합니다.
3. 경로: 기본 흐름, A2
   조건: 프로젝트에 작업별 지침이 아직 없습니다.
   기대 동작: 에이전트는 없다고 보고 진행하며, 사용자가 원하면 지침과 AGENTS.md 색인을 만들자고 제안합니다.
4. 경로: 기본 흐름, A3
   조건: 대화에서 구현 기준이 새로 생깁니다.
   기대 동작: 에이전트가 지침을 고치자고 제안하고, 동의를 받으면 저장하며 새 지침이면 색인도 고칩니다.
