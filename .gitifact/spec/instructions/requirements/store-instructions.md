에이전트와 제품을 만드는 사용자로서, 사람과 에이전트가 같은 구현 기준을 쓰고 필요한 순간에 필요한 만큼만 읽게 하기 위해 프로젝트 지침을 작업 단위의 문서로 저장소에 두고 싶다.

### 범위와 제약

지침 하나는 `.gitifact/instructions/<이름>/` 폴더 하나이고, 본문은 그 폴더의 `index.md`다. 폴더 이름은 소문자·숫자·하이픈이다. 긴 내용은 `references/` 같은 하위 파일로 나누고, `index.md`는 늘 지킬 짧은 규칙과 어떤 작업 때 어느 파일을 읽을지 알리는 색인이 된다. 하위 파일은 그 지침에 딸리며 ID가 없다. 하위 Markdown 파일은 프론트매터에 `title`·`description`을 두어, 에이전트가 본문을 열지 않고 필요한 파일을 고르게 한다.

`index.md`는 다른 문서와 같은 프론트매터(`id`·`title`·`description`)와 본문 규칙을 따른다. ID는 CLI가 발급하는 `I-` ID다. 지침은 에이전트 스킬이 아니며, 에이전트 스킬 폴더로 잇거나 스크립트를 다루지 않는다.

### 수용 조건

1. 조건: 사용자가 새 지침을 만듭니다.
   기대 동작: `instructions new <이름>`이 폴더와 `index.md` 뼈대를 만들고 `I-` ID를 발급합니다.
2. 조건: 지침 폴더 이름을 바꿉니다.
   기대 동작: ID가 같으므로 같은 지침의 이력으로 이어지고 이동으로 기록됩니다.
3. 조건: 지침 폴더에 `index.md`가 없거나 프론트매터가 규칙에 맞지 않습니다.
   기대 동작: `check`가 문제로 알리고 커밋을 거부합니다.
4. 조건: 지침 폴더의 하위 Markdown 파일에 `title`이나 `description`이 없거나, 다른 키가 있습니다.
   기대 동작: `check`가 그 파일을 문제로 알리고 커밋을 거부합니다. Markdown이 아닌 파일은 검사하지 않습니다.
