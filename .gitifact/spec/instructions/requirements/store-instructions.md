에이전트와 제품을 만드는 사용자로서, 사람과 에이전트가 같은 구현 기준을 쓰고 필요한 순간에 필요한 만큼만 읽게 하기 위해 프로젝트 지침을 작업 단위의 문서로 저장소에 두고 싶다.

### 범위와 제약

- 지침 하나는 `.gitifact/instructions/<이름>/` 폴더 하나이고, 본문은 그 폴더의 `index.md`다. 폴더 이름은 소문자·숫자·하이픈이다.
- 긴 내용은 하위 파일로 나누고, `index.md`는 늘 지킬 짧은 규칙과 어떤 작업 때 어느 파일을 읽을지 알리는 색인이 된다.
- 하위 파일은 그 지침에 딸리며 ID가 없다. 하위 Markdown 파일은 프론트매터에 `title`·`description`을 두어, 본문을 열지 않고도 고를 수 있게 한다.
- `index.md`는 다른 문서와 같은 프론트매터와 본문 규칙을 따르고, ID는 CLI가 발급하는 `I-` ID다.
- 지침은 에이전트 스킬이 아니다. 스킬 폴더로 잇거나 스크립트를 다루지 않는다.

### 기본 흐름

1. 사용자가 에이전트에게 새 지침을 부탁한다.
2. 에이전트가 `instructions new <이름>`을 실행한다.
3. 시스템은 폴더와 `index.md` 뼈대를 만들고 `I-` ID를 발급하며 초안으로 표시한다.
4. 에이전트가 본문을 쓰고, 긴 내용은 제목·설명을 단 하위 파일로 나눈다.
5. 에이전트가 초안 표시를 지우고 `check`로 확인한 뒤 커밋한다.

### 대체 흐름

- **A1. 폴더 이름을 바꿈** (5단계 뒤에)
  1. ID가 같으므로 같은 지침의 이력으로 이어지고, 이동으로 기록된다.
- **A2. `index.md`가 없거나 프론트매터가 규칙에 맞지 않음** (5단계에서)
  1. `check`가 문제로 알리고 커밋을 거부한다.
- **A3. 하위 Markdown 파일의 프론트매터가 틀림** (5단계에서)
  1. `title`이나 `description`이 없거나 다른 키가 있으면, `check`가 그 파일을 문제로 알리고 커밋을 거부한다. Markdown이 아닌 파일은 검사하지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 사용자가 새 지침을 만듭니다.
   기대 동작: `instructions new <이름>`이 폴더와 `index.md` 뼈대를 만들고 `I-` ID를 발급합니다.
2. 경로: 기본 흐름, A1
   조건: 지침 폴더 이름을 바꿔 커밋합니다.
   기대 동작: 같은 지침의 이력으로 이어지고 이동으로 기록됩니다.
3. 경로: 기본 흐름, A2
   조건: 지침 폴더에 `index.md`가 없거나 프론트매터가 규칙에 맞지 않습니다.
   기대 동작: `check`가 문제로 알리고 커밋을 거부합니다.
4. 경로: 기본 흐름, A3
   조건: 하위 Markdown 파일에 `description`이 없습니다.
   기대 동작: `check`가 그 파일을 문제로 알리고 커밋을 거부합니다. 같은 폴더의 이미지 파일은 검사하지 않습니다.
