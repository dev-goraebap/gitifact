## 개요

Git author를 기준으로 참여자와 명세 활동을 표시한다. 커밋 작성자를 요구사항 요청자나 승인자로 추정하지 않고, 커밋 수를 구현 완료나 기여 품질로 해석하지 않는다. 화면 이름은 2026-09-15 사용자 요청으로 기여자에서 참여자로 바꿨고 경로 `/contributors`와 계약 필드 contributors는 유지한다.

## 구조와 데이터

명세 API의 서버 리더가 현재 HEAD의 Git 로그에서 author 이름·이메일·작성 시각을 읽는다. Git mailmap이 반영된 이름과 이메일을 사용하며 파일만 바뀐 경우도 반영하도록 관측 때 다시 조회한다.

이메일별로 커밋 수와 최근 활동 시각을 집계한다. 조회 한도는 최근 10,000개 커밋이며 초과 여부를 함께 반환한다. 참여자별 명세 활동은 현재 불러온 이력에서 이메일로 연결한다. 전체 커밋 집계와 불러온 명세 활동의 범위를 구분한다.

## 표시 흐름

1. 목록은 표가 아니라 카드 격자(최소 220px 열)다. 카드마다 48px 원형 아바타·이름·이메일·커밋 수·참여 기능 수·최근 활동을 두고 카드 전체가 상세 링크다. 이름이나 이메일로 검색한다.
2. 상세는 `/contributors/<이메일>` 경로다. 이메일은 percent 인코딩하며 목록의 검색어는 검색 인자로 둔다. 이전의 `?author=` 진입은 리다이렉트하지 않고 목록으로 취급한다. 최근 커밋에 없는 이메일은 찾을 수 없음 상태와 목록 링크를 보여준다.
3. 상세는 목록 대신 같은 폭의 페이지로 열린다. 72px 아바타·이름·이메일·Git 커밋 수·최근 활동을 머리에 두고, 참여한 기능(기능별 contributors에서 이 이메일이 있는 기능과 명세 커밋 수)을 카드로, 최근 명세 활동을 최대 10개 목록으로 보여준다. 절 사이에는 아래 여백을 두어 카드가 다음 절의 구분선에 붙지 않게 한다. 상단 이동 경로는 참여자 / 이름이다.
4. 작성자 필터가 적용된 명세 이력이나 해당 제품 기능(`/features/<S-ID>`)으로 이동한다. 이력 개수와 이전 이력 더 보기 줄은 활동 페이지에만 있고 참여자 화면에는 두지 않는다.

모든 화면의 아바타와 이름은 해당 참여자 상세로 가는 링크다. Astryx의 href 링크는 LinkProvider에 등록한 RouterLink가 받아 전체 새로고침 없이 라우터로 이동시키며, 표 행의 클릭은 행 안의 링크 클릭과 겹치지 않게 링크 대상이면 무시한다. 아바타는 손으로 그린 얼굴 세 가지와 배경색 여섯 가지 중에서 소문자로 바꾼 이메일의 해시로 하나씩 골라 SVG data URL로 표시한다. 같은 이메일은 어느 화면에서나 같은 아바타가 된다. 2026-09-19에 대칭 격자 패턴이 보기 좋지 않다는 사용자 의견으로 이 방식으로 바꿨다. 외부 아바타 서비스에 이메일을 보내지 않는다. 조합이 18가지뿐이라 여러 사람이 같은 아바타를 가질 수 있으므로 신원 확인에는 이름·이메일을 사용한다.

## 오류 처리와 검증

Git 조회와 계약 검증 실패는 오류로 표시하며 참여자가 없다고 바꾸지 않는다. 해당 이메일의 명세 활동이 없으면 최근 이력에 활동이 없다고 안내한다. 코드 커밋만 한 참여자를 누락된 요구사항 작성자로 취급하지 않는다.

서버의 Git author 집계와 브라우저의 선택·검색·관련 이력 이동을 검사한다. 저장소 밖 사용자 계정이나 PR 플랫폼의 구성원 목록은 조회하지 않는다.

## 주요 설계 결정과 제한

별도 회원·팀 관리 저장소를 만들지 않는다. Git이 가진 이름과 이메일을 표시 기준으로 삼아 단순하게 유지한다. 같은 사람이 여러 이메일을 사용하면 mailmap으로 정리된 경우 외에는 다른 항목으로 나타날 수 있다. 실제 조직 구성원 식별과 요청·승인자 인증은 지원하지 않는다.
