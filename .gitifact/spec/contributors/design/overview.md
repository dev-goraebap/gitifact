## 개요

Git author를 참여자로 보고 그 사람이 참여한 기능과 명세 활동을 보인다. 커밋 작성자를 요구사항 요청자나 승인자로 추정하지 않고, 커밋 수를 구현 완료나 기여 품질로 해석하지 않는다. 화면 이름은 참여자이고, 경로 `/contributors`와 계약 필드 `contributors`는 그 이름을 쓴다.

## 집계

브라우저 서버의 체크아웃 리더(`apps/cli/src/server/checkout/checkout-reader.ts`)가 명세 조회(`GET /api/v1/specs`)마다 HEAD의 Git 로그를 읽는다. 이름과 이메일은 mailmap이 반영된 값(`%aN`·`%aE`)이며, mailmap은 HEAD가 그대로여도 바뀔 수 있어 조회 때마다 다시 읽는다.

```mermaid
flowchart TD
  G["HEAD"] --> A["전체 커밋 로그"]
  G --> S["명세·위키 커밋 로그"]
  A --> P["참여자 목록"]
  S --> F["기능별 참여자"]
  P --> V["목록·상세 화면"]
  F --> V
  C["캐시 이력"] -->|"작성자 조건"| V
```

| 집계 | 읽는 범위 | 결과 |
| :--- | :--- | :--- |
| 참여자 목록 | 모든 커밋 중 최근 10,000개 | 이메일별 커밋 수·최근 활동 시각. 넘치면 `contributorsLimited` |
| 기능별 참여자 | `.gitifact/spec`·위키를 건드린 커밋 중 최근 20,000개, 기능마다 2000개까지 | 기능 폴더마다 `contributors`(이메일별 명세 커밋 수)와 `updatedAt` |
| 최근 명세 활동 | 캐시의 전체 이력 | 작성자 조건을 건 이력 질의의 첫 10건 |

두 로그 모두 마이그레이션 커밋(`Gitifact-Migration` 트레일러)은 뺀다. 형식 전환이 모든 문서를 다시 쓰지만 누구의 작업도 아니기 때문이다. 참여자 목록은 모든 커밋을 세고 기능별 참여자는 명세 커밋만 세므로, 코드 커밋만 한 사람은 목록에 있어도 참여한 기능이 없다.

## 화면

목록(`/contributors`)은 카드 격자(최소 220px 열)다. 카드마다 48px 원형 아바타·이름·이메일·커밋 수·참여 기능 수·최근 활동을 두고 카드 전체가 상세 링크다. 이름이나 이메일로 검색하며 검색어는 `q` 검색 인자다.

상세는 `/contributors/<이메일>`(percent 인코딩)이며 목록 대신 같은 폭의 페이지로 열린다. 이전의 `?author=` 진입은 리다이렉트하지 않고 목록으로 취급한다. 불러온 참여자 목록에 없는 이메일은 찾을 수 없음 상태와 목록 링크를 보인다. 상단 이동 경로는 참여자 / 이름이다.

| 상세의 절 | 내용 |
| :--- | :--- |
| 머리 | 72px 아바타, 이름, 이메일, Git 커밋 수, 최근 활동, 작성자 필터를 건 활동 링크(`/activity?author=`) |
| 참여한 기능 | 기능별 `contributors`에 이 이메일이 있는 기능 카드. 이 사람의 명세 커밋 수와 요구사항 수를 보이고 `/features/<S-ID>`로 간다 |
| 최근 명세 활동 | 최대 10개. 변경 종류·문서 종류·제목·시각이며 제목은 그 커밋 페이지로 간다 |

절 사이에는 아래 여백을 두어 카드가 다음 절의 구분선에 붙지 않게 한다. 이력 개수와 이전 이력 더 보기 줄은 활동 페이지에만 있고 참여자 화면에는 두지 않는다.

모든 화면의 아바타와 이름은 해당 참여자 상세로 가는 링크다(`entities/contributor`의 `Person`, `contributorHref`). Astryx의 href 링크는 LinkProvider에 등록한 RouterLink가 받아 전체 새로고침 없이 라우터로 이동한다. 표 행의 클릭은 행 안의 링크 클릭과 겹치지 않게 대상이 링크나 버튼이면 무시한다.

## 아바타

아바타는 손으로 그린 얼굴 세 가지와 배경색 여섯 가지 중에서, 소문자로 바꾼 이메일의 해시(FNV-1a)로 하나씩 골라 SVG data URL로 만든다(`avatarSource`). 같은 이메일은 어느 화면에서나 같은 아바타가 된다. 외부 아바타 서비스에 이메일을 보내지 않는다.

> [!NOTE]
> 조합이 18가지뿐이라 여러 사람이 같은 아바타를 가질 수 있다. 신원 확인에는 이름·이메일을 쓴다.

## 오류 처리와 검증

Git 조회와 계약 검증 실패는 오류로 표시하며 참여자가 없다고 바꾸지 않는다. 작성자 줄을 읽지 못해도 오류다. 해당 이메일의 명세 활동이 없으면 최근 이력에 활동이 없다고 안내하고, 코드 커밋만 한 참여자를 누락된 요구사항 작성자로 취급하지 않는다.

서버의 Git author 집계와 브라우저의 선택·검색·관련 이력 이동을 검사한다. 저장소 밖 사용자 계정이나 PR 플랫폼의 구성원 목록은 조회하지 않는다.

같은 사람이 여러 이메일을 쓰면 mailmap으로 정리된 경우 외에는 다른 항목으로 나타난다. 실제 조직 구성원 식별과 요청·승인자 인증은 지원하지 않는다.

## 결정

| 결정 | 이유 | 기각한 안 |
| :--- | :--- | :--- |
| 별도 회원·팀 저장소를 두지 않고 Git의 이름·이메일을 표시 기준으로 삼는다 | 단순하게 유지한다 | 회원·팀 관리 저장소 |
| 목록은 카드 격자, 상세는 같은 폭의 페이지다 | 사람을 보여 주는 곳이라 아바타가 보이는 카드가 맞고, 상세는 한 사람의 내용에 집중하게 한다 | 표 목록, 옆 패널 상세 |
| 아바타는 이메일 해시로 고른 손그림 얼굴과 배경색이다 | 외부 서비스 없이 만들고, 대칭 격자 패턴은 보기 좋지 않았다 | 대칭 격자 패턴, 외부 아바타 서비스 |
| 최근 명세 활동은 서버에 작성자 조건으로 묻는다 | 불러온 페이지가 아니라 전체 이력에서 그 사람의 최근 변경을 찾는다 | 불러온 이력 페이지에서 이메일로 찾기 |
| 기능별 참여자는 명세·위키 커밋을 한 번의 `git log`로 읽는다 | Windows에서 git 프로세스는 한 번에 약 80ms라, 기능·페이지마다 읽으면 22개 기능과 63개 페이지에 85번을 부른다 | 기능·페이지마다 `git log` |
