# 기여자 조회 설계

## 개요
<!-- gitifact-ref: R-ybmsjjgqtp -->

Git author를 기준으로 기여자와 명세 활동을 표시한다. 커밋 작성자를 요구사항 요청자나 승인자로 추정하지 않고, 커밋 수를 구현 완료나 기여 품질로 해석하지 않는다.

## 구조와 데이터

명세 API의 서버 리더가 현재 HEAD의 Git 로그에서 author 이름·이메일·작성 시각을 읽는다. Git mailmap이 반영된 이름과 이메일을 사용하며 파일만 바뀐 경우도 반영하도록 관측 때 다시 조회한다.

이메일별로 커밋 수와 최근 활동 시각을 집계한다. 조회 한도는 최근 10,000개 커밋이며 초과 여부를 함께 반환한다. 기여자별 명세 활동은 현재 불러온 이력에서 이메일로 연결한다. 전체 커밋 집계와 불러온 명세 활동의 범위를 구분한다.

## 표시 흐름

1. 목록에서 이름·이메일·커밋 수·최근 활동을 표시하고 이름이나 이메일로 검색한다.
2. 선택 이메일을 URL의 author에 저장해 다시 열 수 있게 한다.
3. 상세에서 불러온 명세 활동과 관련 기능을 보여준다. 최근 활동 항목은 최대 10개를 표시한다.
4. 작성자 필터가 적용된 명세 이력이나 해당 제품 기능으로 이동한다.

아바타는 이메일 문자열의 해시로 대칭 SVG 패턴과 색을 만들고 data URL로 표시한다. 외부 아바타 서비스에 이메일을 보내지 않는다. 같은 패턴이 나올 수 있으므로 신원 확인에는 이름·이메일을 사용한다.

## 오류 처리와 검증

Git 조회와 계약 검증 실패는 오류로 표시하며 기여자가 없다고 바꾸지 않는다. 해당 이메일의 명세 활동이 없으면 불러온 범위에 활동이 없다고 안내한다. 코드 커밋만 한 기여자를 누락된 요구사항 작성자로 취급하지 않는다.

서버의 Git author 집계와 브라우저의 선택·검색·관련 이력 이동을 검사한다. 저장소 밖 사용자 계정이나 PR 플랫폼의 구성원 목록은 조회하지 않는다.

## 주요 설계 결정과 제한

별도 회원·팀 관리 저장소를 만들지 않는다. Git이 가진 이름과 이메일을 표시 기준으로 삼아 단순하게 유지한다. 같은 사람이 여러 이메일을 사용하면 mailmap으로 정리된 경우 외에는 다른 항목으로 나타날 수 있다. 실제 조직 구성원 식별과 요청·승인자 인증은 지원하지 않는다.
