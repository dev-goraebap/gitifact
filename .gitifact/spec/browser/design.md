# 명세 브라우저 설계

## 개요

명세 이력·제품 기능·참여자를 연결하는 읽기 전용 브라우저다. React·Astryx로 UI를 구성하고 TanStack Router가 경로·선택·필터를, TanStack Query가 서버 조회 상태를 관리한다. 목록을 대체하는 상세 페이지는 경로 계층(`/features/<S-ID>`, `/contributors/<이메일>`)으로 구분하고, 같은 화면 안의 검색·탭·드로어 선택은 URL 검색 인자에 둔다. 브라우저는 파일이나 Git 명령을 직접 실행하지 않는다.

## 구조와 데이터
<!-- gitifact-ref: R-5eehizubwl -->

왼쪽 메뉴는 Astryx SideNav의 resizable 옵션으로 200~400px 사이에서 너비를 조절하고 localStorage에 유지한다. CLI 로컬 서버가 정적 앱과 세션·명세 API를 제공한다. browser-specs 계약은 현재 기능, Git 명세 변경, 참여자, 다음 커서를 전달한다. 현재 원문은 작업 폴더에서, 이력의 전후·작성자·시점은 Git에서 읽는다. 미커밋 내용은 작업 상태라고 안내한다.

Query 키에는 origin·서버 세션·worktree를 포함한다. API 요청은 세션 헤더를 보내며 응답 형식과 세션을 검증한다. FSD의 entities는 조회를, pages/product는 화면 구성과 검색 상태를 담당한다.

## 활동 타임라인
<!-- gitifact-ref: R-tkl3lrrlpu, R-hsflueyc4b -->

서버는 first-parent Git 로그의 관련 커밋 10개를 최신순으로 읽고 필요한 blob을 일괄 조회한다. 커밋별 스냅샷은 프로세스 메모리에 캐시한다. 다음 커서는 관측 HEAD에 연결해 다른 시점의 페이지가 섞이지 않게 한다.

요구사항 R-ID와 설계 S-ID를 각각 비교해 추가·변경·제거·이동을 표시한다. 화면 이름은 추가·변경·제거·이동이며 저장 형식의 created·modified·deleted·moved는 바꾸지 않는다. 목록은 왼쪽 세로 선 위에 작성자 아바타가 놓이는 타임라인이며, 같은 커밋의 연속 항목도 커밋 해시를 그대로 표시한다. 항목마다 변경 이유를 한 줄로 이어 표시하고 이유가 없으면 미기록 상태를 안내한다. 제목을 열면 상세 서랍(Astryx Dialog)에서 변경 후 원문·변경 전·이유를 확인한다. 선택은 URL의 selected에 저장한다. 이전의 같은 명세 연결 그래프는 읽기에 방해가 되어 2026-09-15에 제거했다.

본문은 1024px 중앙 컬럼이며 스크롤은 콘텐츠 카드가 담당한다. 제목은 스크롤로 사라지고 필터 줄은 상단 바 아래에 고정된다. 종류·기능·작성자·검색 필터는 불러온 범위에 적용한다. 더보기는 기존 목록에 다음 페이지를 추가하며 실패 시 재시도할 수 있다. 모든 이력을 처음부터 한 번에 분석하지 않는다.

## 제품 기능
<!-- gitifact-ref: R-xqf3xsumye -->

기능 목록은 활동 페이지와 같은 1024px 중앙 컬럼의 Astryx Table이며 제목·설명 한 줄·요구사항 수·설계 Token·AvatarGroup 참여자(3명 초과는 +N)·상대 시각을 보여준다. 서버가 기능마다 `.gitifact`와 `.tryce` 폴더 경로로 Git 로그(최대 2000개)를 읽어 contributors와 updatedAt을 응답에 담는다. 행이나 제목을 열면 `/features/<S-ID>` 경로로 이동해 같은 컬럼의 상세 페이지를 그리고 페이지 제목과 필터 줄은 숨긴다. 없는 S-ID는 찾을 수 없음 상태와 목록 링크를 보여준다. 상세의 요구사항 탭은 제목·본문·수용 조건을, 설계 탭은 문서 전체를 표시한다. 설계가 없으면 미작성 상태를 안내한다.

selected·tab은 URL 검색 인자에 저장한다. 이전의 `?feature=` 진입은 리다이렉트하지 않는다. 설계의 R-ID 참조는 현재 전체 기능에서 찾아 해당 요구사항으로 연결한다. 삭제된 참조는 현재 명세에 없다고 표시한다. 과거 설계의 링크도 현재 요구사항으로 연결한다. Markdown은 실행 지시가 아닌 데이터로 렌더링한다.

## 오류 처리와 검증
<!-- gitifact-ref: R-5eehizubwl -->

첫 조회의 골격 화면은 200ms 뒤에 나타나고 한번 보이면 최소 300ms 유지한 뒤 본문이 페이드인한다. 골격은 화면별로 실제 배치(활동은 세로 선·아바타·세 줄, 제품 기능·참여자는 표 행)를 본떠 교체 순간 레이아웃이 바뀌지 않게 한다. 재조회 중 기존 내용을 유지하며 빈 결과·검색 결과 없음·조회 실패를 구분한다. HEAD·원문이 조회 중 바뀌거나 세션이 교체되면 다시 조회하도록 알린다.

계약 fixture로 선택·탭·필터·더보기·누락 참조·모바일·오류를 검사하고, 실제 Git 저장소와 패키징된 서버로 조회를 확인한다. 성능은 실제 측정값으로 보고한다.

## Git 상태

Git 상태 페이지도 같은 중앙 컬럼과 헤더의 새로고침 버튼을 쓴다. 브랜치·HEAD·저장소·마지막 확인을 MetadataList로, Staged·Unstaged·Untracked·충돌 집계를 한 줄로, 변경 경로를 Table로 보여준다. 표의 상태 열은 porcelain 두 글자 코드를 Staged·Unstaged·Untracked·충돌 Token으로 풀어 표시하고 원래 코드는 옆 열에 둔다. 변경이 없으면 빈 상태 일러스트를, 관측 한계와 gitifact 검사 미실행 안내는 하단 상태 줄에 둔다.

## 화면 확대

루트 글자 크기는 1920px까지 100%이고 그 위로는 뷰포트에 비례해 2560px에서 18px에 닿는다. Astryx의 spacing·size-element 토큰은 px로 배포되므로 같은 16px 기준값을 rem으로 다시 선언해 글자와 간격이 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 주요 설계 결정과 제한

요약 대시보드를 첫 화면으로 강제하지 않는다. 요구사항과 설계는 같은 이력에서 종류를 구분하고 공통 원문을 중복 저장하지 않는다. 현재 캐시는 메모리 기반이며 영속 로컬 색인은 아직 구현하지 않았다. 편집·승인 UI와 작업 파일 표시는 범위 밖이다.
