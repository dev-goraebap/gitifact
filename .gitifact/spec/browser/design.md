# 명세 브라우저 설계

## 개요

명세 이력·요구사항·참여자를 연결하는 읽기 전용 브라우저다. React·Astryx로 UI를 구성하고 TanStack Router가 경로·선택·필터를, TanStack Query가 서버 조회 상태를 관리한다. 목록을 대체하는 상세 페이지는 경로 계층(`/features/<S-ID>`, `/contributors/<이메일>`)으로 구분하고, 같은 화면 안의 검색·탭·드로어 선택은 URL 검색 인자에 둔다. 브라우저는 파일이나 Git 명령을 직접 실행하지 않는다.

## 구조와 데이터
<!-- gitifact-ref: R-5eehizubwl -->

왼쪽 메뉴는 Astryx SideNav의 resizable 옵션으로 200~400px 사이에서 너비를 조절하고 localStorage에 유지한다. 메뉴 순서는 제품 개요·요구사항·지침·활동·참여자·Git 상태다. CLI 로컬 서버가 정적 앱과 세션·명세 API를 제공한다. browser-specs 계약은 현재 기능, Git 명세 변경, 참여자, 다음 커서를 전달한다. 현재 원문은 작업 폴더에서, 이력의 전후·작성자·시점은 Git에서 읽는다.

미커밋 내용은 문장 대신 표시로 알린다. 셸은 `useWorkingChanges`로 명세 Query 캐시의 `working`을 읽어 Git 상태 메뉴에 경고 StatusDot을 붙이고, Git 상태 페이지는 같은 값으로 상단 Banner에 "요구사항·제품 개요·지침 화면은 작업 중인 내용이고 활동은 커밋된 내용"임을 설명한다. 이 훅은 명세 API를 스스로 호출하지 않고, 모든 페이지가 이미 읽는 Git 상태 응답의 `.gitifact/`·`.tryce/` 아래 변경 경로를 두 번째 출처로 본다. 처음 구현은 셸에서 명세를 조회했으나 gitifact 저장소가 없는 프로젝트의 Git·소개 화면에서 503 오류가 콘솔에 남아 캐시 읽기로 바꿨고, 캐시만으로는 Git 페이지에 바로 들어올 때 표시가 비어 상태 경로를 더했다.

Query 키에는 origin·서버 세션·worktree를 포함한다. API 요청은 세션 헤더를 보내며 응답 형식과 세션을 검증한다. FSD의 entities는 조회를, pages/product는 화면 구성과 검색 상태를 담당한다.

## 활동 타임라인
<!-- gitifact-ref: R-tkl3lrrlpu, R-hsflueyc4b -->

서버는 first-parent Git 로그의 관련 커밋 10개를 최신순으로 읽고 필요한 blob을 일괄 조회한다. 커밋별 스냅샷은 프로세스 메모리에 캐시한다. 다음 커서는 관측 HEAD에 연결해 다른 시점의 페이지가 섞이지 않게 한다.

요구사항 R-ID와 설계 S-ID를 각각 비교해 추가·변경·제거·이동을 표시한다. 화면 이름은 추가·변경·제거·이동이며 저장 형식의 created·modified·deleted·moved는 바꾸지 않는다. 목록은 왼쪽 세로 선 위에 작성자 아바타가 놓이는 타임라인이며, 같은 커밋의 연속 항목도 커밋 해시를 그대로 표시한다. 항목마다 변경 이유를 한 줄로 이어 표시하고 이유가 없으면 미기록 상태를 안내한다. 제목을 열면 상세 서랍(Astryx Dialog)에서 변경 내용과 이유를 확인한다. 변경 전·후가 모두 있으면 변경 후 본문 위에 변경 전 본문을 겹쳐 두고, 세로 손잡이를 오른쪽으로 끌수록 변경 전이 같은 자리에서 드러난다(이미지 비교 슬라이더 방식). 변경 전 층은 테마의 background-yellow 황색 배경(다크에서는 어두운 올리브)이며 바깥쪽 모서리만 둥글고, 두 본문은 한 그리드 셀을 공유해 높이는 둘 중 큰 쪽이다. 변경 전·변경 후 버튼으로 한쪽을 바로 볼 수 있고 손잡이는 화살표·Home·End 키로도 움직인다. 추가·제거처럼 한쪽만 있으면 본문 하나만 보여준다. Astryx ResizeHandle은 1px 루트 안에서만 포인터를 받아 겹침 비교에 맞지 않았으므로 손잡이는 직접 구현했다. 선택은 URL의 selected에 저장한다. 이전의 같은 명세 연결 그래프는 읽기에 방해가 되어 2026-09-15에 제거했다.

본문은 1024px 중앙 컬럼이며 스크롤은 콘텐츠 카드가 담당한다. 제목은 스크롤로 사라지고 필터 줄은 상단 바 아래에 고정된다. 종류·기능·작성자·검색 필터는 불러온 범위에 적용한다. 더보기는 기존 목록에 다음 페이지를 추가하며 실패 시 재시도할 수 있다. 모든 이력을 처음부터 한 번에 분석하지 않는다.

## 요구사항 목록과 기능 상세
<!-- gitifact-ref: R-xqf3xsumye -->

요구사항 메뉴(`/features`)의 목록은 활동 페이지와 같은 1024px 중앙 컬럼의 Astryx Table이며 제목·설명 한 줄·요구사항 수·설계 Token·AvatarGroup 참여자(3명 초과는 +N)·상대 시각을 보여준다. 서버가 기능마다 `.gitifact`와 `.tryce` 폴더 경로로 Git 로그(최대 2000개)를 읽어 contributors와 updatedAt을 응답에 담는다. 행이나 제목을 열면 `/features/<S-ID>` 경로로 이동해 같은 컬럼의 상세 페이지를 그리고 페이지 제목과 필터 줄은 숨긴다. 없는 S-ID는 찾을 수 없음 상태와 목록 링크를 보여준다. 상세의 요구사항 탭은 제목·본문·수용 조건을, 설계 탭은 문서 전체를 표시한다. 설계가 없으면 미작성 상태를 안내한다. 메뉴 이름은 2026-09-17에 제품 기능에서 요구사항으로 바꿨고 경로는 유지했다.

selected·tab은 URL 검색 인자에 저장한다. 이전의 `?feature=` 진입은 리다이렉트하지 않는다. 설계의 R-ID 참조는 현재 전체 기능에서 찾아 해당 요구사항으로 연결한다. 삭제된 참조는 현재 명세에 없다고 표시한다. 과거 설계의 링크도 현재 요구사항으로 연결한다. Markdown은 실행 지시가 아닌 데이터로 렌더링한다.

## 제품 개요 대시보드

`/product`는 같은 명세 응답으로 계산한 요약을 PRODUCT.md 본문 앞에 둔다. 머리에는 제품 제목·ID·최근 변경·미커밋 Token·변경 이력 링크가 있다. 그 아래 Card 타일 다섯 개(기능 명세 수, 요구사항 수와 기능당 평균, 설계 작성 수와 ProgressBar 비율, 지침 문서 수, 참여자 수), 두 열의 차트 카드(기능별 요구사항 ProgressBar 상위 8개, 불러온 활동의 변경 종류 분할 막대, 참여자별 커밋 분할 막대와 상위 3명·그 외), 최근 명세 활동 5건 목록이 이어진다. 제품 설명 본문은 머리의 제품 문서 보기 링크로 여는 `/product/document` 읽기 페이지에 있다. 본문 첫 블록이 이미지이면 워드마크와 겹치므로 그 한 장만 빼고 나머지 상대 경로 이미지는 `/api/v1/product/assets/<파일명>`으로 바꾼다. 분할 막대는 recharts 같은 라이브러리 대신 인라인 SVG로 그리고 각 분할에 `<title>`로 값을 붙인다. 계열 색과 범례 규칙은 브라우저 지침의 차트 절을 따른다. 요약 대시보드는 활동(`/`)이 아니라 제품 개요에만 있으므로 첫 화면을 강제하지 않는다.

## 오류 처리와 검증
<!-- gitifact-ref: R-5eehizubwl -->

첫 조회의 골격 화면은 200ms 뒤에 나타나고 한번 보이면 최소 300ms 유지한 뒤 본문이 페이드인한다. 골격은 화면별로 실제 배치(활동은 세로 선·아바타·세 줄, 요구사항·참여자는 표 행, 제품 개요는 타일·카드, 지침은 열)를 본떠 교체 순간 레이아웃이 바뀌지 않게 한다. 재조회 중 기존 내용을 유지하며 빈 결과·검색 결과 없음·조회 실패를 구분한다. HEAD·원문이 조회 중 바뀌거나 세션이 교체되면 다시 조회하도록 알린다.

계약 fixture로 선택·탭·필터·더보기·누락 참조·모바일·오류·대시보드 집계·지침 미리보기·미커밋 표시를 검사하고, 실제 Git 저장소와 패키징된 서버로 조회를 확인한다. 성능은 실제 측정값으로 보고한다.

## Git 상태

Git 상태 페이지도 같은 중앙 컬럼과 헤더의 새로고침 버튼을 쓰며 헤더에 마지막 관측 시각을 "조회"로 표시한다. 브랜치·HEAD·저장소를 MetadataList로, Staged·Unstaged·Untracked·충돌 집계를 한 줄로, 변경 경로를 Table로 보여준다. 표의 상태 열은 porcelain 두 글자 코드를 Staged·Unstaged·Untracked·충돌 Token으로 풀어 표시하고 원래 코드는 옆 열에 둔다. 변경이 없으면 빈 상태 일러스트를, 관측 한계와 gitifact 검사 미실행 안내는 하단 상태 줄에 둔다. 미커밋 명세 변경이 있으면 본문 맨 위에 경고 Banner를 둔다.

## 화면 확대

루트 글자 크기는 1920px까지 100%이고 그 위로는 뷰포트에 비례해 2560px에서 18px에 닿는다. Astryx의 spacing·size-element 토큰은 px로 배포되므로 같은 16px 기준값을 rem으로 다시 선언해 글자와 간격이 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 주요 설계 결정과 제한

요약 대시보드를 첫 화면으로 강제하지 않는다. 요구사항과 설계는 같은 이력에서 종류를 구분하고 공통 원문을 중복 저장하지 않는다. 차트 라이브러리를 번들에 더하지 않고 SVG·ProgressBar로 그린다. 현재 캐시는 메모리 기반이며 영속 로컬 색인은 아직 구현하지 않았다. 편집·승인 UI와 작업 파일 표시는 범위 밖이다.

## 문서 읽기

제품 문서·지침 상세·요구사항 본문·설계·소개는 shared/ui/document의 DocumentBody로 렌더링한다. Astryx Markdown은 문단을 680px로 제한하면서 표·코드·구분선은 전체 폭으로 그려 오른쪽 끝이 어긋나므로, 읽기 영역을 48rem 한 폭으로 묶고 contentWidth를 100%로 둔다. 크기는 Astryx 글자 토큰을 읽기 영역에서 재정의해 맞춘다. 본문 16px·줄 간격 1.8, 코드 14px, 제목은 어느 단계에서도 본문보다 크게 잡고 위 간격을 아래보다 넓게 준다. 표는 테두리·둥근 모서리·옅은 머리글 행과 내부 가로 스크롤, 인용은 옅은 바탕과 왼쪽 선, 인라인 코드는 테두리 있는 칩, 링크는 테마상 글자색과 같으므로 밑줄로 구분한다. 지침 미리보기 열과 기능 설명 한 줄은 좁은 자리라 compact 표시를 유지한다.

코드 펜스는 Astryx 기본 렌더러가 CodeBlock으로 그린다. stone 테마의 구문 색은 모두 회색 계열이라 하이라이팅이 보이지 않으므로, GitHub 라이트·다크 값을 한 쌍으로 묶은 구문 테마(shared/ui/document/syntax.ts)를 앱 전체에 SyntaxTheme으로 적용한다. 일반 식별자·구두점·주석·배경은 테마 토큰을 써서 모든 색 조합과 어울린다. Astryx 토크나이저가 모르는 언어(markdown·text 등)는 색 없이 나온다. Tailwind 기반인 fumadocs 스타일을 들여오는 안은 디자인 체계가 둘이 되어 기각했다.

## 설정과 색 조합
<!-- gitifact-ref: R-jsncmqoqjm -->

WORKSPACE 그룹의 마지막 메뉴인 `/settings`에서 화면 모드(시스템·라이트·다크)와 색 조합을 고른다. 선택은 shared/lib/appearance가 localStorage(`gitifact-appearance`)에 저장하고 useSyncExternalStore로 구독하며, 다른 탭의 변경도 storage 이벤트로 따른다. 서버나 프로젝트에는 아무것도 보내지 않는다. 저장값이 깨져 있으면 기본값(시스템·스톤)을 쓰고 저장소를 쓸 수 없으면 그 페이지 동안만 유지한다. AppProviders가 Astryx Theme의 theme와 mode에 반영한다.

기본 스톤은 prebuilt 테마라 첫 화면에 스타일 주입이 없다. 나머지 조합(세이지 & 크림, 올리브 & 웜그레이, 슬레이트 & 블루, 샌드 & 클레이)은 stone 소스를 extends해 글꼴·모서리·아이콘·컴포넌트 재정의를 물려받고 색 토큰 16개만 라이트·다크 쌍으로 명시한다. 값은 Gentask의 팔레트와 hoho-hr의 Halo · Olive 토큰(OKLCH를 hex로 변환)에서 가져왔다. 강조색 하나에서 나머지를 유도하는 방식(color.accent 시드)은 기각했다. stone은 링크와 메뉴 글자가 강조색 토큰을 글자색으로 쓰기 때문에 색이 글자·메뉴·바탕 전체로 번진다. 그래서 글자용 강조 토큰(`--color-text-accent`·`--color-icon-accent`)은 조합의 글자색을 따르고, 채도 높은 강조색은 선택 표시·진행 막대·버튼에만 나타난다. 설정 카드의 미리보기는 라이트·다크 각각의 바탕·표면·강조 점·글자 선을 축소판으로 그린다.
