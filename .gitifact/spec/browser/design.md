# 명세 브라우저 설계

## 개요

명세 이력·요구사항·참여자를 연결하는 읽기 전용 브라우저다. React·Astryx로 UI를 구성하고 TanStack Router가 경로·선택·필터를, TanStack Query가 서버 조회 상태를 관리한다. 목록을 대체하는 상세 페이지는 경로 계층(`/features/<S-ID>`, `/contributors/<이메일>`)으로 구분하고, 같은 화면 안의 검색·탭·드로어 선택은 URL 검색 인자에 둔다. 브라우저는 파일이나 Git 명령을 직접 실행하지 않는다.

## 구조와 데이터
<!-- gitifact-ref: R-5eehizubwl -->

왼쪽 메뉴는 Astryx SideNav의 resizable 옵션으로 200~400px 사이에서 너비를 조절하고 localStorage에 유지한다. 메뉴 순서는 제품 개요·기능별 요구사항·프로젝트 위키·활동·참여자·Git 상태다. 브라우저는 제품 개요(`/product`)에서 시작한다. `/`는 검색 인자가 없으면 `/product`로, 있으면 같은 인자를 붙여 `/activity`로 리다이렉트한다. 0.5.0 전에는 활동이 `/`였으므로 저장해 둔 활동 링크가 필터와 선택을 잃지 않게 했다. CLI 로컬 서버가 정적 앱과 세션·명세 API를 제공한다. browser-specs 계약은 현재 기능, Git 명세 변경, 참여자, 다음 커서를 전달한다. 현재 원문은 작업 폴더에서, 이력의 전후·작성자·시점은 Git에서 읽는다.

미커밋 내용은 문장 대신 표시로 알린다. 셸은 `useWorkingChanges`로 명세 Query 캐시의 `working`을 읽어 Git 상태 메뉴에 경고 StatusDot을 붙이고, Git 상태 페이지는 같은 값으로 상단 Banner에 "제품 개요·기능별 요구사항·위키 화면은 작업 중인 내용이고 활동은 커밋된 내용"임을 설명한다. 이 훅은 명세 API를 스스로 호출하지 않고, 모든 페이지가 이미 읽는 Git 상태 응답의 `.gitifact/`·`.tryce/` 아래 변경 경로를 두 번째 출처로 본다. 처음 구현은 셸에서 명세를 조회했으나 gitifact 저장소가 없는 프로젝트의 Git·소개 화면에서 503 오류가 콘솔에 남아 캐시 읽기로 바꿨고, 캐시만으로는 Git 페이지에 바로 들어올 때 표시가 비어 상태 경로를 더했다.

Query 키에는 origin·서버 세션·worktree를 포함한다. API 요청은 세션 헤더를 보내며 응답 형식과 세션을 검증한다. 명세 조회의 staleTime은 무한이고 갱신은 헤더의 새로고침 버튼뿐이다. 5초였을 때는 명세 화면 다섯이 이 조회 하나를 함께 쓰는 탓에 화면을 옮길 때마다 불러온 페이지가 전부 다시 요청됐다. 더보기를 두 번 누른 뒤 활동으로 돌아오면 3회·약 2초가 들었고 더 불러올수록 늘었다. 지금은 0회다.

browser-specs 계약은 v3에서 체크아웃(현재 기능·위키·참여자·미커밋 여부)을 첫 페이지에만 싣는다. v2는 페이지마다 같은 169KB를 다시 보냈고 서버도 기능마다 로그를 걷고 author 10,000건을 다시 셌다. 이어지는 페이지는 이제 커밋과 그 변경 전후만 담는다(이 저장소 기준 470KB→301KB, 317KB→148KB). 브라우저는 첫 페이지를 체크아웃이 반드시 있는 형식으로 검증하고 나머지 페이지는 이력 형식으로 읽는다. FSD의 entities는 조회를, pages/product는 화면 구성과 검색 상태를 담당한다.

## 활동 타임라인
<!-- gitifact-ref: R-tkl3lrrlpu, R-hsflueyc4b -->

서버는 first-parent Git 로그의 관련 커밋 10개를 최신순으로 읽고 필요한 blob을 일괄 조회한다. 커밋별 스냅샷은 프로세스 메모리에 캐시한다. 다음 커서는 관측 HEAD에 연결해 다른 시점의 페이지가 섞이지 않게 한다.

요구사항 R-ID와 설계 S-ID를 각각 비교해 추가·변경·제거·이동을 표시한다. 화면 이름은 추가·변경·제거·이동이며 저장 형식의 created·modified·deleted·moved는 바꾸지 않는다. 목록은 왼쪽 세로 선 위에 작성자 아바타가 놓이는 타임라인이며, 같은 커밋의 연속 항목도 커밋 해시를 그대로 표시한다. 항목마다 변경 이유를 한 줄로 이어 표시하고 이유가 없으면 미기록 상태를 안내한다. 제목을 열면 상세 서랍(Astryx Dialog)에서 변경 내용과 이유를 확인한다. 변경 전·후가 모두 있으면 변경 후 본문 위에 변경 전 본문을 겹쳐 두고, 세로 손잡이를 오른쪽으로 끌수록 변경 전이 같은 자리에서 드러난다(이미지 비교 슬라이더 방식). 변경 전 층은 테마의 background-yellow 황색 배경(다크에서는 어두운 올리브)이며 바깥쪽 모서리만 둥글고, 두 본문은 한 그리드 셀을 공유해 높이는 둘 중 큰 쪽이다. 변경 전·변경 후 버튼으로 한쪽을 바로 볼 수 있고 손잡이는 화살표·Home·End 키로도 움직인다. 추가·제거처럼 한쪽만 있으면 본문 하나만 보여준다. Astryx ResizeHandle은 1px 루트 안에서만 포인터를 받아 겹침 비교에 맞지 않았으므로 손잡이는 직접 구현했다. 선택은 URL의 selected에 저장한다. 이전의 같은 명세 연결 그래프는 읽기에 방해가 되어 2026-09-15에 제거했다.

본문은 1024px 중앙 컬럼이며 스크롤은 콘텐츠 카드가 담당한다. 제목은 스크롤로 사라지고 필터 줄은 상단 바 아래에 고정된다. 종류·기능·작성자·검색 필터는 불러온 범위에 적용한다. 검색창(`SearchFilter`)은 입력 중인 글자를 자기 상태로 들고 URL의 `q`에는 replace로 따라 반영한다. 입력을 URL에 직접 묶었을 때는 라우터의 비동기 갱신이 한글 조합 도중 이전 값을 되돌려 써서 "검색"이 "ㄱ거검검ㅅ새색색"처럼 쌓였다. 필드가 보낸 값이 늦게 돌아오는 것은 무시하고, 필드가 보내지 않은 값(뒤로가기, `q`가 담긴 링크)이 오면 그 값으로 바꾼다. 같은 검색창을 활동·기능별 요구사항·참여자가 함께 쓴다. 더보기는 기존 목록에 다음 페이지를 추가하며 실패 시 재시도할 수 있다. 모든 이력을 처음부터 한 번에 분석하지 않는다.

## 요구사항 목록과 기능 상세
<!-- gitifact-ref: R-xqf3xsumye -->

기능별 요구사항 메뉴(`/features`)의 목록은 활동 페이지와 같은 1024px 중앙 컬럼의 Astryx Table이며 한 행에 제목·설계 없음 표시·한 줄 설명, 요구사항 수와 가장 많은 기능 대비 ProgressBar, AvatarGroup 참여자(3명 초과는 +N), 상대 시각을 둔다. 제목 아래에 설명을 두면 설명이 있는 행만 높아져 훑어 내려가는 열의 리듬이 깨지므로 한 줄에 모으고 긴 설명은 자른다. 설계는 있는 것이 기본이라 없을 때만 제목 옆 Token으로 표시하고 전용 열을 두지 않는다. 요구사항 수는 숫자만으로는 다른 기능과 견줄 수 없어 막대를 함께 둔다. 필터 줄에는 검색과 설계 여부·참여자·정렬 Selector가 있고 값은 `design`·`author`·`sort` 검색 인자로, 기본 정렬은 최근 변경순이다(저장 순서는 작업 위치를 말해 주지 않는다). 좁혀지면 개수 옆에 전체 개수를 덧붙인다. 상세로 갈 때와 목록으로 돌아올 때 네 인자를 그대로 넘긴다. 서버가 기능마다 `.gitifact`와 `.tryce` 폴더 경로로 Git 로그(최대 2000개)를 읽어 contributors와 updatedAt을 응답에 담는다. 행이나 제목을 열면 `/features/<S-ID>` 경로로 이동해 같은 컬럼의 상세 페이지를 그리고 페이지 제목과 필터 줄은 숨긴다. 없는 S-ID는 찾을 수 없음 상태와 목록 링크를 보여준다. 상세의 요구사항 탭은 제목·본문·수용 조건을, 설계 탭은 문서 전체를 표시한다. 설계가 없으면 미작성 상태를 안내한다. 메뉴 이름은 2026-09-17에 제품 기능에서 요구사항으로, 2026-09-18에 기능 단위 목록임을 드러내도록 기능별 요구사항으로 바꿨다. 경로는 유지했다.

selected·tab은 URL 검색 인자에 저장한다. 이전의 `?feature=` 진입은 리다이렉트하지 않는다. 설계의 R-ID 참조는 현재 전체 기능에서 찾아 해당 요구사항으로 연결한다. 삭제된 참조는 현재 명세에 없다고 표시한다. 과거 설계의 링크도 현재 요구사항으로 연결한다. Markdown은 실행 지시가 아닌 데이터로 렌더링한다.

## 제품 개요
<!-- gitifact-ref: R-oh4oevufr3 -->

`/product`는 같은 명세 응답으로 그린다. 머리는 프로젝트 이름(Git 상태 응답의 체크아웃 폴더 이름)과 한 줄 규모(기능·요구사항·위키 페이지·참여자), 미커밋 Token, 최근 변경 시각이다. 오른쪽 끝에는 불러온 이력을 일자별로 센 21일 막대를 인라인 SVG로 둔다. 계열이 하나라 범례 대신 "최근 21일 변경 · 불러온 활동 N건"으로 센 범위를 밝힌다.

그 아래가 좌우 두 장의 차트 카드(변경 종류 비율, 참여자별 커밋)이고 두 카드는 높이가 같다(Grid `align="stretch"`). 참여자가 많아 범례가 두 줄이 되면 한쪽 카드만 길어지던 것을 2026-09-19 사용자 요청으로 맞췄다. 마지막이 "최근 변경 이력"이다. 이력은 기록마다 오지만 이유는 커밋에 붙으므로 커밋으로 묶어 그린다. 묶지 않으면 한 커밋이 건드린 기록마다 같은 문단이 되풀이된다. 커밋 하나는 작성자·시각, 이유 한 문장(두 줄로 자른다), 그 커밋이 건드린 기록 목록으로 이룬다. 한 커밋의 이유는 건드린 기록마다 따로 저장되지만 같은 의도라 첫 문장만 싣는다. 2026-09-19 사용자 요청으로 남은 개수를 알리던 "이유 N건 더"를 뺐다. 무엇이 가려졌는지 묻게 만들 뿐이고 전부는 활동 화면에 있다. 커밋은 셋까지 싣고 나머지는 활동 타임라인이 맡는다. 활동으로 가는 링크는 이 절의 제목 옆 하나뿐이다.

2026-09-19 사용자 요청으로 요약 타일 다섯 개와 페이지 제목을 걷어내고 변경 이유를 본문으로 삼았다. 타일이 이끌던 화면에는 제품이 기록하는 이유가 없었고 제목은 메뉴·이동 경로와 같은 말을 세 번째로 되풀이했다. 같은 요청에서 기능 현황 카드(살펴볼 곳·최근 손댄 기능)를 뺐고 차트 두 장은 그대로 두었다. 기능 전체 표는 기능별 요구사항 화면이 그린다. 위키 README는 위키 운영 방침이라 개요가 싣거나 링크하지 않는다. 위키에서 README를 읽을 때는 첫 블록이 이미지이면 워드마크와 겹치므로 그 한 장만 빼고, 상대 경로 이미지·링크는 문서 링크 절의 규칙으로 해석한다.

## 오류 처리와 검증
<!-- gitifact-ref: R-5eehizubwl -->

첫 조회의 골격 화면은 200ms 뒤에 나타나고 한번 보이면 최소 300ms 유지한 뒤 본문이 페이드인한다. 골격은 화면별로 실제 배치(활동은 세로 선·아바타·세 줄, 요구사항·참여자는 표 행, 제품 개요는 머리·카드 두 장·변경 이력, 위키는 트리·경로 줄·본문)를 본떠 교체 순간 레이아웃이 바뀌지 않게 한다. 위키 골격은 탐색기의 클래스를 그대로 써서 트리 폭과 경로 줄 높이가 실제와 같고, 트리 행(38px)과 폴더 목록 행(48px)도 실제 간격에 맞춘다. 페이지(`/wiki/$id`)는 제목·정보 세 칸·문단으로, 폴더(`/wiki`)는 테두리 있는 목록과 README 상자로 그린다. 2026-09-19 전까지 위키 골격은 지침 화면 시절의 열 배치 클래스를 쓰고 있었는데 그 클래스가 이미 지워져 모양 없이 그려졌다. 재조회 중 기존 내용을 유지하며 빈 결과·검색 결과 없음·조회 실패를 구분한다. HEAD·원문이 조회 중 바뀌거나 세션이 교체되면 다시 조회하도록 알린다.

계약 fixture로 선택·탭·필터·더보기·누락 참조·모바일·오류·대시보드 집계·위키 탐색기(트리·폴더 목록·페이지)·미커밋 표시를 검사하고, 실제 Git 저장소와 패키징된 서버로 조회를 확인한다. 성능은 실제 측정값으로 보고한다.

## Git 상태

Git 상태 페이지도 같은 중앙 컬럼과 헤더의 새로고침 버튼을 쓰며 헤더에 마지막 관측 시각을 "조회"로 표시한다. 브랜치·HEAD·저장소를 MetadataList로, Staged·Unstaged·Untracked·충돌 집계를 한 줄로, 변경 경로를 Table로 보여준다. 표의 상태 열은 porcelain 두 글자 코드를 Staged·Unstaged·Untracked·충돌 Token으로 풀어 표시하고 원래 코드는 옆 열에 둔다. 변경이 없으면 빈 상태 일러스트를, 관측 한계와 gitifact 검사 미실행 안내는 하단 상태 줄에 둔다. 미커밋 명세 변경이 있으면 본문 맨 위에 경고 Banner를 둔다.

## 화면 확대

루트 글자 크기는 1920px까지 100%이고 그 위로는 뷰포트에 비례해 2560px에서 18px에 닿는다. Astryx의 spacing·size-element 토큰은 px로 배포되므로 같은 16px 기준값을 rem으로 다시 선언해 글자와 간격이 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 주요 설계 결정과 제한

첫 화면은 제품 개요 대시보드다. 2026-09-18 사용자 요청으로 활동에서 바꿨다. 요구사항과 설계는 같은 이력에서 종류를 구분하고 공통 원문을 중복 저장하지 않는다. 집계 차트는 라이브러리 없이 SVG·ProgressBar로 그린다. 문서의 다이어그램만 mermaid를 번들에 담으며 그 대가는 결정 0008에 있다. 현재 캐시는 메모리 기반이며 영속 로컬 색인은 아직 구현하지 않았다. 편집·승인 UI와 작업 파일 표시는 범위 밖이다.

## 문서 읽기
<!-- gitifact-ref: R-wa3wnknrlt -->

위키 페이지·요구사항 본문·설계·활동 전후 본문·소개는 shared/ui/document의 DocumentBody로 렌더링한다. Astryx Markdown은 문단을 680px로 제한하면서 표·코드·구분선은 전체 폭으로 그려 오른쪽 끝이 어긋나므로, 읽기 영역을 48rem 한 폭으로 묶고 contentWidth를 100%로 둔다. 크기는 Astryx 글자 토큰을 읽기 영역에서 재정의해 맞춘다. 본문 16px·줄 간격 1.8, 코드 14px, 제목은 어느 단계에서도 본문보다 크게 잡고 위 간격을 아래보다 넓게 준다. 표는 테두리·둥근 모서리·옅은 머리글 행과 내부 가로 스크롤, 인용은 옅은 바탕과 왼쪽 선, 인라인 코드는 테두리 있는 칩, 링크는 테마상 글자색과 같으므로 밑줄로 구분한다. 지침 미리보기 열과 기능 설명 한 줄은 좁은 자리라 compact 표시를 유지한다.

코드 펜스는 `components.code`를 우리 렌더러로 바꿔 받는다. 언어가 `mermaid`면 다이어그램으로 그리고 나머지는 Astryx CodeBlock 그대로다. Astryx는 이 슬롯을 바꾸면 자기 감싸개까지 내주므로 블록 사이 간격은 document.module.css의 클래스가 대신 준다. stone 테마의 구문 색은 모두 회색 계열이라 하이라이팅이 보이지 않으므로, GitHub 라이트·다크 값을 한 쌍으로 묶은 구문 테마(shared/ui/document/syntax.ts)를 앱 전체에 SyntaxTheme으로 적용한다. 일반 식별자·구두점·주석·배경은 테마 토큰을 써서 모든 색 조합과 어울린다. Astryx 토크나이저가 모르는 언어(markdown·text 등)는 색 없이 나온다. Tailwind 기반인 fumadocs 스타일을 들여오는 안은 디자인 체계가 둘이 되어 기각했다.

다이어그램은 mermaid 11이며 `import('mermaid')`로만 불러 자기 청크에 남는다. 다이어그램이 없는 문서는 그 청크를 내려받지 않고, 파일은 패키지에 함께 담겨 있어 네트워크를 쓰지 않는다. mermaid는 색을 SVG 안에 써 넣어 `var(--color-*)`를 스스로 읽지 못하므로, 그리기 직전에 그 자리에서 토큰으로 칠한 탐침 요소의 계산된 색(`rgb(…)`)을 읽어 themeVariables로 넘기고 화면 모드·색 조합이 바뀌면 다시 그린다. `securityLevel: 'strict'`로 원문의 click 지시를 거부한다. 라벨은 `htmlLabels: false`로 SVG 텍스트로 그린다. 종류별 설정만으로는 꺼지지 않아 최상위 설정도 함께 준다. 폭이 열보다 넓은 그림은 열에 맞춰 축소되는데, foreignObject 안의 HTML 라벨은 축소를 따르지 않아 상자 밖으로 삐져나오기 때문이다. mermaid는 그림을 문서에 넣어 크기를 재므로, 그 자리를 화면 밖 고정 위치의 요소 하나로 지정한다. 기본값인 `<body>`에 재면 문서가 잠깐 뷰포트보다 커져 스크롤바가 생겼다 사라지고 화면이 좌우로 흔들린다. 재는 요소를 숨기면(visibility:hidden) 폭이 0으로 측정되므로 화면 밖에 두되 숨기지 않는다. 글꼴이 도착하기 전에 재면 상자가 작게 잡히므로 `document.fonts.ready`를 기다린다. 문법이 잘못된 펜스는 문서 전체를 잃지 않도록 그 자리에만 원문 CodeBlock과 파서 메시지를 보여 준다. 렌더러가 만든 SVG는 문자열이라 그 자리에만 innerHTML로 넣으며, 이는 원문 Markdown의 HTML을 실행하지 않는다는 규칙과 별개다. CDN 로딩은 오프라인 동작과 어긋나 기각했고, 그림을 이미지로 미리 굽는 안은 원문이 저장소에서 바로 읽혀야 해 기각했다.

GitHub 알림(`> [!NOTE]` 등 다섯 종류)은 `components.blockquote`에서 가른다. Astryx는 인용 안의 내용을 이미 React 요소로 만들어 넘기므로, 첫 글자 뭉치에서 표지를 떼어 내고 남은 내용을 그대로 쓴다. 표지가 없으면 Astryx Blockquote 그대로다. Astryx는 Blockquote를 인용에만 쓰라고 하므로 알림 상자는 VStack·HStack·Text와 색 토큰(blue·green·purple·yellow·red)으로 짰다. 종류 이름은 다른 화면 문구와 같이 shared/i18n에 둔다. 원문을 미리 고쳐 넣는 안은 Markdown 인스턴스가 쪼개져 제목 id와 목차가 어긋나므로 기각했다.

## 문서 검색
<!-- gitifact-ref: R-fqlesmxflt -->

`mod+K`와 머리의 검색 버튼이 같은 창을 연다. 열림 여부는 `shared/lib/search`의 작은 저장소가 들고, 팔레트는 셸이 한 번 그리며 버튼은 헤더가 그린다. 두 위젯이 서로를 참조하지 않게 상태만 shared에 둔다.

Astryx CommandPalette를 쓰고 검색 재료는 첫 페이지가 이미 준 체크아웃이다. 기능·요구사항·설계·위키 페이지를 한 줄씩 항목으로 펼치고, 본문은 Markdown 표시를 걷어낸 글로 비교한다. 제목이 맞으면 앞에, 본문만 맞으면 뒤에 둔다. 분류는 `auxiliaryData.group`으로 묶이며 순서는 잘 맞은 것이 먼저다. 항목 한 줄은 제목·위치·맞은 대목이고 맞은 글자를 표시한다. 고르면 위키는 `/wiki/$documentId`, 요구사항과 설계는 기능 상세의 해당 탭으로 보낸다.

팔레트를 다루며 고친 것들이다. searchSource를 매 렌더 새로 만들면 선택 강조가 풀려 Enter가 아무것도 열지 못했으므로 한 번만 만든다. 강조가 없을 때 Enter가 죽어 있어, 입력의 keydown에서 강조가 없으면 첫 결과를 연다. 팔레트는 열릴 때와 타자마다만 검색하고 다시는 하지 않으므로, 문서를 읽기 전에 입력한 낱말이 빈 결과로 굳지 않도록 검색이 자료 도착을 기다렸다가 답한다. 디바운스로 밀린 약속은 버리지 않고 마지막 결과로 함께 끝낸다. 버리면 그 transition이 끝나지 않아 대기 표시가 계속 돌았다. 여는 목록과 검색은 큐를 나눈다. 같이 쓰면 타자가 여는 목록의 약속을 대신 답해 두 목록이 한꺼번에 보였다.

결과 영역은 22rem 고정이다. 결과 수에 맞추면 타자마다 창이 커졌다 작아졌다 했다. 읽는 중에는 결과 줄과 같은 규격의 골격을, 맞는 문서가 없으면 PageState의 검색 일러스트를 같은 자리에 둔다. 검색 대상을 이력 본문까지 넓히려면 브라우저로 다 내려보내는 방식이 아니라 서버 검색이 필요하므로, 그때 목록에서 변경 전후 본문을 덜어내는 일과 함께 정한다.

## 설정과 색 조합
<!-- gitifact-ref: R-jsncmqoqjm -->

WORKSPACE 그룹의 마지막 메뉴인 `/settings`에서 화면 모드(시스템·라이트·다크)와 색 조합을 고른다. 선택은 shared/lib/appearance가 localStorage(`gitifact-appearance`)에 저장하고 useSyncExternalStore로 구독하며, 다른 탭의 변경도 storage 이벤트로 따른다. 서버나 프로젝트에는 아무것도 보내지 않는다. 저장값이 깨져 있으면 기본값(시스템·스톤)을 쓰고 저장소를 쓸 수 없으면 그 페이지 동안만 유지한다. AppProviders가 Astryx Theme의 theme와 mode에 반영한다.

라이트 모드의 글자색은 모든 조합에서 거의 검정보다 한 단계 밝힌다(스톤 `#25252a`→`#3a3a40`, 세이지 `#3b4439`, 올리브 `#36372e`, 슬레이트 `#36415a`, 클레이 `#473b34`). 2026-09-19 사용자가 라이트 모드의 글자와 로고가 너무 어둡다고 해 SandboxHr의 값을 따랐다. 워드마크는 글자색으로 그려지므로 함께 밝아진다. 다크 모드는 그대로다. 그래서 스톤도 prebuilt 테마를 그대로 쓰지 않고 stone 소스를 extends해 글자 토큰 두 개만 바꾼다. 첫 화면은 전역 CSS가 가져오는 stone theme.css로 그려지고 바뀐 글자 토큰은 런타임에 주입된다. 나머지 조합(세이지 & 크림, 올리브 & 웜그레이, 슬레이트 & 블루, 샌드 & 클레이)은 stone 소스를 extends해 글꼴·모서리·아이콘·컴포넌트 재정의를 물려받고 색 토큰 16개만 라이트·다크 쌍으로 명시한다. 값은 Gentask의 팔레트와 hoho-hr의 Halo · Olive 토큰(OKLCH를 hex로 변환)에서 가져왔다. 강조색 하나에서 나머지를 유도하는 방식(color.accent 시드)은 기각했다. stone은 링크와 메뉴 글자가 강조색 토큰을 글자색으로 쓰기 때문에 색이 글자·메뉴·바탕 전체로 번진다. 그래서 글자용 강조 토큰(`--color-text-accent`·`--color-icon-accent`)은 조합의 글자색을 따르고, 채도 높은 강조색은 선택 표시·진행 막대·버튼에만 나타난다. 설정 카드의 미리보기는 라이트·다크 각각의 바탕·표면·강조 점·글자 선을 축소판으로 그린다.

## 문서 링크

문서 링크는 원문을 두고 렌더링 때 번역한다. `resolveDocumentLink.ts`가 문서의 저장소 경로(`from`)와 링크로 대상을 계산한다. 스킴이 있거나 `//`로 시작하면 외부(새 탭, noopener), `#`만 있으면 페이지 안 앵커, `/`로 시작하면 앱 경로다. 그 밖은 `from`의 폴더 기준으로 `.`·`..`를 풀어 저장소 상대 경로를 만들고, 위키 페이지 경로와 같으면 `/wiki/$documentId`, `spec/<기능>/requirements.md`·`design.md`면 `/features/$featureId`의 해당 탭, `.gitifact/assets/` 아래면 `/api/v1/assets/<인코딩한 경로>`로 바꾼다. 저장소 루트 위로 올라가거나 그 밖의 저장소 파일이면 "브라우저 밖" 상태다. href 없는 Astryx Link를 흐린 색과 점선 밑줄로 그리고 Tooltip을 붙이며, 클릭하면 clipboard에 저장소 경로를 복사하고 toast로 알린다. 대상이 없는 페이지·기능은 취소선 Text와 툴팁이다(비활성 button은 hover가 없어 툴팁이 뜨지 않아 링크 모양을 쓰지 않았다). 이미지는 같은 규칙으로 src를 바꾸고 해석되지 않으면 대체 텍스트만 보인다. 문서 경로는 `DocumentBody`의 `path`로 받아 context에 두고, `DocumentIndexProvider`가 첫 명세 응답의 페이지·기능 목록을 제공한다. 서버는 `.gitifact` 밖 파일을 제공하지 않는다.

설계 탭은 `sources`가 있으면 본문 위에 "참고 문서" 목록을 compact List로 그린다. 제목이 링크(위키 경로는 같은 해석 규칙, url은 새 탭)이고 설명에 note와 호스트 또는 상대 경로를 둔다. 카드 대신 행으로 둔 것은 디자인 시스템 지침의 조밀한 자료 규칙을 따른 것이다.
