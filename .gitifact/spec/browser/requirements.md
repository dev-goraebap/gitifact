# 요구사항 브라우저

## 최신순 활동 타임라인
<!-- gitifact-req: R-tkl3lrrlpu -->

프로젝트 참여자로서, 최근 무엇이 왜 달라졌는지 파악하기 위해 요구사항과 설계의 변경 이력을 최신순으로 살펴보고 필요한 기능의 활동을 골라 보고 싶다.

### 범위와 제약

활동 페이지는 요구사항·설계의 추가·변경·제거·이동을 최신순 타임라인으로 보여주고 기능으로 필터링한다. 현재 명세와 요약 대시보드를 별도 첫 화면으로 강제하지 않는다.

### 수용 조건

1. 조건: 사용자가 이력 항목이나 기능 필터를 선택합니다.
   기대 동작: 해당 요구사항의 변경 전후와 이유를 상세 서랍에서 확인하고 관련 제품 기능으로 이동할 수 있습니다. 서랍은 데스크톱에서 오른쪽에 붙고 너비를 조절할 수 있으며 모바일에서는 전체 화면입니다. 닫으면 필터와 스크롤 위치를 유지한 목록으로 돌아갑니다.

2. 조건: 사용자가 오래된 이력을 더 확인합니다.
   기대 동작: 더보기로 다음 이력을 이어 불러옵니다. 기존 목록을 유지하고 추가 조회 중·실패 후 재시도·마지막 이력 상태를 구분합니다. 검색과 필터가 불러온 범위에 적용됨을 안내합니다.

3. 조건: 요구사항 또는 설계를 변경해 커밋합니다.
   기대 동작: 명세 이력에서 요구사항과 설계의 변경을 구분하고 같은 커밋의 항목을 함께 표시합니다. 전체·요구사항·설계 필터로 좁히고 설계의 변경 전후·이유를 확인할 수 있습니다.

각 항목에는 작성자·상대 시각, 변경 종류·명세 종류·제목·기능, 커밋과 변경 이유 한 줄을 표시한다. 이유가 없으면 미기록 상태를 안내하고, 변경 후 원문은 상세에서 확인한다. 항목 사이의 관계 그래프는 두지 않는다.

## 작성자 표시와 관계 표현 금지
<!-- gitifact-req: R-hsflueyc4b -->

프로젝트 참여자로서, 변경의 작성자를 확인하고 이력을 오해하지 않기 위해 실제 Git 작성자와 기록에 근거한 활동 표시를 보고 싶다.

### 범위와 제약

타임라인은 항목마다 Git author 기반 로컬 아바타를 세로 선 위에 표시한다. 같은 요구사항의 변경을 잇는 관계 그래프는 두지 않으며, Git 브랜치 병합이나 무관한 요구사항을 관계로 꾸미지 않는다.

### 수용 조건

1. 조건: 이력 목록을 표시합니다.
   기대 동작: Git author 이름과 이메일 기반 로컬 아바타를 표시합니다. 요구사항·설계 사이의 관계를 선이나 그래프로 꾸며내지 않습니다.

## 기능별 현재 명세
<!-- gitifact-req: R-xqf3xsumye -->

프로젝트 참여자로서, 기능이 현재 어떤 동작을 요구하는지 이해하기 위해 기능별 최신 명세와 수용 조건을 함께 읽고 싶다.

### 범위와 제약

요구사항 메뉴의 목록은 명세 파일(기능) 단위로 구성하고 그 안의 요구사항과 수용 조건을 제공한다.

### 수용 조건

1. 조건: 사용자가 기능이나 요구사항을 선택합니다.
   기대 동작: 실제 S-ID·R-ID에 연결된 현재 내용을 읽고 관련 이력으로 이동할 수 있습니다. 조건·기대 동작을 불필요한 박스 없이 표현합니다.

기능 목록은 표로 제목·설명·요구사항 수·설계 유무·참여자·최근 변경을 보여주고, 기능을 열면 목록 대신 같은 폭의 상세 페이지로 바뀐다. 참여자는 기능 폴더를 바꾼 커밋의 Git author를 겹친 아바타로 표시하며 커밋 전 기능은 미커밋으로 표시한다. 기능 상세는 요구사항·설계 탭을 제공한다. 설계가 없으면 미작성 상태를 안내한다. 설계의 관련 R-ID는 현재 소속 기능의 요구사항 항목으로 연결하고 현재 없으면 이를 알린다. 탭과 선택은 URL로 복원한다. 미커밋 명세 변경은 목록 위 문장이 아니라 Git 상태 메뉴의 표시와 Git 상태 페이지의 안내로 알린다.

## 읽기 전용 조회와 응답성
<!-- gitifact-req: R-5eehizubwl -->

프로젝트 참여자로서, 원본을 바꾸지 않고 현재 작업의 기록을 확인하기 위해 조회 상태를 구분할 수 있는 읽기 전용 브라우저를 사용하고 싶다.

### 범위와 제약

브라우저는 React·Astryx와 프로젝트 프론트엔드 지침을 따른다. 조회로 원본을 수정하지 않고 worktree·세션을 구분한다.

### 수용 조건

1. 조건: 사용자가 최초 조회·재조회하거나 파일이 바뀝니다.
   기대 동작: 최신 목록부터 읽고 재생성 가능한 Git 제외 색인과 캐시를 활용합니다. 변경과 오류를 숨기지 않으며 로딩·빈 결과·오류를 구분합니다. 성능 목표는 실제 측정값과 함께 보고합니다.

2. 조건: 데이터 조회가 진행되거나 결과가 비어 있습니다.
   기대 동작: 짧은 조회에는 로딩을 깜빡이지 않고, 지연되는 조회에는 골격 화면을 표시합니다. 재조회 중에는 기존 내용을 유지하고 빈 결과·검색 결과 없음·오류를 구분한 안내를 제공합니다.

3. 조건: 사용자가 브라우저를 탐색합니다.
   기대 동작: 로고와 어울리는 두꺼운 제목 폰트와 메뉴별 Hugeicons 아이콘을 제공합니다. 폰트와 빈 화면 일러스트는 외부 서비스 요청 없이 로컬에서 표시합니다.

## 화면 모드와 색 조합 설정
<!-- gitifact-req: R-jsncmqoqjm -->

Gitifact 브라우저를 쓰는 사용자로서, 오래 읽어도 편한 화면으로 기록을 보기 위해 밝은·어두운 모드와 색 조합을 내 취향에 맞게 고르고 싶다.

### 범위와 제약

설정은 그 브라우저에만 저장하는 개인 취향이며 프로젝트 기록이나 서버에 남기지 않는다. 색 조합은 모두 라이트와 다크를 함께 갖고, 글자는 무채색에 가깝게 유지해 어느 조합에서도 본문의 가독성이 달라지지 않는다.

### 수용 조건

1. 조건: 사용자가 설정에서 화면 모드를 시스템·라이트·다크 중에서 고릅니다.
   기대 동작: 화면이 즉시 바뀌고, 시스템을 고르면 운영체제 설정을 따릅니다.
2. 조건: 사용자가 색 조합을 고릅니다.
   기대 동작: 바탕·표면·강조색이 그 조합으로 바뀌되 메뉴와 본문 글자는 그 조합의 글자색으로 유지됩니다. 현재 조합은 선택 해제되지 않고 다른 조합으로만 바뀝니다.
3. 조건: 사용자가 페이지를 새로 고치거나 다른 메뉴로 이동합니다.
   기대 동작: 고른 모드와 조합이 유지됩니다. 저장된 값을 읽을 수 없으면 기본값으로 보여 줍니다.

## 문서 링크의 브라우저 해석
<!-- gitifact-req: R-wgi4sahmou -->

문서를 읽는 참여자로서, 원문의 파일 링크를 그대로 따라가기 위해 브라우저에서 문서 사이의 상대 링크가 404 없이 해당 화면으로 이어지기를 원한다.

### 범위와 제약

원문은 바꾸지 않는다. 위키 페이지·명세·에셋으로 가는 링크는 해당 화면과 에셋 주소로, 외부 URL은 새 탭으로 연결한다. gitifact 문서가 아닌 저장소 파일은 브라우저가 열지 않으며 경로만 복사할 수 있다. 서버가 `.gitifact` 밖의 파일을 제공하거나 원격 저장소 주소로 바꾸는 방식은 쓰지 않는다.

### 수용 조건

1. 조건: 위키 페이지 본문에 다른 페이지나 명세로 가는 상대 링크가 있습니다.
   기대 동작: 클릭하면 그 페이지 또는 기능 상세의 해당 탭으로 이동합니다.
2. 조건: 본문이 에셋 이미지를 상대 경로로 참조합니다.
   기대 동작: 이미지가 본문에 표시됩니다.
3. 조건: 링크가 저장소의 다른 파일(예: docs/…)을 가리킵니다.
   기대 동작: 이동하지 않고 안내 툴팁을 보이며, 클릭하면 저장소 경로가 복사됩니다.
4. 조건: 링크 대상 페이지가 현재 명세에 없습니다.
   기대 동작: 이동하지 않는 표시와 대상 경로를 보여 줍니다.
