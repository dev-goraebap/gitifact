프로젝트 참여자로서, 기능이 현재 어떤 동작을 요구하는지 이해하기 위해 기능별 최신 명세와 수용 조건을 함께 읽고 싶다.

### 범위와 제약

기능별 요구사항 메뉴의 목록은 명세 파일(기능) 단위로 구성하고 그 안의 요구사항과 수용 조건을 제공한다. 목록은 검색어·설계 여부·참여자로 좁히고 정렬 기준을 고를 수 있으며, 고른 조건은 주소에 남아 상세를 열고 돌아와도 유지된다.

### 수용 조건

1. 조건: 사용자가 기능이나 요구사항을 선택합니다.
   기대 동작: 실제 S-ID·R-ID에 연결된 현재 내용을 읽고 관련 이력으로 이동할 수 있습니다. 조건·기대 동작을 불필요한 박스 없이 표현합니다.


2. 조건: 사용자가 설계 여부·참여자를 고르거나 검색어를 입력합니다.
   기대 동작: 목록이 그 조건으로 좁혀지고 남은 개수와 전체 개수를 함께 알립니다. 고른 조건은 기능을 열고 목록으로 돌아올 때까지 유지됩니다. 맞는 기능이 없으면 조건을 바꾸라고 알립니다.

3. 조건: 사용자가 견줄 값이 있는 열의 머리를 누릅니다.
   기대 동작: 그 열 기준으로 기능의 순서가 바뀌고 어느 열로 정렬 중인지와 방향을 열 머리가 알립니다. 한 번 더 누르면 방향이 뒤집힙니다. 기본은 최근 변경 내림차순이며 고른 순서는 주소에 남습니다. 견줄 값이 없는 열은 정렬을 제공하지 않습니다.

기능 목록은 표로 제목과 한 줄 설명, 요구사항 수와 그 크기 비교, 참여자, 최근 변경을 보여주고 그 기능의 요구사항을 아래에 한 행씩 잇는다. 요구사항 행을 고르면 상세의 그 요구사항으로 이동하며 주소의 프래그먼트가 그 위치를 가리킨다. 목록은 기능 단위로 페이지를 나누어 한 기능의 요구사항이 페이지에 걸쳐 끊기지 않게 하고, 요구사항이 아주 많은 기능은 일부만 보인 뒤 나머지를 상세로 잇는다. 기능 행은 한 줄이며 모든 기능 행의 높이가 같다. 설계는 있는 것이 기본이라 없는 기능만 제목 옆에 표시하고, 기능을 열면 목록 대신 같은 폭의 상세 페이지로 바뀐다. 참여자는 기능 폴더를 바꾼 커밋의 Git author를 겹친 아바타로 표시하며 커밋 전 기능은 미커밋으로 표시한다. 기능 상세는 요구사항·설계 탭을 제공한다. 요구사항 탭은 맨 위에 기능 소개(index.md 본문)를 한 번 보여 주고 그 아래에 요구사항을 잇는다. 설계가 없으면 미작성 상태를 안내한다. 설계의 관련 R-ID는 현재 소속 기능의 요구사항 항목으로 연결하고 현재 없으면 이를 알린다. 반대로 요구사항에서는 그 요구사항을 설명하는 설계 절로 이동할 수 있다. 요구사항과 설계의 제목은 형광펜 표시로 서로 구분되고, 다른 화면에서 특정 요구사항이나 설계로 들어오면 그 절에 빗금 바탕을 깔아 어느 것을 보러 왔는지 알리며, 주소를 직접 열어도 그 위치에서 시작한다. 탭과 선택은 URL로 복원한다. 미커밋 명세 변경은 목록 위 문장이 아니라 Git 상태 메뉴의 표시와 Git 상태 페이지의 안내로 알린다.
