프로젝트 참여자로서, 원본을 바꾸지 않고 현재 작업의 기록을 확인하기 위해 조회 상태를 구분할 수 있는 읽기 전용 브라우저를 사용하고 싶다.

### 범위와 제약

브라우저는 React·Astryx와 프로젝트 프론트엔드 지침을 따른다. 조회로 원본을 수정하지 않고 worktree·세션을 구분한다.

### 수용 조건

1. 조건: 사용자가 최초 조회·재조회하거나 파일이 바뀝니다.
   기대 동작: 최신 목록부터 읽고 재생성 가능한 Git 제외 색인과 캐시를 활용합니다. 변경과 오류를 숨기지 않으며 로딩·빈 결과·오류를 구분합니다. 성능 목표는 실제 측정값과 함께 보고합니다.

2. 조건: 브라우저를 연 채로 에이전트가 문서를 고치거나 커밋한 뒤, 사용자가 브라우저 탭으로 돌아옵니다.
   기대 동작: 화면은 그대로 두고 새 변경이 있다는 알림과 새로 고침을 보입니다. 새로 고침을 누르면 지금 상태로 다시 읽습니다. 변경이 없으면 알림을 보이지 않습니다.

3. 조건: 데이터 조회가 진행되거나 결과가 비어 있습니다.
   기대 동작: 짧은 조회에는 로딩을 깜빡이지 않고, 지연되는 조회에는 화면마다 로딩 표시를 한 번만 보인 뒤 본문을 한꺼번에 보입니다. 재조회 중에는 기존 내용을 유지하고 빈 결과·검색 결과 없음·오류를 구분한 안내를 제공합니다.

4. 조건: 사용자가 브라우저를 탐색합니다.
   기대 동작: 로고와 어울리는 두꺼운 제목 폰트와 메뉴별 Hugeicons 아이콘을 제공합니다. 폰트와 빈 화면 일러스트는 외부 서비스 요청 없이 로컬에서 표시합니다.

5. 조건: 사용자가 검색창에 한글을 입력기로 조합해 입력합니다.
   기대 동작: 조합 중인 글자가 끊기거나 겹쳐 쌓이지 않고 입력한 그대로 보이며 그 검색어로 목록이 좁혀집니다.

6. 조건: 이력을 더 불러온 뒤 다른 화면에 갔다가 돌아옵니다.
   기대 동작: 불러온 이력이 그대로 남아 있고 서버에 다시 묻지 않습니다. 다시 읽는 시점은 새로고침뿐이며, 그때는 불러온 페이지를 모두 다시 읽습니다.

7. 조건: 브라우저 서버를 다시 띄우거나 새 커밋이 생긴 뒤 이력을 엽니다.
   기대 동작: 이미 읽은 이력은 다시 읽지 않고 새 커밋만 더 읽습니다. 이 색인은 작업 폴더와 git status에 나타나지 않으며, 지우거나 손상돼도 다음 조회 때 다시 만들어집니다.
