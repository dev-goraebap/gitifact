## 메뉴와 경로

CLI 로컬 서버가 정적 앱과 API를 함께 제공하고, 브라우저는 제품 개요에서 시작한다. 현재 원문은 작업 폴더에서, 이력의 전후·작성자·시점은 Git에서 읽으며 둘 다 로컬 캐시(data 설계의 캐시와 질의 절)를 거친다.

| 그룹 | 메뉴 | 경로 | 상세 경로 |
| :--- | :--- | :--- | :--- |
| WORKSPACE | 제품 개요 | `/product` | — |
| | 기능별 요구사항 | `/features` | `/features/<S-ID>` |
| | 프로젝트 지침 | `/instructions` | `/instructions/agents`, `/instructions/<I-ID>?file=<경로>` |
| | 결정기록 | `/records` | `/records/<기록 ID>`, `/records/commits/<커밋>` |
| | 참여자 | `/contributors` | `/contributors/<이메일>` |
| | Git 상태 | `/git` | — |
| | 설정 | `/settings` | — |
| GITIFACT | 소개 | `/about` | — |
| | 시작하기 | `/getting-started` | — |
| | 패치노트 | `/changelog` | — |

표의 순서가 메뉴 순서다. `/`는 검색 인자와 관계없이 `/product`로 replace 리다이렉트한다.

왼쪽 메뉴는 Astryx SideNav의 resizable 옵션으로 너비를 200~400px 사이에서 조절하고, 그 값을 localStorage에 둔다.

## 작업 중인 변경 표시

커밋하지 않은 명세 변경은 문장 대신 표시로 알린다. 셸의 `useWorkingChanges`가 두 출처를 본다. 하나는 명세 Query 캐시의 `working`이고, 다른 하나는 모든 페이지가 이미 읽는 Git 상태 응답 중 `.gitifact/` 아래의 변경 경로다. 이 훅은 명세 API를 스스로 부르지 않는다. Git 상태 페이지로 바로 들어오면 명세 캐시가 비어 있으므로 두 번째 출처가 필요하다.

변경이 있으면 Git 상태 메뉴에 경고 StatusDot을 붙인다. Git 상태 페이지는 상단 Banner에 "제품 개요·기능별 요구사항·프로젝트 지침 화면은 작업 중인 내용이고 결정기록은 커밋된 내용"임을 적는다.

## 결정기록

### 타임라인

한 항목이 커밋 하나인 타임라인이다. 왼쪽 세로 선 위에 작성자 아바타를 두고, 날짜가 바뀌는 자리에는 날짜 표시를 두며 세로 선을 끊는다.

| 부분 | 내용 |
| :--- | :--- |
| 머리 | 작성자(참여자 링크), "기록 N건"과 "문서 N건", 상대 시각, 짧은 커밋 해시, 커밋 제목 |
| 기록 줄 | 커밋이 더한 결정기록마다 한 줄 묶음. 기록 제목(기록 상세 `/records/<기록 ID>`로 가는 링크), 결정 섹션의 첫 줄, 그 기록이 설명하는 문서 줄 3개까지 |
| 기록 없는 변경 | 어느 기록도 설명하지 않는 변경은 마지막에 문서 줄로 모은다. 그중 수정·이동·삭제가 있을 때만 "결정기록 없이 바뀐 문서"를 붙인다 |

기록 줄의 둘째 줄은 결정 섹션(없으면 첫 섹션)의 첫 줄을 한 줄 글로 보인다. 목록은 Markdown을 그리지 않으므로 코드 표시·굵게·링크 대상 같은 표기를 지운다. 섹션 전체(맥락·결정·검토한 대안)는 목록에 적지 않고 기록 상세에서 읽는다.

문서 줄은 변경 종류와 문서 종류를 붙인 배지, 그 바로 뒤에 `기능 · 문서 제목`이다. 기록 아래의 문서 제목은 기록 상세의 그 문서(`/records/<기록 ID>#<문서 ID>`)로, 기록 없는 변경의 문서 제목은 커밋 페이지의 그 문서 절(`/records/commits/<커밋>#<문서 ID>`)로 간다. 한 기록이 문서를 3개보다 많이 설명하면 "문서 N건 더 →"로 기록 상세에 잇는다. 한 커밋은 기록을 5개까지 보이고 나머지는 "기록 N건 더 →"로 커밋 페이지에 맡긴다.

문서 변경은 기능 S-ID, 요구사항 R-ID, 설계 D-ID, 지침 I-ID, 위키 W-ID를 각각 비교해 추가·변경·제거·이동으로 표시한다. 0.8.0 마이그레이션 전 이력의 설계는 기능 S-ID로 비교한다. 저장 형식의 이름(created·modified·deleted·moved)은 화면 이름과 별개로 그대로 둔다.

문서 수는 그 항목에서 지금 보이는 문서 변경의 수다. 서버는 커밋별 전체 건수를 주지 않고 페이지는 커밋 중간에서도 끊긴다. 페이지에 걸친 커밋은 다음 페이지를 불러오면 한 항목으로 합쳐지고 수도 함께 올라간다.

### 목록의 조회와 필터

본문은 1024px 중앙 컬럼이고 스크롤은 콘텐츠 카드가 맡는다. 제목은 스크롤로 사라지고 필터 줄은 상단 바 아래에 고정된다. 종류·기능·작성자·검색 필터는 서버가 전체 이력에 적용하며, 목록 아래에 "전체 N건 중 M건"을 알린다. 조건을 바꾸는 동안에는 이전 결과를 유지한다.

검색창(`SearchFilter`)은 입력 중인 글자를 자기 상태로 들고 URL의 `q`에는 replace로 따라 반영한다. 검색창이 보낸 값이 늦게 돌아오면 무시하고, 뒤로가기나 `q`가 담긴 링크처럼 밖에서 온 값이면 그 값으로 바꾼다. 같은 검색창을 활동·기능별 요구사항·참여자가 함께 쓴다.

더보기는 다음 50건을 목록에 더하고 실패하면 재시도할 수 있다. 불러온 페이지는 다른 화면에 다녀와도 남긴다. 커밋 항목은 이벤트·기능 객체의 동일성으로 비교하는 memo 컴포넌트라서, 더보기 때 새 커밋만 그린다. 한 줄 자르기는 CSS로 한다.

### 커밋 페이지

`/records/commits/<커밋>`은 커밋 하나를 `/api/v1/commit`으로 한 번에 받아 그린다. 받는 동안 글줄 모양 골격을, 실패하면 오류를 보이고 한 번 받은 커밋은 세션 동안 다시 묻지 않는다. 목록이 아니라 커밋으로 받으므로 목록에 없는 커밋의 링크도 열린다. 읽을 것이 산문이 아니라 두 벌의 원문이라 64rem 대신 96rem 컬럼을 쓴다(`isWide`).

페이지는 위에서 아래로 다음 순서다.

1. "← 결정기록" 링크, 머리: 커밋 메시지(제목), 그 아래 한 줄에 작성자·상대 시각·로컬 날짜와 시각·해시(커미터가 다르면 커미터)
2. 결정기록 절: 커밋이 더한 기록의 제목(기록 상세로 가는 링크)과 "문서 N건"의 목록. 기록이 없으면 "이 커밋에는 결정기록이 없습니다."를 보인다. 기록 없이 수정·이동·삭제된 문서가 있으면 "결정기록 없이 바뀐 문서"와 그 문서 칩(문서 종류 토큰과 제목)을 두고, 칩은 아래의 그 문서 절로 간다
3. 바뀐 문서 절: 문서마다 한 절(앵커는 문서 ID). 배지, 제목, ID, 경로, 현재 문서 링크, 이 문서의 이력, 변경 비교
4. 같은 커밋의 소스 변경(`CommitSource`)

"같은 커밋의 소스 변경"은 그 커밋이 문서 밖에서 바꾼 파일을 한 줄씩 보이는 Astryx CollapsibleGroup이다. 줄마다 상태 Token, 경로(이동이면 `옛 경로 → 새 경로`), `+N −M`을 둔다. 행을 열 때만 그 파일의 양쪽을 받아 `LineDiff`로 보이고, 이진 파일과 큰 파일은 원문 대신 이유를 알린다. 한 커밋이 파일 수백 개를 바꿀 수 있으므로 닫힌 행은 아무것도 읽지 않는다.

### 기록 상세

`/records/<기록 ID>`는 기록 하나를 읽는 페이지다. 기록 ID는 `DR-`이거나, 과거 커밋에서 읽은 기록 도입 전 이유이면 `H-`다. 먼저 `/api/v1/record`로 현재 HEAD 이력에서 그 기록을 더한 커밋을 찾고, 그 커밋을 커밋 페이지와 같은 `/api/v1/commit` 조회로 읽는다. 받은 커밋은 세션 동안 두 페이지가 함께 쓴다. 커밋 페이지와 같은 96rem 컬럼이다.

1. "← 결정기록" 링크, 머리: 기록 제목(h1), 커밋 페이지와 같은 메타 줄. 해시는 커밋 페이지로 가는 링크다. 그 아래 한 줄에 `<기록 ID> · <커밋 메시지>`
2. 기록의 섹션: 섹션마다 h2 제목(맥락·결정·검토한 대안을 화면 언어로)과 Markdown 본문. 46rem 읽기 폭이다
3. "이 기록이 설명하는 문서": 문서마다 접히는 행(배지와 제목)
4. "같은 커밋의 다른 기록": 같은 커밋의 다른 기록마다 제목(기록 상세 링크)과 "문서 N건". 다른 기록이 있을 때만 둔다
5. 같은 커밋의 소스 변경(`CommitSource`)

문서 행은 기록이 설명하는 문서가 3개 이하이면 모두 열린 채로, 그보다 많으면 닫힌 채로 시작한다. 주소의 프래그먼트가 가리키는 문서는 열린 채로 시작하고 그 행으로 스크롤한다. 닫힌 행은 아무것도 그리지 않는다. 열린 행은 문서 ID, 경로, "현재 기능 명세 보기 →" 또는 "현재 지침 보기 →", "이 문서의 이력 →"(`/records?q=<문서 ID>`), 그 아래 변경 비교를 보인다. 비교는 프론트매터 항목 다음에 본문 줄이고, 추가·삭제된 문서는 본문 하나다.

받는 동안 커밋 페이지와 같은 골격을 보인다. HEAD 이력에 그 기록이 없어 서버가 404로 답하는 경우를 포함해, 두 조회 중 하나가 실패하면 오류와 다시 시도를 보인다.

### 변경 비교

변경 전·후가 모두 있으면 `ChangeDiff`가 git diff처럼 보이고, 추가·제거처럼 한쪽만 있으면 렌더링한 본문 하나를 보인다. 비교 계산은 브라우저가 한다. 줄 비교 표는 위젯 `widgets/diff-view`의 `LineDiff`이며 문서와 소스 파일이 함께 쓴다.

| 대상 | 표시 |
| :--- | :--- |
| 프론트매터 값 | 바뀐 항목만 `이전 → 이후` |
| 프론트매터 목록(`requirements`·`sources`) | 빠진 항목과 더한 항목만. ID로 가리킨 문서는 지금의 제목으로 |
| 본문 줄 | 원문 줄 단위 비교(`shared/lib/diff`, 최장 공통 부분열). 지운 줄 빨강, 더한 줄 초록 바탕, 옛·새 줄 번호 |
| 바뀐 줄의 단어 | n번째 지운 줄과 n번째 더한 줄을 짝지어 다른 단어를 진한 바탕으로. 남는 글자가 4분의 1 미만인 짝은 통째로 바뀐 줄로 둔다 |
| 표시 없는 줄 | Astryx `tokenize`로 구문 색. 확장자로 언어를 정하고 모르는 확장자는 색 없음 |
| 먼 무변경 구간 | 변경에서 3줄보다 먼 구간을 "바뀌지 않은 N줄 펼치기"로 접음 |

구문 색은 양쪽 원문을 통째로 토큰화해 여러 줄에 걸친 문자열·주석도 한 덩어리로 칠한다. 색은 테마의 `--color-syntax-*`라 화면 모드와 색 조합을 따른다.

줄 번호와 부호(`−`·`+`)는 각자 칸을 가져 본문의 시작선이 모든 줄에서 같다. 줄 번호는 오른쪽 정렬·고정폭 숫자이고 본문과 실선 하나로 나뉜다. 긴 줄이 접히면 이어지는 줄을 1.5칸 들여 쓴다(`text-indent`와 같은 크기의 왼쪽 여백). 셀 여백은 `.diff td` 초기화보다 구체적인 선택자(`.diff .code`)로 준다. 같은 구체성이면 초기화가 이긴다.

보기는 화면 폭이 정하고 고르는 장치는 없다. 1024px 이상은 좌우 보기, 그 아래는 통합 보기다.

## 기능별 요구사항

### 목록

`/features`는 1024px 중앙 컬럼의 Astryx Table이다. 기능 행 아래에 그 기능의 요구사항 행이 낮게 이어진다(`data-row`로 구분).

| 행 | 내용 |
| :--- | :--- |
| 기능 | 제목 위, 한 줄 설명(길면 자름) 아래의 두 줄. 설계가 없으면 제목 옆 Token, 있으면 셀 끝에 설계 탭으로 가는 "설계 N →". 요구사항 수와 가장 많은 기능 대비 ProgressBar, AvatarGroup 참여자(3명 넘으면 +N), 상대 시각 |
| 요구사항 | 번호, 제목, 한 줄 설명(길면 자름). 요구사항 수 열에 "수용 조건 N". 그 기능에 설계가 있는데 이 요구사항을 다루는 설계가 없을 때만 셀 끝에 "설계 없음" |
| 나머지 | 기능당 요구사항 12개를 넘으면 "요구사항 N개 더"로 상세에 이음 |

행은 `model/feature-rows.ts`가 위 세 종류로 만든다. 페이지는 40행을 넘기 전까지 기능을 담고 한 기능을 쪼개지 않는다. 페이지는 숫자 검색 인자 `page`(`?page=2`)다.

기능 행은 두 줄을 담는 대신 위아래 여백을 줄여(12px) 한 줄일 때의 높이를 넘지 않는다. 수용 조건 수는 브라우저가 본문의 `### 수용 조건`·`### Acceptance criteria` 절 아래 번호 항목을 세어 만든다(`model/acceptance.ts`). 기능 행에는 빗금(`repeating-linear-gradient`)을 깐다. 묶음의 머리에 자기 바탕이 생기고, 배경 이미지라 hover 바탕이 아래로 비친다. 묶음 사이는 마지막 요구사항 행의 아래 여백으로 벌린다(`:has(+ tr[data-row=feature])`). 빗금이 다시 시작하는 자리가 다음 묶음이다.

페이지 매김은 카드 바닥에 붙는 푸터에 둔다. 푸터가 있는 화면만 바깥 page와 안쪽 column·content·featureTable의 flex 축소를 막아 본문 길이만큼 높이가 늘게 한다. 높이가 화면 크기로 줄면 행이 부모 밖으로 넘치고 sticky 헤더가 화면 위로 밀려난다. 짧은 페이지에서는 푸터가 든 칸을 카드 높이까지 늘이고(`min-height:100%`, `flex:1`) `margin-block-start:auto`로 바닥에 붙인다.

필터 줄에는 검색, 설계 여부 Selector, 참여자 Selector가 있고 값은 `q`·`design`·`author` 검색 인자다. 좁혀지면 요구사항 수 옆에 전체 개수를 덧붙인다. 상세로 갈 때 `q`·`design`·`author`·`sort`·`dir`·`page`를 넘기고, 상세의 목록 링크는 `q`·`design`·`author`·`sort`를 되살린다.

정렬은 열 머리에서 한다. 견줄 값이 있는 기능 이름·요구사항 수·최근 변경만 `sortable`이다. `useTableSortable`은 머리의 표시와 조작만 맡고 실제 정렬은 화면이 기능에만 적용하며, 요구사항은 문서가 준 순서를 지킨다.

| 상태 | 값 |
| :--- | :--- |
| 검색 인자 | `sort`(열), `dir`(방향) |
| 기본 | 최근 변경 내림차순. 주소에 쓰지 않음 |
| 처음 누른 열 | 이름은 오름차순, 개수와 날짜는 내림차순 |

서버는 `.gitifact/spec`·`.gitifact/instructions`·AGENTS.md를 건드린 커밋을 Git 로그 한 번으로 읽어, 기능 폴더마다 `contributors`와 `updatedAt`을 응답에 담는다. 로그는 커밋 20,000개까지 읽고 기능마다 2000개까지 세며, 마이그레이션 커밋은 뺀다.

### 기능 상세

행이나 제목을 열면 같은 컬럼에 `/features/<S-ID>`를 그리고 페이지 제목과 필터 줄은 숨긴다. 없는 S-ID는 찾을 수 없음 상태와 목록 링크를 보인다. 탭은 요구사항·설계이고 `tab`·`selected`는 검색 인자, 보러 온 절은 프래그먼트가 가리킨다.

| 탭 | 내용 |
| :--- | :--- |
| 요구사항 | 맨 위에 기능 소개(`index.md` 본문) 한 번, 이어서 요구사항마다 제목·본문·수용 조건 |
| 설계 | 설계 파일을 `order` 순으로 모두 잇고 파일마다 제목·설명·본문. 설계가 없으면 미작성 안내 |

두 탭의 절은 같은 모양이다. 제목 위에 `요구사항 01 · R-…`·`설계 01 · D-…`처럼 번호와 ID를 두고, 제목에는 형광펜 표시(`<mark>`)를 긋는다. 본문 아래에는 관련 문서를 종류별 목록으로 둔다. 설계는 다루는 요구사항, 참고 문서, 변경 이력 링크다.

링크로 들어온 절에는 기능 목록의 기능 행과 같은 빗금 바탕을 깐다. `?tab=design&selected=<D-ID>#<D-ID>`는 그 설계에서 시작하고, 설계 탭의 `selected`가 요구사항 ID이면 그 요구사항을 다루는 첫 설계에서 시작한다. 붙여 넣은 주소의 프래그먼트는 절이 그려지기 전에 읽히므로, 대상이 바뀔 때 화면이 그 절을 직접 올린다. `?feature=` 진입은 리다이렉트하지 않는다.

목차는 1200px 이상에서 탭 바로 아래부터 본문 오른쪽 14rem 열에 두고 스크롤을 따라온다. IntersectionObserver로 읽는 구간(상단 바 아래부터 화면 위쪽 45%)에 든 절 중 마지막을 표시한다. 그보다 좁으면 목차가 본문 위에 오고 표시는 하지 않는다.

요구사항 본문의 상대 링크는 그 요구사항 파일(`requirements/<slug>.md`)을 기준으로 해석한다. 설계 프론트매터의 `requirements`는 현재 전체 기능에서 찾아 해당 요구사항으로 잇고, 과거 설계의 링크도 현재 요구사항으로 잇는다. 지워진 참조는 현재 명세에 없다고 표시한다. Markdown은 실행 지시가 아닌 데이터로 렌더링한다.

## 제품 개요

`/product`는 체크아웃과 이력 요약(`/api/v1/history/summary`)으로 그린다. 페이지 제목과 요약 타일 없이, 머리 아래 차트와 최신 결정기록이 본문이다.

| 부분 | 내용 |
| :--- | :--- |
| 머리 | 프로젝트 이름(Git 상태 응답의 체크아웃 폴더 이름), 한 줄 규모(기능·요구사항·프로젝트 지침·참여자), 미커밋 Token, 최근 변경 시각 |
| 머리 오른쪽 | 최근 21일 일자별 변경 막대(인라인 SVG). 범례 대신 "최근 21일 변경 · 전체 활동 N건" |
| 차트 카드 두 장 | 전체 이력의 변경 종류 비율, 참여자별 커밋. 높이를 맞춤(Grid `align="stretch"`) |
| 최신 활동 | 결정기록 화면의 타임라인 컴포넌트. 커밋 셋, 커밋마다 문서 변경 10개 뒤 "문서 N건 더 →"로 커밋 페이지에 이음 |

최신 활동의 문서 수는 가려진 것을 포함한 커밋 전체 수다. 문서 10개를 보이고 "문서 15건 더"라면 그 커밋은 25건이다. 문서 수백 개를 바꾼 커밋도 화면을 덮지 않는다. 결정기록 화면으로 가는 링크는 이 절의 제목 옆 하나다.

이력 요약은 체크아웃과 따로 조회하므로 화면이 그려진 뒤에 올 수 있다. 답이 오기 전에는 건수와 빈 상태 대신 타임라인 골격과 막대 자리를 둔다. "전체 활동 0건"이나 "커밋된 명세 활동이 아직 없습니다"는 사실과 반대이기 때문이다.

기능 전체 표는 기능별 요구사항 화면이 그리고 개요에는 두지 않는다.

## Git 상태

같은 중앙 컬럼과 헤더의 새로고침 버튼을 쓰고, 헤더에 마지막 관측 시각을 "조회"로 표시한다. 미커밋 명세 변경이 있으면 본문 맨 위에 경고 Banner를 둔다.

| 부분 | 내용 |
| :--- | :--- |
| 저장소 | 브랜치·HEAD·저장소를 MetadataList로 |
| 집계 | Staged·Unstaged·Untracked·충돌을 한 줄로 |
| 변경 경로 | Table. 상태 열은 porcelain 두 글자 코드를 Staged·Unstaged·Untracked·충돌 Token으로 풀고 원래 코드는 옆 열에 |
| 변경 없음 | 빈 상태 일러스트 |
| 하단 상태 줄 | 관측 한계와 gitifact 검사 미실행 안내 |

## 설정과 색 조합

`/settings`에서 화면 모드(시스템·라이트·다크)와 색 조합을 고른다. shared/lib/appearance가 선택을 localStorage(`gitifact-appearance`)에 저장하고 useSyncExternalStore로 구독하며, 다른 탭의 변경은 storage 이벤트로 따른다. 서버나 프로젝트에는 아무것도 보내지 않는다. AppProviders가 Astryx Theme의 theme와 mode에 반영한다.

저장값이 깨져 있으면 기본값(시스템·스톤)을 쓰고, 저장소를 쓸 수 없으면 그 페이지 동안만 유지한다. 설정 카드의 미리보기는 라이트·다크 각각의 바탕·표면·강조 점·글자 선을 축소판으로 그린다.

모든 조합은 stone 소스를 extends해 글꼴·모서리·아이콘·컴포넌트 재정의를 물려받는다. 스톤은 라이트 글자 토큰 두 개만 바꾼다. 첫 화면은 전역 CSS가 가져오는 stone theme.css로 그리고, 바뀐 글자 토큰은 런타임에 주입한다. 나머지 조합(세이지 & 크림, 올리브 & 웜그레이, 슬레이트 & 블루, 샌드 & 클레이)은 색 토큰 16개를 라이트·다크 쌍으로 명시한다. 값은 Gentask의 팔레트와 hoho-hr의 Halo · Olive 토큰(OKLCH를 hex로 변환)에서 왔다.

| 조합 | 라이트 모드 글자색 |
| :--- | :--- |
| 스톤 | `#3a3a40` |
| 세이지 | `#3b4439` |
| 올리브 | `#36372e` |
| 슬레이트 | `#36415a` |
| 클레이 | `#473b34` |

라이트 글자색은 거의 검정보다 한 단계 밝고, 글자색으로 그리는 워드마크도 함께 밝아진다. 다크 모드는 테마 값 그대로다. 글자용 강조 토큰(`--color-text-accent`·`--color-icon-accent`)은 조합의 글자색을 따르고, 채도 높은 강조색은 선택 표시·진행 막대·버튼에만 나타난다.

## 화면 확대

루트 글자 크기는 1920px까지 100%이고, 그 위로는 뷰포트에 비례해 2560px에서 18px에 닿는다. Astryx의 spacing·size-element 토큰은 px로 배포되므로 같은 16px 기준값을 rem으로 다시 선언해 글자와 간격이 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 시작하기 안내

`/getting-started`의 `pages/getting-started`는 소개와 같은 64rem 중앙 컬럼에 PageHeader와 DocumentBody를 쓴다. 페이지 제목은 화면 문구 카탈로그에서 읽고, Markdown의 최상위 제목은 표시할 때 지워 중복하지 않는다. 소개의 GitHub CLI 안내 링크는 앱 안에서 이 경로로 연결한다.

원본은 `packages/intro/<lang>/getting-started.md`(한국어·영어)다. packages/intro의 공개 export를 shared/i18n이 가져와 localDocument로 제공하므로, 별도 HTTP 조회나 명세 저장소에 의존하지 않는다. 영어판과 npm README는 한국어 원문과 같은 내용이다.

| 내용 | 규칙 |
| :--- | :--- |
| 사용 흐름 | 현재 CLI 도움말·내장 지침으로 확인한 것 |
| 입력 JSON 형식 | 복제하지 않고 `guide show spec`·`commit`으로 안내 |
| 명령 예시 | npx로 통일. 처음 도입·업데이트는 @latest, 일상 예시는 `npx gitifact`. `--yes`와 버전 고정은 에이전트 블록이 관리 |
| 프로젝트 설치 | 별도 절. 에이전트용 지침의 gitifact 약칭은 유지 |
| 0.7 저장 규약 프로젝트 | 업데이트 절에서 한 번 옮겨야 한다는 것과 `guide show migrate` |

검사는 메뉴 순서, 소개 링크, 키보드 이동, 직접 진입·새로고침, 모바일 두 테마를 다룬다. 명세가 없는 임시 Git 저장소에서도 실제 CLI 서버가 안내를 제공하는지 확인한다.

## GitHub 저장소 바로가기

BrowserShell의 SideNav footer에서 버전 표시 옆에 GitHub 로고와 이름을 둔다. 기존 SvgIcon과 Hugeicons의 GithubIcon을 쓰고 외부 이미지를 가져오지 않는다. 링크는 현재 체크아웃의 원격이 아니라 고정된 제품 저장소 주소이며, `target="_blank"`와 `rel="noopener noreferrer"`로 새 탭에서 연다.

모바일 탐색에서도 같은 footer를 쓴다. 링크는 세션 조회 성공 여부와 무관하게 보이고, 새 탭 안내 툴팁은 현재 표시 언어를 따른다.
