`mod+K`와 머리의 검색 버튼이 같은 창을 연다. 열림 여부는 `shared/lib/search`의 작은 저장소가 들고, 팔레트는 셸이 한 번 그리며 버튼은 헤더가 그린다. 두 위젯이 서로를 참조하지 않게 상태만 shared에 둔다.

Astryx CommandPalette를 쓴다. 입력 전의 "최근 변경" 목록은 체크아웃의 최근 변경일로 브라우저가 만든다. 입력한 뒤에는 서버(`/api/v1/search`)에 묻는다. 서버는 검색 전에 작업 폴더 문서를 캐시와 맞추며 수정 시각·크기가 바뀐 기능·요구사항·설계·위키 파일의 검색 행만 바꾸고, 이력을 캐시에 읽어 넣을 때 변경마다 제목과 이유·메시지를 넣는다. CLI의 `docs search`도 같은 검색 행을 쓴다. 검색 행은 FTS5 trigram 표에 소문자로 두어 `LIKE '%…%'`가 세 글자부터 색인을 쓰고, 두 글자 이하와 `%`·`_`가 든 검색어는 훑어서 찾는다. 체크아웃은 제목 앞부분 → 제목 → 위치 → 본문 순으로 24개, 지난 변경은 HEAD의 계보에서 최신순으로 8개다. 결과 한 줄은 제목·위치·맞은 대목(서버가 자른다)이고 맞은 글자를 표시한다. 고르면 위키는 `/wiki/$documentId`, 요구사항과 설계는 기능 상세의 해당 탭, 변경은 `/activity?selected=<키>`로 보낸다. 새 검색이 나가면 이전 요청은 취소한다. Astryx 팔레트는 결과가 오기 전에 이미 보이는 목록을 제목으로 먼저 좁히고, 남는 게 없으면 빈 상태를 보인다. 입력 전 목록에서 첫 낱말을 치면 거의 늘 남는 게 없어, 결과가 올 때까지(약 0.5~0.7초) "검색할 문서가 없습니다" 그림이 번쩍였다. 입력칸의 change 이벤트로 "기다리는 중"을 세우고, 그동안의 빈 상태 자리에 결과 줄과 같은 모양의 골격을 둔다. 검색은 팔레트가 transition 안에서 부르므로 거기서 세운 상태는 결과가 온 뒤에야 보였다. 좁힌 부분 목록 자체는 팔레트의 동작이고 틀린 내용이 아니어서 그대로 둔다. 체크아웃을 브라우저에 두고 찾던 방식은 지난 변경까지 찾으려면 이력 전체를 내려받아야 해 서버 검색으로 옮겼다.

팔레트를 다루며 고친 것들이다. searchSource를 매 렌더 새로 만들면 선택 강조가 풀려 Enter가 아무것도 열지 못했으므로 한 번만 만든다. 강조가 없을 때 Enter가 죽어 있어, 입력의 keydown에서 강조가 없으면 첫 결과를 연다. 팔레트는 열릴 때와 타자마다만 검색하고 다시는 하지 않으므로, 문서를 읽기 전에 입력한 낱말이 빈 결과로 굳지 않도록 검색이 자료 도착을 기다렸다가 답한다. 디바운스로 밀린 약속은 버리지 않고 마지막 결과로 함께 끝낸다. 버리면 그 transition이 끝나지 않아 대기 표시가 계속 돌았다. 여는 목록과 검색은 큐를 나눈다. 같이 쓰면 타자가 여는 목록의 약속을 대신 답해 두 목록이 한꺼번에 보였다.

결과 영역은 22rem 고정이다. 결과 수에 맞추면 타자마다 창이 커졌다 작아졌다 했다. 읽는 중에는 결과 줄과 같은 규격의 골격을, 맞는 문서가 없으면 PageState의 검색 일러스트를 같은 자리에 둔다. 과거 시점의 본문 전문은 찾지 않는다. 필요해지면 changes 표의 전후 본문을 검색 행에 더하면 된다.
