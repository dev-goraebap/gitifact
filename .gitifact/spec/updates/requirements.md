# 버전 확인과 패치노트

## 에이전트의 세션 시작 버전 확인
<!-- gitifact-req: R-cj525dk5vt -->

에이전트와 Gitifact를 쓰는 사용자로서, 브라우저를 열지 않아도 새 버전을 안내받고 업데이트 여부를 직접 결정하고 싶다.

### 수용 조건

1. 조건: 에이전트가 새 세션에서 프로젝트 지침을 읽습니다.
   기대 동작: 지침에 지정된 CLI 버전으로 읽기 전용 업데이트 확인을 한 번 수행하도록 안내합니다. 확인 과정은 프로젝트 파일·index·커밋을 바꾸지 않습니다.
2. 조건: 지정 버전보다 새 정식 버전이 있습니다.
   기대 동작: 에이전트는 현재·새 버전을 알리고 업데이트 여부를 묻습니다. 동의한 경우에만 새 버전으로 지침을 갱신하고 다시 읽어 이후 작업에 사용합니다. 업데이트 동의만으로 커밋·푸시하지 않습니다.
3. 조건: 사용자가 업데이트를 거절하거나 조회가 실패·비활성화됩니다.
   기대 동작: 지정 버전으로 작업을 이어가며 같은 세션에서 다시 묻지 않습니다. 확인 실패를 최신 상태로 해석하지 않습니다.
4. 조건: 팀원이 갱신된 지침을 pull한 뒤 새 세션을 시작합니다.
   기대 동작: 에이전트는 갱신된 지침에 적힌 버전으로 실행합니다. npx 방식은 별도 전역 설치 없이 해당 버전을 사용합니다.
5. 조건: 사용자가 브라우저를 실행합니다.
   기대 동작: 브라우저와 서버는 새 버전을 조회하지 않으며 업데이트 알림·대화상자를 제공하지 않습니다. 현재 버전과 패치노트는 계속 볼 수 있습니다.

### 범위와 제약

세션 시작과 사용자 동의 절차는 생성되는 에이전트 지침으로 전달하며 CLI가 에이전트의 행동을 강제하지 않는다. 레지스트리 요청에 프로젝트 정보를 보내지 않고 GITIFACT_NO_UPDATE_CHECK로 확인을 끌 수 있다.

## 브라우저의 현재 버전 표시
<!-- gitifact-req: R-hlndpxflx7 -->

Gitifact 브라우저를 쓰는 사용자로서, 지금 어떤 버전으로 보고 있는지 알기 위해 화면에서 실행 중인 CLI 버전을 확인하고 싶다.

### 수용 조건

1. 조건: 브라우저가 세션 정보를 받았습니다.
   기대 동작: 사이드 메뉴 하단에 실행 중인 CLI 버전을 작은 글자로 표시하고, 누르면 패치노트로 이동합니다. 세션 정보를 받기 전에는 임의의 버전을 표시하지 않습니다.

## 명령줄의 업데이트 확인
<!-- gitifact-req: R-cr5rajcs4a -->

터미널이나 에이전트로 Gitifact를 쓰는 사용자로서, 브라우저를 열지 않고도 최신 상태를 유지하기 위해 한 명령으로 새 버전 여부와 설치 방법을 확인하고 프로젝트의 지침 블록을 현재 버전에 맞추고 싶다. 업데이트할 때마다 블록 변경을 따로 커밋하지 않도록, 요청하면 블록 갱신이 정해진 메시지로 커밋되기를 원한다.

### 범위와 제약

명령은 설치를 직접 실행하지 않는다. 지침 블록은 이미 GITIFACT 블록이 있는 파일에서만 갱신하며 새 파일을 만들지 않는다. init이 만들 지침 파일이 빠져 있으면 만들지 않고 init 재실행을 안내한다. init·update·읽기 전용 확인은 같은 레지스트리 조회와 버전 비교 코드를 쓴다. 커밋은 사용자가 커밋 옵션을 지정했을 때만 하며, 옵션 없는 실행은 커밋하지 않는다. 커밋에는 블록 안만 바뀐 지침 파일만 담고 메시지는 버전만 달라지는 고정 문장이다. 기존 staging과 다른 변경은 보존하고 훅·서명을 유지하며 푸시하지 않는다.

### 수용 조건

1. 조건: 사용자가 update --check를 실행합니다.
   기대 동작: 현재 버전, 조회 상태와 최신 버전을 출력하고, 새 버전이 있으면 전역 설치 없이 새 버전을 실행하고 지침을 갱신하는 npx 명령을 함께 안내합니다. 파일이나 지침을 갱신하지 않으며 Git 저장소 밖에서도 동작합니다.
2. 조건: 사용자가 --check 없이 update를 실행하고 초기화된 프로젝트의 블록이 실행 중인 CLI 버전과 다릅니다.
   기대 동작: 마커 사이만 현재 버전의 블록으로 교체하고 갱신한 파일을 알립니다. 초기화되지 않은 위치에서는 버전 확인만 수행합니다.
3. 조건: 사용자가 커밋 옵션과 함께 명령을 실행했고, 지침 파일이 HEAD와 블록 안에서만 다릅니다.
   기대 동작: 그 지침 파일만 고정 메시지로 커밋하고 커밋과 파일을 알립니다. 다른 staging은 그대로 남습니다. 앞서 커밋 없이 갱신만 해 둔 블록도 같은 방식으로 커밋합니다.
4. 조건: 커밋 옵션을 지정했지만 블록 밖에도 커밋되지 않은 수정이 있거나, Git이 추적하지 않는 파일이거나, Git이 커밋을 거부합니다.
   기대 동작: 아무것도 커밋하지 않고 갱신한 블록은 그대로 두며, 커밋하지 않은 이유와 파일을 알립니다.
5. 조건: 초기화된 프로젝트의 블록이 AGENTS.md에만 있고 CLAUDE.md와 .claude/CLAUDE.md가 없습니다.
   기대 동작: 파일을 만들지 않고 빠진 CLAUDE.md를 알리며, gitifact init을 다시 실행하면 만들어진다고 안내합니다.
6. 조건: --check와 --commit을 함께 지정합니다.
   기대 동작: 잘못된 옵션 조합으로 거부하고 파일과 커밋을 바꾸지 않습니다.

## 버전별 패치노트
<!-- gitifact-req: R-yrk7zcukqy -->

Gitifact를 업데이트한 사용자로서, 무엇이 달라졌는지 파악하기 위해 버전마다 추가·변경·제거·수정된 내용을 시간순으로 보고 싶다.

### 범위와 제약

패치노트의 원본은 CLI에 함께 배포되는 언어별 Markdown 하나이며 브라우저는 서버 API로 받는다. 설치된 버전까지의 기록만 보여 준다.

### 수용 조건

1. 조건: 사용자가 패치노트 페이지를 엽니다.
   기대 동작: 최신 버전부터 버전·날짜와 추가·변경·제거·수정 항목을 타임라인으로 보여 줍니다.
2. 조건: 요청한 언어의 패치노트가 없습니다.
   기대 동작: 기본 언어의 패치노트를 보여 주고 다른 언어로 대체됐음을 알립니다.
