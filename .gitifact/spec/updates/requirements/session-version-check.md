에이전트와 Gitifact를 쓰는 사용자로서, 세션 도중에 나온 새 버전이나 팀원이 올린 프로젝트 기준 버전을 다음 명령에서 바로 알고, 업데이트할지는 직접 정하고 싶다.

### 범위와 제약

안내는 명령 결과보다 먼저 한 줄만 stderr로 내며 JSON 출력을 바꾸지 않는다. 명령은 프로젝트 설정과 사용자 캐시만 읽고 레지스트리 응답을 기다리지 않는다. 레지스트리 요청에 프로젝트 정보를 보내지 않고, GITIFACT_NO_UPDATE_CHECK로 새 버전 조회를 끌 수 있다. 사용자에게 묻는 절차는 에이전트 지침으로 전달하며 CLI가 에이전트의 행동을 강제하지 않는다. 실행 중인 CLI가 프로젝트 기준보다 낮아도 명령을 막지 않는다.

### 수용 조건

1. 조건: 사용자가 gitifact 명령을 실행하고, 마지막 새 버전 확인이 1시간보다 오래됐습니다.
   기대 동작: 명령은 레지스트리 응답을 기다리지 않고 끝납니다. 확인은 명령과 따로 진행되고, 그 결과는 다음 명령부터 안내에 쓰입니다. 여러 명령이 동시에 실행돼도 확인은 한 번만 합니다.
2. 조건: 실행 중인 CLI보다 새 정식 버전이 있습니다.
   기대 동작: 명령 결과 앞에 새 버전과 현재 버전, 전역 설치 뒤 update를 실행하는 방법, 나중에 미루는 명령을 한 줄로 알립니다. 에이전트는 다음 작업 전에 설치 명령을 그대로 보여 주며 지금 업데이트(권장)와 나중에 중 하나를 사용자에게 묻고, 동의하면 설치와 update를 직접 실행합니다. 업데이트 동의만으로 커밋·푸시하지 않습니다.
3. 조건: 사용자가 나중에를 고릅니다.
   기대 동작: 안내된 버전은 24시간 동안 다시 안내하지 않습니다. 그보다 새 버전이 나오면 바로 안내합니다.
4. 조건: 팀원이 프로젝트 기준 버전을 올린 커밋을 pull했고, 실행 중인 CLI가 그보다 낮습니다.
   기대 동작: 다음 명령에서 프로젝트 기준 버전과 실행 중인 버전, 그 버전의 전역 설치 명령을 알립니다. 이 안내는 새 버전 안내보다 앞서며, 명령은 그대로 실행됩니다.
5. 조건: 실행 중인 CLI가 프로젝트 기준 버전보다 새 버전이고 알릴 새 버전은 없습니다.
   기대 동작: update로 프로젝트 기준을 올릴 수 있다고 알립니다.
6. 조건: 조회가 실패하거나 GITIFACT_NO_UPDATE_CHECK로 꺼져 있습니다.
   기대 동작: 새 버전 안내 없이 명령을 실행하며, 확인 실패를 최신 상태로 해석하지 않습니다. 꺼져 있어도 프로젝트 기준 버전 비교는 계속합니다.
7. 조건: 에이전트가 새 세션을 시작했는데 gitifact 명령이 없습니다.
   기대 동작: 에이전트는 프로젝트 설정에 적힌 기준 버전의 전역 설치 명령을 보여 주며 허용을 묻고, 허용받으면 직접 설치합니다.
8. 조건: 사용자가 브라우저를 실행합니다.
   기대 동작: 브라우저와 서버는 새 버전을 조회하지 않으며 업데이트 알림·대화상자를 제공하지 않습니다. 현재 버전과 패치노트는 계속 볼 수 있습니다.
