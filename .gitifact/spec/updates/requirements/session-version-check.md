에이전트와 Gitifact를 쓰는 사용자로서, 세션 도중에 나온 새 버전이나 팀원이 올린 프로젝트 기준 버전을 다음 명령에서 바로 알고, 업데이트할지는 직접 정하고 싶다.

### 범위와 제약

- 안내는 명령 결과보다 먼저 stderr에 한 줄만 내고, JSON 출력을 바꾸지 않는다.
- 명령은 프로젝트 설정과 사용자 캐시만 읽고 레지스트리 응답을 기다리지 않는다.
- 레지스트리 요청에 프로젝트 정보를 보내지 않는다.
- 사용자에게 묻는 절차는 에이전트 지침으로 전하고, CLI가 에이전트의 행동을 강제하지 않는다.
- 실행 중인 CLI가 프로젝트 기준보다 낮아도 명령을 막지 않는다.

### 기본 흐름

1. 사용자나 에이전트가 `gitifact` 명령을 실행한다.
2. 시스템은 사용자 캐시에서 알려진 최신 버전을, 프로젝트 설정에서 기준 버전을 읽는다.
3. 실행 중인 CLI보다 새 정식 버전이 있으면, 시스템은 명령 결과 앞에 새 버전과 현재 버전, 전역 설치 뒤 `update`하는 방법, 나중에 미루는 명령을 한 줄로 알린다.
4. 시스템은 명령을 그대로 실행한다.
5. 에이전트는 다음 작업 전에 설치 명령을 그대로 보여 주며, 지금 업데이트(권장)와 나중에 중 하나를 사용자에게 묻는다.
6. 사용자가 지금을 고르면 에이전트가 설치와 `update`를 직접 실행한다. 이 동의만으로 커밋하거나 푸시하지 않는다.

### 대체 흐름

- **A1. 마지막 확인이 1시간보다 오래됨** (2단계에서)
  1. 시스템은 명령과 따로 레지스트리를 확인해 캐시를 갱신하고, 그 결과를 다음 명령부터 쓴다. 여러 명령이 동시에 실행돼도 확인은 한 번만 한다.
- **A2. 사용자가 나중에를 고름** (6단계에서)
  1. 에이전트가 `update --later`를 실행하고, 시스템은 그 버전을 24시간 동안 다시 안내하지 않는다. 그보다 새 버전이 나오면 바로 안내한다.
- **A3. 프로젝트 기준 버전이 더 높음** (3단계에서)
  1. 팀원이 올린 기준 버전을 pull해 실행 중인 CLI가 그보다 낮으면, 시스템은 기준 버전과 현재 버전, 그 버전의 전역 설치 명령을 새 버전 안내보다 먼저 알린다.
- **A4. 실행 중인 CLI가 기준 버전보다 높음** (3단계에서)
  1. 알릴 새 버전이 없으면, 시스템은 `update`로 프로젝트 기준을 올릴 수 있다고 알린다.
- **A5. 조회가 실패하거나 꺼져 있음** (A1에서)
  1. 조회가 실패하거나 `GITIFACT_NO_UPDATE_CHECK`로 꺼져 있으면, 시스템은 새 버전 안내 없이 명령을 실행하고 실패를 최신 상태로 보지 않는다. 기준 버전 비교는 계속한다.
- **A6. `gitifact` 명령이 없음** (1단계에서)
  1. 에이전트는 설정에 적힌 기준 버전의 전역 설치 명령을 보여 주며 허용을 묻고, 허용받으면 직접 설치한다.
- **A7. 브라우저를 실행함** (1단계 대신)
  1. 브라우저와 서버는 새 버전을 조회하지 않고 업데이트 알림을 두지 않는다. 현재 버전과 패치노트는 볼 수 있다.

### 수용 조건

1. 경로: 기본 흐름
   조건: 새 정식 버전이 있을 때 `--format json`으로 명령을 실행합니다.
   기대 동작: stderr에 안내가 한 줄 나오고, stdout의 JSON은 안내가 없을 때와 같습니다.
2. 경로: 기본 흐름
   조건: 새 버전 안내를 본 에이전트에게 사용자가 지금 업데이트를 고릅니다.
   기대 동작: 에이전트가 설치 명령을 보여 준 뒤 설치와 `update`를 실행하고, 커밋이나 푸시는 하지 않습니다.
3. 경로: 기본 흐름, A1
   조건: 마지막 새 버전 확인이 1시간보다 오래된 상태에서 명령 여러 개를 동시에 실행합니다.
   기대 동작: 명령은 레지스트리 응답을 기다리지 않고 끝나고, 확인은 한 번만 하며 그 결과는 다음 명령부터 쓰입니다.
4. 경로: 기본 흐름, A2
   조건: 사용자가 나중에를 고릅니다.
   기대 동작: 그 버전은 24시간 동안 다시 안내하지 않고, 더 새 버전이 나오면 바로 안내합니다.
5. 경로: 기본 흐름, A3
   조건: 팀원이 기준 버전을 올린 커밋을 pull했고 실행 중인 CLI가 그보다 낮습니다.
   기대 동작: 다음 명령에서 기준 버전과 설치 명령을 새 버전 안내보다 먼저 알리고, 명령은 그대로 실행합니다.
6. 경로: 기본 흐름, A4
   조건: 실행 중인 CLI가 기준 버전보다 새 버전이고 알릴 새 버전은 없습니다.
   기대 동작: `update`로 프로젝트 기준을 올릴 수 있다고 알립니다.
7. 경로: 기본 흐름, A1, A5
   조건: `GITIFACT_NO_UPDATE_CHECK`를 켜고 명령을 실행합니다.
   기대 동작: 새 버전 안내 없이 실행하고, 기준 버전 비교 안내는 계속 나옵니다.
8. 경로: A6
   조건: 새 세션에서 `gitifact` 명령이 없습니다.
   기대 동작: 에이전트가 기준 버전의 설치 명령을 보여 주며 허용을 묻고, 허용받으면 직접 설치합니다.
9. 경로: A7
   조건: 사용자가 브라우저를 실행합니다.
   기대 동작: 새 버전을 조회하지 않고 업데이트 알림이나 대화상자가 없으며, 현재 버전과 패치노트는 볼 수 있습니다.
