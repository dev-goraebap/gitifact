터미널이나 에이전트로 Gitifact를 쓰는 사용자로서, 브라우저를 열지 않고도 최신 상태를 유지하기 위해 한 명령으로 새 버전 여부와 설치 방법을 확인하고 프로젝트의 지침 블록과 기준 버전을 현재 버전에 맞추고 싶다. 업데이트할 때마다 그 변경을 따로 커밋하지 않도록, 요청하면 정해진 메시지로 커밋되기를 원한다.

### 범위와 제약

명령은 설치를 직접 실행하지 않고, 설치 방법은 전역 설치로 안내한다. 프로젝트 기준 버전과 블록 언어는 프로젝트 설정 파일에 두며, update는 기준 버전을 실행 중인 버전으로 올리되 낮추지 않는다. 지침 블록은 이미 GITIFACT 블록이 있는 파일에서만 갱신하며 새 파일을 만들지 않는다. init이 만들 지침 파일이 빠져 있으면 만들지 않고 init 재실행을 안내한다. init·update·읽기 전용 확인과 명령마다의 안내는 같은 레지스트리 조회와 버전 비교 코드를 쓴다. 커밋은 사용자가 커밋 옵션을 지정했을 때만 하며, 블록 안만 바뀐 지침 파일과 기준 버전·블록 언어만 바뀐 설정 파일만 담고 메시지는 버전만 달라지는 고정 문장이다. 기존 staging과 다른 변경은 보존하고 훅·서명을 유지하며 푸시하지 않는다.

### 수용 조건

1. 조건: 사용자가 update --check를 실행합니다.
   기대 동작: 현재 버전, 조회 상태와 최신 버전을 출력하고, 새 버전이 있으면 전역 설치 명령과 이어서 update를 실행하라는 안내를 함께 보입니다. 파일이나 지침을 갱신하지 않으며 Git 저장소 밖에서도 동작합니다.
2. 조건: 사용자가 --check 없이 update를 실행하고, 초기화된 프로젝트의 블록 문구나 기준 버전이 실행 중인 CLI와 다릅니다.
   기대 동작: 마커 사이만 현재 버전의 블록으로 교체하고 설정의 기준 버전을 실행 중인 버전으로 올린 뒤 갱신한 파일을 알립니다. 설정에 이 CLI가 모르는 항목이 있으면 그대로 둡니다. 초기화되지 않은 위치에서는 버전 확인만 수행합니다.
3. 조건: 프로젝트 기준 버전이 실행 중인 CLI보다 새 버전입니다.
   기대 동작: 블록과 설정을 바꾸지 않고, 프로젝트 기준 버전과 그 버전의 설치 명령을 알립니다.
4. 조건: 사용자가 커밋 옵션과 함께 명령을 실행했고, 지침 파일은 HEAD와 블록 안에서만, 설정 파일은 기준 버전과 블록 언어만 다릅니다.
   기대 동작: 그 파일들만 고정 메시지로 커밋하고 커밋과 파일을 알립니다. 다른 staging은 그대로 남습니다. 앞서 커밋 없이 갱신만 해 둔 파일도 같은 방식으로 커밋합니다.
5. 조건: 커밋 옵션을 지정했지만 블록 밖이나 설정의 다른 항목에도 커밋되지 않은 수정이 있거나, Git이 추적하지 않는 파일이거나, Git이 커밋을 거부합니다.
   기대 동작: 아무것도 커밋하지 않고 갱신한 파일은 그대로 두며, 커밋하지 않은 이유와 파일을 알립니다.
6. 조건: 초기화된 프로젝트의 블록이 AGENTS.md에만 있고 CLAUDE.md와 .claude/CLAUDE.md가 없습니다.
   기대 동작: 파일을 만들지 않고 빠진 CLAUDE.md를 알리며, gitifact init을 다시 실행하면 만들어진다고 안내합니다.
7. 조건: 사용자가 update --later를 실행합니다.
   기대 동작: 지금 안내되는 새 버전을 24시간 동안 안내하지 않고 언제까지인지 알립니다. 알려진 새 버전이 없으면 미룰 것이 없다고 알립니다. 프로젝트 파일은 바꾸지 않습니다.
8. 조건: --check·--commit·--later 중 둘 이상을 함께 지정합니다.
   기대 동작: 잘못된 옵션 조합으로 거부하고 파일과 커밋을 바꾸지 않습니다.
9. 조건: 문서가 아직 이전 저장 규약인 프로젝트에서 새 버전의 update를 실행합니다.
   기대 동작: 블록은 새 버전으로 갱신하고, 문서를 새 구조로 전환해야 한다는 것과 전환 절차를 읽는 명령을 함께 알립니다. 전환 전에는 문서 명령이 동작하지 않는다는 것도 알립니다.
