## 개요

모든 명령이 결과 앞에 새 버전과 프로젝트 기준 버전을 한 줄로 알린다. 새 버전은 사용자 캐시에서 읽고 레지스트리 조회는 명령과 따로 뒤에서 하므로, 명령은 네트워크를 기다리지 않는다. 프로젝트 기준 버전과 블록 언어는 `.gitifact/config.json`의 `cli`·`language`에 두고 `init`·`update`가 쓴다. 사용자에게 묻는 절차는 에이전트가 지침을 보고 따른다. 브라우저는 현재 버전과 패치노트만 보인다. 설치와 커밋은 자동으로 실행하지 않는다.

| 파일 | 다루는 것 |
| :--- | :--- |
| interface | 레지스트리 조회와 확인 결과, 계약, 명령마다의 안내와 사용자 캐시, `update` 명령과 커밋, 브라우저와 패치노트 |

## 오류 처리

> [!IMPORTANT]
> 레지스트리 확인의 실패는 명령을 실패시키지 않고 `unavailable`로만 남는다. `unavailable`은 최신이라는 뜻이 아니다.

오프라인·시간 초과·중단·잘못된 응답은 모두 `unavailable`이며 `update`와 `update --check`는 그대로 성공한다. 명령 앞의 안내는 설정·캐시를 읽거나 쓰지 못해도, 뒤의 확인을 띄우지 못해도 아무것도 알리지 않고 명령을 이어 간다. 마커가 깨진 지침 파일이 있으면 `update`는 `AGENT_DOCS_MALFORMED`로 거부하고 아무것도 쓰지 않는다. `update --check`는 지침 파일을 읽지 않으므로 깨진 블록이 있어도 버전 확인을 계속한다.

## 검증

테스트는 네트워크를 쓰지 않는다. 조회 함수와 패치노트·블록 읽기를 주입해 확인한다.

| 대상 | 확인하는 것 |
| :--- | :--- |
| 확인 결과 | 새 버전·최신·오류·형식 오류·시간 초과·비활성화 |
| 안내와 캐시 | 안내 우선순위, 1시간·조회 중 판정, `--later` 24시간과 더 새 버전의 재안내, 비활성화 때 프로젝트 비교 유지, 깨진 설정·캐시, 빌드한 CLI의 stderr 안내와 JSON 불변, 분리 실행된 확인이 캐시를 쓰고 끝남 |
| `update --check` | 임시 프로젝트의 오래된 블록·깨진 블록·staging·HEAD가 실행 전후 같음, 저장소 밖 실행, `--commit`과의 충돌 |
| `update` | 블록과 `cli`·`language` 갱신, 더 새 기준 버전의 보존, 설정의 모르는 필드 보존, 커밋·거부·사용자 변경 보존 |
| 브라우저 | 레지스트리 요청·반복 조회·업데이트 UI가 없고 버전 링크·패치노트가 남음 |
| 패키지 검사(`scripts/test-package.mjs`) | 설치본의 init이 `cli`를 쓰고, `--check`가 파일을 보존하고, `update`가 블록과 `cli`를 되살림, 세션이 v3, 패치노트 첫 항목이 패키지 버전 |

## 미결 사항

`update --apply`(자기 교체 설치)는 제공하지 않는다. 뒤의 확인이 Windows에서 창을 띄우지 않는지는 `windowsHide`에 기대며 자동 검사로 확인하지 않는다.
