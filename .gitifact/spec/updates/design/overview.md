## 개요

에이전트가 새 세션에서 지정 버전으로 새 릴리스를 확인하고, 사용자가 동의하면 새 버전으로 지침 블록을 갱신한다. 세션당 한 번이라는 규칙과 사용자에게 묻는 절차는 에이전트가 지침을 보고 따르며, CLI는 확인이 읽기 전용이라는 것만 보장한다. 브라우저는 현재 버전과 패치노트만 보인다. 설치와 커밋은 자동으로 실행하지 않는다.

| 파일 | 다루는 것 |
| :--- | :--- |
| interface | 레지스트리 조회와 확인 결과, 계약, 세션 시작 흐름, `update` 명령과 블록 커밋, 브라우저와 패치노트 |

## 오류 처리

> [!IMPORTANT]
> 레지스트리 확인의 실패는 명령을 실패시키지 않고 `unavailable`로만 남는다. `unavailable`은 최신이라는 뜻이 아니다.

오프라인·시간 초과·중단·잘못된 응답은 모두 `unavailable`이며 `update`와 `update --check`는 그대로 성공한다. 마커가 깨진 지침 파일이 있으면 `update`는 `AGENT_DOCS_MALFORMED`로 거부하고 아무것도 쓰지 않는다. `update --check`는 지침 파일을 읽지 않으므로 깨진 블록이 있어도 버전 확인을 계속한다.

## 검증

테스트는 네트워크를 쓰지 않는다. 조회 함수와 패치노트·블록 읽기를 주입해 확인한다.

| 대상 | 확인하는 것 |
| :--- | :--- |
| 확인 결과 | 새 버전·최신·오류·형식 오류·시간 초과·비활성화 |
| `update --check` | 임시 프로젝트의 오래된 블록·깨진 블록·staging·HEAD가 실행 전후 같음, 저장소 밖 실행, `--commit`과의 충돌 |
| `update` | 블록 갱신·커밋·거부·사용자 변경 보존 |
| 브라우저 | 레지스트리 요청·반복 조회·업데이트 UI가 없고 버전 링크·패치노트가 남음 |
| 패키지 검사(`scripts/test-package.mjs`) | 설치본의 `--check`가 파일을 보존하고 `update`가 블록을 되살림, 세션이 v3, 패치노트 첫 항목이 패키지 버전 |

## 결정

| 결정 | 이유 | 기각한 안 |
| :--- | :--- | :--- |
| 새 버전 안내는 에이전트의 세션 시작 확인으로 모은다 | 묻는 절차는 에이전트가 따르고 CLI는 조회가 읽기 전용임만 보장하면 된다 | 브라우저 알림과 서버의 조회(반복 조회·업데이트 대화상자) |
| 설치를 자동으로 하지 않고 새 버전의 실행 명령만 알린다 | 사용자 동의 전에는 버전을 바꾸지 않고 프로젝트가 지정한 실행 방식을 유지한다. 설치 방식은 CLI가 소유하지 않고, 자기 교체는 실행 중 자기 파일을 바꿔야 한다 | 자기 교체 설치(`update --apply`), 브라우저 요청으로 명령을 실행하는 경로 |
| 블록 커밋은 `--commit`을 준 실행에서만 한다. 에이전트 지침은 커밋까지 요청받았을 때만 이 옵션을 쓰게 한다 | 자동 기록은 자동 커밋 권한이 아니라는 제품 원칙을 지킨다 | 기본 커밋과 `--no-commit`(원칙에 예외가 생기고 사람이 직접 실행해도 커밋이 생김), 에이전트 지침만 추가(메시지와 범위가 에이전트마다 달라지고 테스트로 보장할 수 없음) |
| 파일 전체가 블록 안에서만 다를 때만 커밋한다 | 사용자의 작업 중 수정과 섞이지 않는다 | 블록 구간만 골라 부분 staging |
| 빠진 CLAUDE.md는 `update`가 만들지 않고 알린 뒤 `init` 재실행을 안내한다 | `update`가 만들면 새 파일을 블록 커밋에 넣을지 따로 정해야 하고 유지 명령이 도입 동작을 겸한다 | `update`가 만들기, 안내 없이 `init` 재실행에 맡기기(이미 도입한 프로젝트가 모르고 지나침) |
| 0.7 저장 규약 프로젝트에서도 블록은 갱신하고 `migrationRequired`로 전환을 안내한다 | 거부하면 업데이트에 동의해도 끝나지 않고, 옛 블록으로 돌아가 전환 순서를 따로 찾아야 한다 | 블록을 바꾸지 않고 거부, 안내 없이 갱신(다음 `docs` 명령이 거부될 때에야 전환이 필요함을 앎) |
| 조회 결과를 디스크에 저장하지 않는다 | 에이전트가 세션 시작에 한 번만 확인한다 | 하루 한 번으로 제한하는 캐시(프로젝트 밖에 파일을 쓰는 첫 사례가 되므로 필요해지면 따로 정함) |
| `update --check`는 별도 `update-check` 계약으로 답한다 | 블록 갱신·커밋 결과가 없어 `update` 응답과 혼동하지 않는다 | `update` 계약 재사용 |

## 미결 사항

`update --apply`(자기 교체 설치)와 조회 결과 캐시는 제공하지 않는다.
