CLI 사용자로서, 명령과 오류를 이해하기 위해 실행 환경이나 명시한 언어로 안내를 받고 싶다.

### 범위와 제약

- 표시 언어는 한국어와 영어다.
- 언어가 바뀌어도 명령어·옵션·JSON 키·오류 코드·ID는 그대로다.

### 기본 흐름

1. 사용자나 에이전트가 CLI 명령을 실행한다.
2. 시스템은 `--lang ko|en`을 우선하고, 없으면 `GITIFACT_LANG`·`LC_ALL`·`LC_MESSAGES`·`LANG`·운영체제 언어 순으로 표시 언어를 정한다.
3. 시스템은 도움말·텍스트 출력·오류·내장 지침(`guide show`)을 그 언어로 보인다.

### 대체 흐름

- **A1. 한국어 지역 표기** (2단계에서)
  1. `ko_KR.UTF-8` 같은 한국어 지역 표기를 한국어로 읽는다.
- **A2. 지원하지 않는 언어** (2단계에서)
  1. 시스템은 영어로 보인다.
- **A3. 브라우저 서버가 요청을 받음** (1단계 대신)
  1. 서버는 요청마다 그 요청의 표시 언어로 오류를 돌려주고, 다른 요청이나 CLI의 언어에 영향을 주지 않는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: `LANG`이 한국어인 환경에서 `--lang en`으로 실행합니다.
   기대 동작: 영어로 안내합니다.
2. 경로: 기본 흐름, A1
   조건: `LANG=ko_KR.UTF-8`로 실행합니다.
   기대 동작: 한국어로 안내합니다.
3. 경로: 기본 흐름, A2
   조건: 한국어·영어가 아닌 언어 환경에서 실행합니다.
   기대 동작: 영어로 안내합니다.
4. 경로: 기본 흐름
   조건: 한국어로 `--format json` 출력을 받습니다.
   기대 동작: JSON 키와 오류 코드, ID는 언어와 관계없이 같습니다.
5. 경로: A3
   조건: 서로 다른 언어의 브라우저가 같은 서버에 요청합니다.
   기대 동작: 각 요청이 자기 언어로 오류를 받고, 서로 영향을 주지 않습니다.
