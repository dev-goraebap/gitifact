기존 Gitifact 사용자로서, 표시 언어를 바꾸거나 CLI를 업데이트해도 프로젝트 기록과 지침을 계속 사용하고 싶다.

### 범위와 제약

- 표시 언어를 바꿔도 사용자가 쓴 문서를 번역하지 않는다.
- 지침 블록의 언어는 프로젝트 설정의 `language`를 따른다.

### 기본 흐름

1. 기존 사용자가 CLI를 올리거나 표시 언어를 바꾼다.
2. 사용자가 같은 저장 규약(schemaVersion 3)의 프로젝트에서 조회·초기화·업데이트를 실행한다.
3. 시스템은 도입 기준선·ID·요구사항·설계·지침·결정기록을 그대로 읽고 쓴다.
4. 시스템은 지침 블록을 갱신할 때 설정의 블록 언어를 따르고, 마커 밖 내용은 보존한다.

### 대체 흐름

- **A1. 저장 규약이 바뀐 버전** (2단계에서)
  1. 시스템은 문서를 건드리지 않고 전환 절차(`guide show migrate`)를 안내한다.
- **A2. 설정에 블록 언어가 없음** (4단계에서)
  1. 시스템은 0.8.2 이하가 쓴 블록 첫 줄의 언어를 읽어 설정에 옮긴다. 언어 표시가 없는 더 옛 블록은 한국어로 읽는다.
- **A3. `--lang`을 지정함** (4단계에서)
  1. 시스템은 그 언어로 블록을 갱신하고 설정의 언어도 바꾼다.
- **A4. 새 프로젝트에 도입함** (2단계 대신)
  1. 시스템은 새 블록을 실행 중인 CLI의 언어로 만들고 설정에 적는다.

### 수용 조건

1. 경로: 기본 흐름
   조건: CLI를 올리거나 표시 언어를 바꾼 뒤 기존 프로젝트를 조회하고 업데이트합니다.
   기대 동작: 기준선·ID·문서·결정기록을 그대로 쓰고, 블록은 설정의 언어로 유지됩니다.
2. 경로: 기본 흐름, A1
   조건: 저장 규약이 바뀐 버전으로 올립니다.
   기대 동작: 문서를 건드리지 않고 전환 절차를 안내합니다.
3. 경로: 기본 흐름, A2
   조건: 설정에 `language`가 없고 블록 첫 줄에 영어 표시가 있는 프로젝트를 업데이트합니다.
   기대 동작: 블록을 영어로 유지하고 설정에 `language: en`을 적습니다. 언어 표시가 없는 옛 블록이면 한국어로 읽습니다.
4. 경로: 기본 흐름, A3
   조건: `--lang en`을 지정해 업데이트합니다.
   기대 동작: 블록이 영어로 바뀌고 설정도 바뀌며, 마커 밖 내용은 그대로입니다.
5. 경로: A4
   조건: 영어로 실행하는 CLI로 새 프로젝트에 도입한 뒤 표시 언어를 바꿉니다.
   기대 동작: 블록은 영어로 만들어지고, 이후 표시 언어를 바꿔도 사용자 문서는 번역되지 않습니다.
