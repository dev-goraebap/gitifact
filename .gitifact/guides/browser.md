# 브라우저

브라우저는 CLI 로컬 서버가 제공하는 읽기 전용 React SPA다. 요구사항 이력, 제품 기능, 참여자, 제품 개요, 지침, Git 상태를 보여주며 요구사항을 편집하거나 승인을 만들지 않는다.

## 화면

| 경로 | 화면 |
| :--- | :--- |
| `/` | 활동. 커밋된 요구사항·설계·문서의 추가·변경·이동·제거 타임라인, 필터, 상세 드로어 |
| `/product` | 제품 개요. PRODUCT.md를 그대로 한 페이지로 |
| `/features`, `/features/$featureId` | 제품 기능 목록과 요구사항·설계 탭 상세 |
| `/guides`, `/guides/$documentId` | 지침. 열 보기(기본)와 목록 보기, 문서 본문 |
| `/contributors`, `/contributors/$email` | 참여자 카드와 상세 |
| `/git` | Git 상태 |

목록을 대체하는 상세는 경로 매개변수로 구분한다. 같은 화면 안의 상태(활동 드로어의 `selected`, 기능 상세의 `tab`, 지침의 `folder`·`view`, 검색어 `q`)는 검증된 search params에 둔다. 검색 입력은 URL replace, 상세 이동은 뒤로가기로 복원한다.

## 코드 구성 (FSD)

`app`(라우트·provider) → `pages` → `widgets` → `features` → `entities` → `shared` 방향으로만 의존한다. 단일 화면의 api/model/ui는 해당 page에 둔다. 여러 화면이 공유하는 조회·도메인 표현만 entities, 공통 화면 블록은 widgets에 둔다. 같은 계층의 다른 슬라이스를 참조하지 않고 외부에서는 index.ts 공개 API만 쓴다. 명세·문서 화면은 `pages/product` 슬라이스가 조합하고 세션·명세 Query는 `entities/project`가 소유한다.

## 데이터 흐름

| 상태 | 소유 |
| :--- | :--- |
| CLI 응답·조회 오류·재조회 상태 | TanStack Query |
| 상세 대상(기능 ID·참여자 이메일·문서 ID) | Router 경로 매개변수 |
| 검색·필터·탭·드로어 선택·보기 방식 | Router의 검증된 search params |
| 모바일 메뉴 등 일시 UI | 컴포넌트 또는 app provider |

QueryClient는 앱에서 하나만 만든다. 조회 키에 계약 버전·서버 세션·repository/worktree를 포함하고 다른 세션의 캐시를 이어 보여주지 않는다. 처음 로딩·빈 결과·조회 실패를 구분하고 재조회 실패는 이전 자료와 확인 시각을 유지한다. 세션 변경·계약 불일치는 다시 연결하도록 한다. 실패를 빈 목록이나 clean으로 바꾸지 않는다.

읽기 HTTP는 AbortSignal을 전달하고 서버 상태를 localStorage에 영구 저장하지 않는다. 자동 재시도는 제한하며 상태 갱신 POST를 반복하지 않는다. 파일 변경을 자동 통지받는다고 가정하지 않고 명시적 새로고침으로 갱신한다. 이력은 useInfiniteQuery와 더보기로 이어 읽고 다음 페이지 실패 시 기존 목록을 보존한다.

초기 조회는 200ms 뒤 골격을 보여주고 한번 보이면 최소 300ms 유지한 뒤 본문을 페이드인한다(useLoadingHold). 골격은 화면별 실제 배치를 본뜬다. 재조회 중에는 현재 목록을 유지한다.

## 레이아웃

AppShell은 wash 변형의 inset 배치다. 왼쪽 메뉴(기본 240px, 200~400px 조절, localStorage 유지)와 바닥이 같은 배경이고 본문은 둥근 모퉁이·테두리·낮은 그림자의 카드 안에 있다. 카드가 스크롤 컨테이너다. 64rem 미만에서는 여백·모퉁이·그림자를 없앤다.

페이지 헤더는 폴더 아이콘·프로젝트명 뒤에 이동 경로를 잇는 얇은 바다. 중간 계층은 링크, 마지막은 텍스트다. 새로고침처럼 페이지 전체에 걸친 동작은 헤더 오른쪽 ghost 버튼이다. 설명·경로·조회 시각은 헤더가 아니라 본문이나 하단 상태 줄에 둔다. 제목 옆 개수 배지는 두지 않는다.

모든 화면이 64rem 중앙 컬럼을 쓴다. 지침의 열 보기는 그 안에서 14rem 열이 오른쪽으로 이어지고 남는 공간은 일러스트로 채우며, 문서를 고르면 열 보기·목록 보기 모두 별도 상세 페이지로 이동한다. 목록 보기는 현재 폴더의 하위 폴더와 문서를 한 표로 보여주고 폴더 행을 누르면 그 폴더로 들어간다. 검색 중에는 전체 트리를 평면으로 보여준다. 미커밋 안내 문구는 활동·제품 기능 목록에만 둔다. 활동 상세 드로어는 데스크톱에서 오른쪽 도킹 패널(폭 조절 가능), 1024px 미만에서 전체 화면이다. 드로어의 변경 내용은 변경 후 위에 변경 전을 겹치고 손잡이를 끌어 드러내는 비교 슬라이더이며 변경 전 층은 `--color-background-yellow`다.

루트 글자 크기는 1920px까지 100%, 그 위로는 뷰포트에 비례해 2560px에서 18px이다. Astryx의 spacing·size-element 토큰은 같은 16px 기준값을 rem으로 다시 선언해 글자와 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 서버 계약

`/api/v1/session`, `/api/v1/status`(+`/refresh` POST), `/api/v1/specs?cursor&head`, `/api/v1/product/assets/<파일명>`을 쓴다. specs는 현재 명세와 문서, first-parent 이력의 관련 커밋 10개씩과 그 변경 전후, Git author 집계를 반환한다. HEAD가 달라지면 이어 읽기를 거부한다. 참여자는 최근 10,000개 커밋 기준이며 초과 시 표시한다. 필터는 불러온 범위에 적용된다.

Markdown은 Astryx의 안전한 렌더링을 쓰고 원시 HTML을 실행하지 않는다. 이메일 기반 아바타는 로컬에서 생성하며 외부 서비스에 이메일을 보내지 않는다.
