# 브라우저

브라우저는 CLI 로컬 서버가 제공하는 읽기 전용 React SPA다. 제품 개요, 요구사항, 프로젝트 위키, 활동, 참여자, Git 상태를 보여주며 요구사항을 편집하거나 승인을 만들지 않는다.

## 화면

브라우저는 제품 개요에서 시작한다. 메뉴 순서는 제품 개요 → 기능별 요구사항 → 프로젝트 위키 → 활동 → 참여자 → Git 상태이며, 아래 GITIFACT 절에 소개가 있다.

| 경로 | 화면 |
| :--- | :--- |
| `/product` | 제품 개요. 현재 명세 요약 타일·차트·최근 활동 대시보드. 위키로 가는 링크는 없다 |
| `/features`, `/features/$featureId` | 기능별 요구사항. 기능 명세 목록과 요구사항·설계 탭 상세 |
| `/wiki`, `/wiki/$documentId` | 프로젝트 위키. 왼쪽 트리와 오른쪽 본문(폴더 내용 또는 페이지)으로 된 탐색기 |
| `/` | 시작 주소. `/product`로 리다이렉트하고, 검색 인자가 있으면 0.5.0 전 활동 주소로 보고 같은 인자로 `/activity`에 보낸다 |
| `/activity` | 활동. 커밋된 요구사항·설계·문서의 추가·변경·이동·제거 타임라인, 필터, 상세 드로어 |
| `/contributors`, `/contributors/$email` | 참여자 카드와 상세 |
| `/git` | Git 상태 |
| `/about` | Gitifact 소개. README와 같은 내용 |

목록을 대체하는 상세는 경로 매개변수로 구분한다. 같은 화면 안의 상태(활동 드로어의 `selected`, 기능 상세의 `tab`, 위키의 `folder`, 검색어 `q`)는 검증된 search params에 둔다. 검색 입력은 URL replace, 상세 이동은 뒤로가기로 복원한다. 검색창은 입력값을 URL에 직접 묶지 않는다. 라우터의 비동기 갱신이 한글 조합 중인 값을 되돌려 쓰므로 필드가 입력값을 들고 URL에 따라 반영한다(`pages/product/ui/SearchFilter.tsx`).

## 코드 구성 (FSD)

`app`(라우트·provider) → `pages` → `widgets` → `features` → `entities` → `shared` 방향으로만 의존한다. 단일 화면의 api/model/ui는 해당 page에 둔다. 여러 화면이 공유하는 조회·도메인 표현만 entities, 공통 화면 블록은 widgets에 둔다. 같은 계층의 다른 슬라이스를 참조하지 않고 외부에서는 index.ts 공개 API만 쓴다. 명세·문서 화면은 `pages/product` 슬라이스가 조합하고 세션·명세 Query와 미커밋 여부 훅(`useWorkingChanges`)은 `entities/project`가 소유한다. 화면 문구는 `shared/i18n`의 `t()`·`tNodes()`로 가져오고 소개 본문은 `packages/intro/<lang>/intro.md`를 `shared/i18n`이 가져오고, 맨 앞 로고 블록은 같은 패키지의 로고 파일을 번들한 이미지로 보여 준다. 규칙은 CLI 지침의 문구 절을 따른다.

## 데이터 흐름

| 상태 | 소유 |
| :--- | :--- |
| CLI 응답·조회 오류·재조회 상태 | TanStack Query |
| 상세 대상(기능 ID·참여자 이메일·문서 ID) | Router 경로 매개변수 |
| 검색·필터·탭·드로어 선택·위키 폴더 | Router의 검증된 search params |
| 모바일 메뉴 등 일시 UI | 컴포넌트 또는 app provider |

QueryClient는 앱에서 하나만 만든다. 조회 키에 계약 버전·서버 세션·repository/worktree를 포함하고 다른 세션의 캐시를 이어 보여주지 않는다. 처음 로딩·빈 결과·조회 실패를 구분하고 재조회 실패는 이전 자료와 확인 시각을 유지한다. 세션 변경·계약 불일치는 다시 연결하도록 한다. 실패를 빈 목록이나 clean으로 바꾸지 않는다.

읽기 HTTP는 AbortSignal을 전달하고 서버 상태를 localStorage에 영구 저장하지 않는다. 자동 재시도는 제한하며 상태 갱신 POST를 반복하지 않는다. 파일 변경을 자동 통지받는다고 가정하지 않고 명시적 새로고침으로 갱신한다. 이력은 useInfiniteQuery와 더보기로 이어 읽고 다음 페이지 실패 시 기존 목록을 보존한다.

미커밋 명세 변경 여부는 두 출처를 함께 본다. 명세 응답의 `working`은 명세 화면이 채운 Query 캐시에서만 읽고 셸이 명세 API를 따로 호출하지 않으므로, gitifact 저장소가 없는 프로젝트에서 Git·소개 화면이 오류를 내지 않는다. 모든 페이지가 헤더의 프로젝트명을 위해 읽는 Git 상태 응답에서는 `.gitifact/`(과거 `.tryce/`) 아래 변경 경로가 있으면 같은 표시를 켠다. 그래서 Git 상태 페이지로 바로 들어와도 인디케이터와 배너가 보인다.

초기 조회는 200ms 뒤 골격을 보여주고 한번 보이면 최소 300ms 유지한 뒤 본문을 페이드인한다(useLoadingHold). 골격은 화면별 실제 배치를 본뜬다. 재조회 중에는 현재 목록을 유지한다.

## 레이아웃

AppShell은 wash 변형의 inset 배치다. 왼쪽 메뉴(기본 240px, 200~400px 조절, localStorage 유지)와 바닥이 같은 배경이고 본문은 둥근 모퉁이·테두리·낮은 그림자의 카드 안에 있다. 카드가 스크롤 컨테이너다. 64rem 미만에서는 여백·모퉁이·그림자를 없앤다. 미커밋 명세 변경이 있으면 Git 상태 메뉴 항목 오른쪽에 경고색 StatusDot을 두고, 설명 문장은 Git 상태 페이지 상단의 Banner에만 둔다. 활동·요구사항 목록 위에 안내 문장을 두지 않는다.

페이지 헤더는 폴더 아이콘·프로젝트명 뒤에 이동 경로를 잇는 얇은 바다. 중간 계층은 링크, 마지막은 텍스트다. 헤더 오른쪽에는 조회 시각(`<time>` + "조회")과 새로고침 ghost 버튼을 나란히 둔다. 48rem 미만에서는 조회 시각을 숨긴다. "로컬 읽기 전용" 같은 안내는 두지 않으며 설명·경로는 본문에 둔다. 제목 옆 개수 배지는 두지 않는다.

제품 개요·요구사항·활동·참여자·Git 상태·소개는 64rem 중앙 컬럼을 쓴다. 제품 개요는 페이지 제목 대신 대시보드 머리(제품 제목·ID·최근 변경·미커밋 Token·이력 링크)로 시작한다. 위키는 저장소 호스팅의 파일 탐색기 구성을 따라 콘텐츠 카드 전체를 채운다. 왼쪽 17rem에 위키 전체를 접고 펴는 Astryx TreeList, 오른쪽에 현재 위치 Breadcrumbs와 본문이 있다. 본문은 폴더일 때 그 폴더의 내용(폴더 먼저, 파일은 이름·제목·최근 변경)이고 폴더에 README.md가 있으면 목록 아래에 이어 보여 준다. 파일일 때는 제목·경로·ID·최근 변경·활동 링크와 읽기 본문이다. 트리와 본문은 따로 스크롤하고, 위치가 바뀌면 본문은 맨 위에서 시작한다. `/wiki`와 `/wiki/$documentId`는 부모 라우트 하나가 그려 페이지를 옮겨도 트리의 펼침 상태가 유지되고 화면 전체가 다시 나타나지 않는다. 48rem 미만에서는 트리를 숨기고 경로와 폴더 목록으로 이동한다. 활동 상세 드로어는 데스크톱에서 오른쪽 도킹 패널(폭 조절 가능), 1024px 미만에서 전체 화면이다. 드로어의 변경 내용은 변경 후 위에 변경 전을 겹치고 손잡이를 끌어 드러내는 비교 슬라이더이며 변경 전 층은 `--color-background-yellow`다.

루트 글자 크기는 1920px까지 100%, 그 위로는 뷰포트에 비례해 2560px에서 18px이다. Astryx의 spacing·size-element 토큰은 같은 16px 기준값을 rem으로 다시 선언해 글자와 함께 커진다. 페이지별 zoom이나 root font-size 변경은 두지 않는다.

## 차트

차트 라이브러리를 추가하지 않는다. 제품 개요의 부분-전체 막대는 인라인 SVG로 그리고, 크기 비교는 Astryx ProgressBar를 쓴다. 계열 색은 Astryx 데이터 토큰을 파랑 → 주황 → 보라 → 초록 순서로 고정해 쓰고 꼬리는 `--color-data-neutral`이다(인접 쌍의 색각 이상 분리 검증을 통과한 순서). 글자는 텍스트 토큰만 쓰고 계열 색을 입히지 않는다. 계열이 둘 이상이면 항상 범례를 두고 각 항목에 값과 비율을 직접 적는다. 분할 사이에는 표면색 2px 간격을 둔다.

## 서버 계약

`/api/v1/session`, `/api/v1/status`(+`/refresh` POST), `/api/v1/specs?cursor&head`, `/api/v1/assets/<경로>`를 쓴다. specs는 현재 명세와 문서, first-parent 이력의 관련 커밋 10개씩과 그 변경 전후, Git author 집계를 반환한다. HEAD가 달라지면 이어 읽기를 거부한다. 참여자는 최근 10,000개 커밋 기준이며 초과 시 표시한다. 필터는 불러온 범위에 적용된다. 대시보드의 변경 종류·최근 활동은 불러온 범위 기준이며 건수를 함께 표시한다.

Markdown은 Astryx의 안전한 렌더링을 쓰고 원시 HTML을 실행하지 않는다.

## 문서 링크

문서 본문의 상대 링크는 원문을 바꾸지 않고 그릴 때 해석한다. `shared/ui/document/resolveDocumentLink.ts`가 문서의 저장소 경로를 기준으로 대상을 계산하고 Astryx `Markdown`의 `components.link`·`components.image`로 렌더링한다. 위키 페이지는 `/wiki/$documentId`, 명세는 `/features/$featureId?tab=requirements|design`, 에셋은 `/api/v1/assets/<경로>`, 외부 URL은 새 탭이다. 저장소의 다른 파일은 이동하지 않는 링크 모양으로 두고 클릭하면 경로를 복사한다. 대상이 없는 페이지·기능은 취소선 텍스트와 툴팁으로 표시한다. 문서 경로는 context로 전달하며 `DocumentIndexProvider`가 첫 명세 응답의 페이지·기능 목록을 제공한다. 앞에 `/`가 붙은 링크는 앱 경로로 본다. 이메일 기반 아바타는 로컬에서 생성하며 외부 서비스에 이메일을 보내지 않는다.
