# 결정 0003. 위키 운영 방침은 README

상태: Accepted · 2026-09-18

## 맥락

0002는 모든 `docs <topic>`의 운영 지침을 `.gitifact/overrides/`로 재정의하게 했다. 써 보니 프로젝트마다 달라져야 하는 것은 위키를 꾸리는 방식뿐이었고, workflow·spec·design·commit까지 형식과 운영 두 파일로 나눠 유지할 이유가 없었다. 위키는 사용자가 쓰지 않아도 되지만 기본으로 제공되어야 했다.

## 결정

위키 운영 방침은 `.gitifact/wiki/README.md` 자체다. `docs wiki`는 형식 뒤에 README 본문을 싣고, README가 없으면 내장 기본 방침을 싣는다. `init`은 처음 도입할 때 기본 방침으로 README를 만들고 다시 만들지 않는다. 기본 방침은 "결정 기록(ADR)을 쌓는다" 하나다. 나머지 topic은 CLI 내장 지침만 쓰며 재정의와 `--eject`는 없앤다. 블록은 "요구사항·설계·코드를 바꾸기 전에 `docs wiki`를 확인한다"와 "위키 방식을 바꾸려면 README를 `spec save`로 고친다"를 안내한다.

## 결과

재정의 폴더와 topic별 두 파일이 사라지고, 위키 방침이 위키 안에서 사람과 에이전트에게 같이 보인다. README를 지우면 내장 기본으로 돌아가며 `init`은 되살리지 않는다. `init`이 처음으로 위키 페이지(`W-` ID)를 만든다. 기각한 안: 모든 topic의 재정의 유지(수요 없이 유지 비용만 큼), README를 일반 페이지로 두고 에이전트가 직접 읽게 하기(읽기를 빠뜨릴 수 있고 README가 없을 때의 기본이 없음).
