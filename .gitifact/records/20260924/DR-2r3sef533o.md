## 맥락

입력 파일을 둘 곳과 정리 규칙이 없자 프로젝트에 입력 JSON·명령 결과·명세 사본이 쌓였고, 무엇을 지워도 되는지 사용자가 직접 가려야 했다. 정리를 지침으로만 요구하면 삭제가 에이전트의 성실함에 달린다.

## 결정

CLI가 커밋 성공 때 자신이 알려 준 폴더 안의 입력 파일을 지운다. 실패·dry run·결과가 불확실한 커밋은 파일을 남긴다. 수정 시각이 7일 지난 파일은 다음 조회 때 정리한다. 빌드·테스트 로그처럼 gitifact 명령과 무관한 에이전트 산출물은 범위에 넣지 않는다.

## 검토한 대안

- 외부 경로에 쓰고 작업 후 지우라고 지침에만 적기(삭제가 에이전트의 성실함에 달린다. 샌드박스가 작업 폴더 밖 쓰기를 막으면 다시 프로젝트 안에 쓰고, Windows의 `~`·공백 경로 해석 문제가 있다)
