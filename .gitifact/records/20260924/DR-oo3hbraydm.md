## 맥락

사용자가 Gitifact 자체의 버그·개선을 남기고 싶을 때 GitHub 이슈 양식을 따로 찾지 않고 에이전트에게 부탁하게 하려 했다. 이슈는 외부로 나가는 글이라 사용자 확인이 필요하고, CLI가 GitHub 토큰을 받거나 보관하면 관리할 비밀이 생긴다. CLI가 외부로 보내는 요청은 지금까지 레지스트리 조회 하나였다.

## 결정

`gitifact feedback --file <json|->`을 둔다(사용자 선택). 로그인된 `gh`가 있으면 사용자 계정으로 `gh issue create`를 실행하고, 없거나 실패하면 제목·본문을 채운 이슈 작성 주소를 출력한다. 본문에는 버전·운영체제·Node·`schemaVersion`만 덧붙이고 `--dry-run` 미리보기를 둔다. 에이전트는 초안을 보여 주고 확인받은 뒤에만 보낸다.

## 검토한 대안

- 작성 페이지 주소만 출력(사용자가 늘 한 번 더 제출해야 한다)
- GitHub API와 토큰(토큰을 받아 보관해야 한다)
