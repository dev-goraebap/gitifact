## 맥락

로컬 서버의 라우팅을 정리하면서 express·Fastify 같은 프레임워크를 검토했다. 느린 원인은 HTTP가 아니라 git 프로세스와 파일 읽기였고, 라우팅·JSON은 1ms도 걸리지 않는다. 보안 검사는 제품 고유라 프레임워크를 써도 직접 짜야 한다. CLI는 런타임 의존성 없이 파일 하나로 번들된다.

## 결정

로컬 서버에 HTTP 프레임워크를 넣지 않는다(사용자 결정). 라우팅 정리는 경로 표와 계약의 zod 스키마로 한다.

## 검토한 대안

- express·Fastify(느린 원인이 HTTP가 아니고, 런타임 의존성 없는 번들과 맞지 않음)
