## 맥락

결정 단위 커밋은 권장일 뿐 강제하지 않고, 에이전트는 사용자 요청 없이는 커밋하지 않는다. 그래서 작업을 마친 뒤 커밋하지 않은 채 다음 작업을 이어 가면 같은 파일에 두 결정이 섞여 나눠 커밋할 수 없게 되고, 이력에서 어느 변경이 어느 결정의 것인지 흐려진다. 사용자는 커밋 단위가 깔끔할 때 이력이 보기 편하다며, 강제하지 않되 과하지 않은 안내를 원했다.

## 결정

에이전트는 작업 하나를 마치고 커밋하지 않은 채 다음 작업을 시작하게 되면 커밋을 한 번 제안하고, 같은 파일에 두 작업이 섞이면 결정별로 나눠 커밋하기 어렵다는 이유를 한 줄로 덧붙인다. 제안은 커밋 권한이 아니어서 답을 받기 전에는 커밋하지 않고, 원하지 않으면 같은 세션에서 다시 묻지 않는다. AGENTS 블록은 줄을 늘리지 않고 커밋 권한 줄에 이어 쓰며, 자세한 안내는 `guide show commit`에 둔다.

## 검토한 대안

- 커밋 강제 또는 CLI 경고(커밋 묶음은 프로젝트마다 다르고, 사용자가 강제하지 않기로 했다)
- 작업이 끝날 때마다 묻기(과하다는 우려로, 다음 작업으로 넘어가는 때 한 번만 묻는다)
