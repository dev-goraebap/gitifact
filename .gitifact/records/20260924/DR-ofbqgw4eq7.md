## 맥락

활동 화면은 이력을 페이지로 받아 받은 범위 안에서만 거르고 셌다. 필터가 아직 불러오지 않은 변경을 찾지 못했고 건수도 받은 범위의 것이었다. 사용자는 git을 쓰더라도 화면은 DB를 쓸 때처럼 전체를 대상으로 검색·필터·페이징해야 한다고 했다. 커밋이 바꾼 파일만 읽게 바꾸면서 전체를 읽는 비용은 명세 커밋 37개에 약 0.5초로 작아졌다.

## 결정

이력과 작업 폴더 문서를 SQLite 캐시에 두고 필터·검색·건수를 전체 이력 기준으로 SQL로 답한다. 커밋의 변경은 한 번 읽어 영구히 두고 HEAD마다 커밋 순서만 더하므로, 서버를 다시 띄워도 읽은 커밋은 다시 읽지 않는다. 캐시는 파생물이라 지우거나 형식 번호가 다르거나 손상되면 다시 만든다. 파일은 CLI와 함께 쓰는 `.gitifact/cache/index.db`이고, Node 24 내장 `node:sqlite`로 열어 패키지 의존성이 늘지 않는다.

## 검토한 대안

- 서버 메모리에만 두기(띄울 때마다 전체를 다시 읽음)
- JSON 파일(결국 메모리에 올려 직접 거르고 찾아야 함)
