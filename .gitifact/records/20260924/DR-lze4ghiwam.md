## 맥락

Windows에서 git 프로세스는 하는 일과 무관하게 한 번에 약 80ms가 든다. 작성자 집계가 기능마다·위키 페이지마다 `git log`를 띄우면, 기능 22개와 페이지 63개인 저장소에서 85번을 부른다.

## 결정

기능별 참여자는 명세·위키를 건드린 커밋을 한 번의 `git log`로 읽어 기능 폴더별로 나눈다. 최근 20,000개 커밋을 읽고 기능마다 2000개까지 센다.

## 검토한 대안

- 기능·페이지마다 `git log`(프로세스 수가 기능·페이지 수만큼 는다)
