## 맥락

0.7까지는 기능마다 `requirements.md`와 `design.md` 한 파일에 요구사항과 설계를 모두 담았다. 에이전트가 요구사항 하나를 읽으려 해도 기능 파일 전체를 열어야 했고, 기능이 커지면 설계 한 파일이 4만 자를 넘었다. 대가는 파일 수가 늘고(이 저장소 기능 9개에 요구사항 45, 설계 19) 설계 절과 요구사항의 짝이 파일 단위로 굵어진 것이다.

## 결정

문서 하나가 파일 하나다. 기능 폴더에 소개 `index.md`(S-), 요구사항 `requirements/<slug>.md`(R-), 설계 `design/<slug>.md`(D-, 관점별 파일, `overview.md` 필수)를 둔다. 프로젝트 지침은 `.gitifact/instructions/<이름>/index.md`(I-)다. 에이전트는 `docs list`로 제목·설명만 보고 필요한 파일만 열며, 문서를 옮기거나 제목을 바꾸면 파일 이동·수정일 뿐이다.

## 검토한 대안

- 요구사항 여러 개를 한 파일에 두고 프론트매터 목록으로 나누기(제목과 ID의 대응을 따로 유지해야 함)
- SQLite 원본(바이너리라 커밋마다 통째 저장, 레코드 단위 병합 도구 필요, diff 없음)
