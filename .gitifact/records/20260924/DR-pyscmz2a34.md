## 맥락

Windows에서 git 프로세스는 하는 일과 무관하게 한 번에 약 80ms라 호출 수가 곧 시간이다. 커밋마다 저장소 전체를 두 번 읽던 0.7의 첫 구현은 페이지 하나에 git 37~39회였다. 작성자 집계는 기능·위키 페이지마다 `git log`를 띄워 기능 22·페이지 63이면 85회였다. 0.8.0으로 전환한 저장소는 0.7 커밋의 트리를 커밋마다 따로 읽어, 캐시가 빈 상태의 첫 이력 조회가 8.6초였다.

## 결정

git 호출은 묶음 단위로 한다. 커밋의 변경은 100개씩 묶어 읽는다. 0.7 커밋은 배치의 커밋과 부모의 트리 목록을 8개씩 동시에 받고 blob 전체를 `cat-file --batch` 한 번으로 읽어, 첫 조회가 2.85초가 됐다. 작성자 집계는 저장소를 건드린 커밋을 `git log` 한 번으로 읽으며, 두 실제 저장소의 0.7 전체 이력에서 예전 방식과 결과가 같음을 대조했다.

## 검토한 대안

- 커밋·문서마다 git 호출
- 동시 실행만 늘리기(`cat-file`은 8건에서 625→571ms에 그침)
- `git log --raw`로 0.7 트리 잇기(1.0.0에 지울 코드에 복잡도를 더함)
