## 맥락

`specs list`와 `instructions list`는 걸러내기·정렬·페이지를 명령 안에서 했다. 같은 목록을 브라우저 서버가 주려면 두 곳에 따로 지어야 했다. 변경의 원문을 읽는 조회도 Git 호출과 섞여 있어, 나중에 Git이 없는 곳(원격 서버, 정적 스냅샷)에서 조회를 그대로 쓸 길이 없었다.

## 결정

목록의 걸러내기·정렬·묶기·자르기는 `queries/`의 조회가 하고 명령과 서버는 받은 결과를 그린다(DR-jvbx23yyyj의 첫 적용). 페이지 자르기는 `queries/paging.ts` 하나이며 없는 커서는 undefined로 답해 CLI는 거부하고 서버는 404로 답한다. 변경의 원문은 캐시가 받은 원문 공급원(`Originals`)으로 읽고, 지금은 Git 하나를 둔다.

## 검토한 대안

- 명령마다 가공하고 서버는 따로 짓기(같은 목록이 두 벌이 되어 결과가 어긋난다)
- 원문 공급원 없이 Git 호출을 그대로 두기(Git 없는 곳으로 조회를 옮기려면 그때 조회를 고쳐야 한다)
