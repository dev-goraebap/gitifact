## 맥락

0.8.2에서 체크아웃을 틀과 화면별 조회로 나누자 목록·상세 화면이 틀을 읽을 때 한 번, 자기 목록을 읽을 때 한 번 골격을 그렸다. 두 번째 골격에는 가짜 필터 줄이 있어 진짜 필터 아래에 겹쳤다. 사용자는 화면마다 골격을 맞추기보다 공통 로딩 애니메이션을 보이다가 부드럽게 본문으로 바꾸는 쪽을 골랐다.

## 결정

셸의 로더 하나가 화면을 그리는 첫 조회를 모두 기다린다. 100ms 뒤에 바로 나타나 최소 300ms 머물고, 본문은 모든 조회가 답한 뒤 한꺼번에 페이드인한다. 로더는 카드 위에 겹쳐 레이아웃이 움직이지 않는다. 화면이 보인 뒤의 조회는 제자리의 작은 로더를 쓴다. 결정기록 목록을 포함한 모든 화면에 적용한다. 그림은 사용자가 고른 LottieFiles의 선 로켓을 `lottie_light`(번들 +165KB)로 그리고 테마 색으로 덮는다.

## 검토한 대안

- 화면마다 모양에 맞춘 골격 한 번(목록·상세 12곳을 따로 맞춰야 한다)
- 직접 그린 Git 가지 SVG와 CSS 애니메이션(사용자가 완성도가 떨어진다고 봄)
- `lottie-web` 전체판(`eval`을 써서 CSP에 막힌다)
- 선 고양이(Pet Loading, 먼저 적용했으나 사용자가 로켓의 완성도를 더 높게 봤다)
