## 맥락

브라우저 화면을 고칠 때마다 에이전트가 `pnpm check`(약 200초)를 돌렸다. 그런데 화면은 사용자가 보고 여러 번 고쳐 달라고 하는 일이 많았다. 검수 한 번마다 전체 검사를 기다렸고, 검사하는 동안 브라우저 서버를 꺼야 해서 사용자가 화면을 볼 수 없었다. 사용자가 브라우저 작업은 사용자 검수를 받고, 전체 검사를 언제 할지 다시 정하자고 했다.

## 결정

화면을 바꾸면 바뀐 화면의 테스트 파일만 돌리고, 실제 앱을 띄워 주소를 알리며 사용자 검수를 요청한다. 사용자가 고칠 점이 없다고 하면 커밋 직전에 서버를 끄고 `pnpm check`를 한 번 돌린다. 화면이 아닌 변경은 지금처럼 커밋 묶음마다 한 번 돌린다.

## 검토한 대안

- 여러 커밋을 모아 배포 전에만 전체 검사(깨진 커밋이 이력에 남고 원인 커밋을 찾기 어렵다)
- 작업마다 전체 검사(검수를 주고받을 때마다 약 200초를 기다리고 서버를 꺼야 한다)
