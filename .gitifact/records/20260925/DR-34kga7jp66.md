## 맥락

기록 상세 한 페이지에 기록 섹션, 설명하는 문서, 같은 커밋의 다른 기록, 소스 파일이 목록으로 이어져 있었다. 사용자가 코드와 다른 기록은 커밋에 속하므로 따로 보고, 문서와 코드 모두 왼쪽 목록·오른쪽 diff로 읽는 편이 통일감 있고 보기 편하다고 했다. 결정기록 화면의 자원을 기록·커밋·문서로 나누고 1단계로 이 두 페이지부터 바꾸기로 했다(사용자 결정).

## 결정

커밋 페이지는 결정기록·문서·코드 탭으로 나누고 탭마다 `?tab=`으로 주소를 둔다. 문서 탭, 코드 탭, 기록 상세의 문서는 모두 왼쪽 파일 목록과 오른쪽 본문 하나로 읽는다. 좁은 화면에서는 목록을 숨기고 선택 상자로 파일을 고른다. 기록 상세의 커밋 정보는 머리의 메타 줄에 두고 다른 기록·코드는 커밋 페이지의 탭으로 링크한다. 목록의 커밋 해시와 제목은 커밋 페이지로 링크한다.

## 검토한 대안

- 기록 상세 안에서 탭으로 나누기(코드와 다른 기록이 기록 페이지에 남고, 커밋의 코드를 주소로 가리킬 수 없다)
- 파일을 접는 행으로 유지(파일마다 열고 닫아야 하고, 여러 파일을 오가며 읽기 어렵다)
- 좁은 화면에서 목록을 본문 위에 두기(파일이 많으면 본문이 한참 아래로 밀린다)
- 기록 상세 아래의 커밋 카드(사용자가 머리의 메타 줄로 충분하다고 했다)
