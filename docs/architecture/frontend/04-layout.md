# 프론트엔드 레이아웃

Gentask의 04-layout.md와 Claude의 browser-design-v2/Main.dc.html을 바탕으로 구성한다. 프로토타입의 고정 화면 크기·예시 데이터·이전 파일 형식은 그대로 구현하지 않는다.

앱 전체 골격은 widgets/app-shell, 라우트 연결은 app, 본문은 pages가 소유한다. 데스크톱 왼쪽 메뉴는 약 15rem을 사용한다. 이력·기여자는 목록과 약 26rem의 상세를 배치하지만, 제품 기능은 19~21rem 기능 목록과 남은 폭을 사용하는 명세 본문으로 구성한다. 문서 읽기에 목록 중심의 상세 패널 비율을 재사용하지 않는다. 헤더는 제목·설명·조회 시각으로 구성하고 필터 툴바와 분리한다. 긴 경로와 좁은 화면에서는 줄바꿈을 허용한다. 제목 옆 개수 배지는 두지 않는다.

제품 기능은 history-prototype의 문서 중심 배치를 따른다. 검색은 기능 목록 안에 두고 행에 제목·요구사항 수·S-ID를 표시한다. 본문은 명세 제목·목차·요구사항별 구분과 R-ID를 제공한다. 조건과 기대 동작은 박스 없이 줄을 구분하며, 표시용 줄바꿈 때문에 저장된 원문을 바꾸지 않는다. neutral 테마는 유지하고 색상·선택·배경은 설치된 토큰을 사용한다.

배치만 바뀌면 CSS, 상호작용이 바뀌면 React 컴포넌트로 처리한다. 모바일 경계는 Astryx neutral의 lg(1024px)와 CSS의 64rem을 일치시킨다. 경계를 바꾸면 두 위치를 함께 수정한다. 좁은 화면에서는 메뉴를 열고 닫을 수 있고 선택한 상세가 목록 대신 본문 폭을 사용한다. 상세를 닫으면 필터를 유지한 목록으로 돌아간다. 데스크톱 목록은 행 기반, 상세는 독립 스크롤을 사용한다. 긴 제목·ID·경로·Markdown이 페이지 전체를 가로로 밀어내지 않도록 한다.

Astryx AppShell·Layout·LayoutPanel·LayoutContent·VStack·HStack을 우선 사용한다. 중복 패딩과 구분선을 줄이고 간격은 토큰을 사용한다. 본문에는 rem을 사용하며 페이지별 zoom이나 root font-size 변경은 하지 않는다.

키보드 내비게이션, 상세 진입과 닫기, 작은 화면, 긴 콘텐츠, 라이트·다크를 검증한다. Tryce는 읽기 전용이므로 생성 FAB·편집 모달·자동 저장은 포함하지 않는다.

## 이력 받은편지함 배치

사용자가 제공한 Astryx Playground의 받은편지함 예시를 기준으로 이력은 Table 열로 정렬한다. 작성자·요구사항과 이유·기능·변경 종류·시각을 배치하며 행은 64px, 표 헤더는 40px이다. 그래프는 헤더 아래 실제 행 중앙에 맞춘다. 상세를 열면 작성자와 기능 열을 접고 작성자는 제목 아래에 표시한다. 모바일에서는 시각 열도 접으며 전체 정보는 상세에서 읽는다. 메일의 체크박스·답장·보관 동작은 도입하지 않는다.

행 클릭과 Enter/Space로 변경 상세를 열고 현재 행을 강조한다. 이유 미리보기는 한 줄로 제한하며 실제 이유가 없으면 커밋 메시지를 보여준다. R-ID와 전체 시각은 상세에서 확인한다. 변경 종류는 텍스트와 색상을 함께 표시한다.

이력 미리보기는 변경 이유 대신 변경 후 본문을 표시한다. 삭제는 삭제 안내로 구분하며 변경 전 본문을 변경 후로 오인시키지 않는다. 상세를 열어도 작성자 아바타는 유지하고 좁은 열에서는 이름만 생략한다. 읽기 패널은 Astryx LayoutPanel/useResizable/ResizeHandle로 독립 스크롤과 너비 조절을 제공한다. 상단에 변경 종류·닫기, 본문에 제목·작성자·시각과 변경 후를 배치하고 변경 전은 접어서 제공한다. 삭제된 항목의 변경 전은 처음부터 펼친다. 변경 이유는 상세 아래에 보존한다.
