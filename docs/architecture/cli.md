# CLI와 공통 코드

CLI는 사용자 입력과 실행 환경을 받아 제품 규칙을 실행하는 진입점이다. 터미널 명령과 브라우저 API가 같은 규칙을 사용하도록 구성한다. [제품 기준](../bref.md)의 영속 형식과 개발 예외는 그대로 적용한다.

## 코드 책임

```text
apps/cli/src/
  main.ts                프로세스 시작과 명령 연결
  commands/              인자 해석, 유스케이스 호출
  adapters/
    git/                 Git 실행과 스냅샷 읽기
    filesystem/          파일·잠금·보존·복구
    skills/              스킬 탐색과 관리 대상 배포
  output/                core 결과를 버전 있는 DTO·텍스트로 변환
  server/                HTTP·정적 파일 제공과 실행 수명
packages/core/src/
  domain/                요구사항·상태·사건·진단
  formats/               공개 형식별 파싱·검증
  use-cases/             조회·검사·기록의 작업 흐름
  ports/                 저장소·파일·시계 등 외부 입력 계약
packages/contracts/src/
  versions/              외부 JSON 계약과 런타임 검증
```

이는 역할의 배치도이며 첫 기능에 필요하지 않은 폴더는 만들지 않는다. FSD는 브라우저의 조직 규칙으로 사용하고 CLI에 억지로 적용하지 않는다.

명령은 인자와 환경을 확인해 core를 호출하고 결과를 출력한다. Git 실행·전역 시간·파일 시스템을 core 안에서 직접 호출하지 않는다. 필요한 경계를 작은 port로 정의하고 CLI에서 구현체를 연결한다. 모든 함수에 불필요한 인터페이스나 클래스를 만들지는 않는다.

Git·파일 어댑터는 아직 CLI만 사용하는 동안 앱 안에 둔다. 다른 서버나 도구가 실제로 재사용해야 할 때 독립 패키지로 추출한다. `packages/utils`에 관련 없는 코드를 모으지 않는다.

## 계약과 오류

내부 domain 모델과 외부 JSON DTO를 구분한다. `contracts`는 브라우저에서도 실행 가능한 타입·검증·오류 코드를 제공하고 Node.js 전용 코드를 포함하지 않는다. CLI의 출력과 HTTP 응답은 같은 버전별 DTO를 사용하되, 명령별 요약과 화면별 응답 범위는 각 계약에 맞게 구성한다.

stdout에는 선택한 출력 형식만 내보낸다. 로그·진행 상황은 stderr로 구분한다. 오류의 종류와 종료 코드를 문서화하며, 검사 실패·진단 발견·미실행을 하나의 boolean으로 합치지 않는다. 정확한 종료 코드와 필드는 첫 CLI 계약에서 확정한다.

형식 해석은 공개 버전별로 분리하고 과거 의미를 보존한다. 알 수 없는 형식으로 쓰지 않는다. Git 명령에는 shell 문자열을 조합하는 대신 인자 배열을 사용하고, 경로·참조·종료 코드를 확인한다. Git 및 파일 접근은 호출된 현재 checkout을 기준으로 한다.

## 로컬 서버

첫 브라우저 서버는 `apps/cli` 안에서 Node.js의 `node:http`로 제공한다. 세 개의 고정 endpoint와 정적 자산 제공에 별도 프레임워크를 추가하지 않았다. 상세 계약은 [로컬 브라우저 서버](../specs/browser-server.md)를 따른다. 별도의 `apps/server`는 독립 실행·배포가 필요할 때 검토한다. 명령 파서는 Commander를 사용한다.

서버는 기본적으로 loopback에 바인딩한다. 현재 프로젝트 컨텍스트를 서버가 결정하고, 클라이언트의 임의 경로로 로컬 파일이나 명령을 실행하지 않는다. 외부 origin의 요청을 무조건 허용하지 않고 재검사 같은 동작도 origin·호스트 검증을 적용한다. Markdown·diff·스킬 내용은 데이터로 렌더링하며 임의 HTML 실행을 허용하지 않는다.

GET은 정의한 조회만 수행한다. 재검사는 별도 요청으로 받고 중복 실행을 제어한다. 진행 중인 요청의 취소, 서버 종료, 포트 충돌, 정적 파일 경로를 처리한다. 서버를 종료하면 자신이 만든 작업과 리소스만 정리한다.

스킬·요구사항의 편집 endpoint는 제공하지 않는다. 브라우저의 읽기 전용 범위를 바꾸는 일은 서버 라이브러리 선택과 별개의 제품 결정이다.

## 빌드와 배포

core·contracts를 먼저 빌드하고 browser와 cli를 각자의 환경에 맞게 빌드한다. CLI 패키징 단계에서 필요한 내부 코드를 번들하거나 명시적으로 포함하고, 브라우저 정적 파일과 스킬 배포 자산을 수집한다. 게시하지 않은 private workspace 패키지를 레지스트리에서 찾는 배포물이 되지 않도록 한다.

배포 검증은 packed artifact를 새 임시 폴더에 설치해 수행한다. monorepo 상대 경로나 개발 의존성이 우연히 있어서 성공한 결과를 배포 성공으로 보지 않는다. 스킬 원본 업그레이드와 파생본 sync도 분리해 시험한다.

## 테스트 경계

- core는 고정 입력으로 형식·상태 전이·진단을 시험한다.
- Git·파일 어댑터는 임시 저장소에서 index·작업 트리·이력·worktree를 구분해 시험한다.
- CLI는 인자, stdout/stderr, 종료 코드, 잘못된 형식과 실패 후 복구를 확인한다.
- contracts는 제공자와 소비자가 같은 JSON을 검증하는지 확인한다.
- 서버는 정의한 조회 범위·재검사·정적 파일·잘못된 입력을 시험한다.
- 브라우저와의 통합은 실제 API로 첫 화면과 재검사를 확인한다.

첫 환경 구성에서 테스트 도구와 실행 명령을 선택·검증해 기록한다. 핵심 호환성 시험은 tryce 자체의 check에만 의존하지 않는다.
