# 에이전트 스킬 연결

`tryce-workflow`는 작업 시작의 brief 조회와 작업 중 중요한 note 작성을 에이전트에 연결한다. 사용자에게 매번 note 명령을 실행하도록 요구하지 않는다. 스킬은 판단 절차이며 대화를 감시하는 서비스나 실행 훅이 아니다.

상태: 개발 저장소의 첫 연결. 2026-09-13 사용자가 원본만 커밋하고 에이전트용 복사본은 로컬 생성하기로 결정했다. 이번 동기화 스크립트는 DEV-04의 개발 도구이며 제품의 init/sync/eject 명령이나 공개 설치 규약은 아니다.

## 원본과 복사본

| 역할 | 경로 | Git 보관 |
| :--- | :--- | :--- |
| 편집 원본 | `.agents/skills/tryce-workflow/SKILL.md` | 커밋 |
| Claude Code 복사본 | `.claude/skills/tryce-workflow/SKILL.md` | 로컬 생성, ignore |
| 로컬 배포 관계·지문 | `.agents/tryce-local-skills.json` | 로컬 생성, ignore |

Codex는 원본을 읽는다. Claude Code에는 같은 내용을 복사한다. 사용자 전역 경로와 다른 스킬은 관리하지 않는다. 파일명이 같거나 내용 지문이 같아도 매니페스트가 없는 기존 복사본은 소유 파일로 채택하지 않는다.

원본은 현재 구현된 brief·note만 안내한다. 이 저장소에서는 AGENTS.md와 개발 문서가 지정한 `pnpm cli` 또는 빌드 실행 파일을 사용한다. 다른 프로젝트에서는 그 프로젝트가 지정한 CLI를 확인해야 한다. 스킬 본문에 이 저장소의 절대 경로나 개발 전용 예외를 심지 않는다.

## 생성과 갱신

```sh
pnpm skills:sync
pnpm skills:check
pnpm skills:test
```

sync는 실행 스크립트가 속한 이 저장소를 대상으로 한다. 임의 대상 경로나 전역 설치 옵션은 없다. 첫 실행은 복사본과 로컬 매니페스트를 만들고, 재실행은 원본이 바뀐 경우 관리 중인 복사본만 갱신한다. 원본을 새 템플릿으로 교체하는 upgrade는 수행하지 않는다.

check는 파일을 쓰지 않고 복사본과 원본의 일치를 확인한다. 성공은 종료 코드 0, 누락·오래된 복사본·사용자 수정·읽기 실패는 종료 코드 1이다. 새 checkout에서는 먼저 sync를 실행한다. 저장소의 전체 테스트는 개인 복사본 생성을 요구하지 않고 임시 폴더에서 동기화를 검증한다.

로컬 매니페스트 버전 1은 고정 source·target 경로와 마지막 배포 바이트의 SHA-256을 기록한다. 복사 전 전후 지문을 먼저 저장하고 완성된 임시 파일을 게시한다. 중단 후에는 기록한 두 상태 중 실제 파일에 맞춰 재개한다. 임의 지문으로 매니페스트를 고쳐 충돌을 우회하지 않는다. 이는 로컬 복구 자료이며 프로젝트 기록 형식 prototype-1을 바꾸지 않는다.

복사본을 직접 수정했다면 sync가 실패한다. 원본과 비교해 필요한 내용을 원본에 반영하고, 로컬 수정본을 별도로 보존한 뒤 마지막 배포 상태로 복구하고 다시 실행한다. 소유권이 없는 같은 이름의 파일도 사용자가 보존·이동할 대상을 확인하기 전에는 덮어쓰지 않는다.

잠금 `.agents/tryce-local-skills.lock`이 남으면 실행 중인 sync가 없는지 확인한다. 중단된 실행의 잠금임을 확인한 뒤 해당 잠금만 정리한다. 실패 시 남은 `.tryce-skill-*.tmp`는 복구 자료로 확인하고 정리한다. 지속적으로 경로를 바꾸는 외부 프로세스, 실제 전원 손실·디스크 부족·ACL 오류는 검증하지 않았다.

## 제거와 배포 범위

자동 eject는 아직 없다. 로컬 연결을 제거하려면 매니페스트의 고정 대상과 지문이 현재 복사본과 같은지 확인하고 그 파일과 로컬 매니페스트만 제거한다. 수정본은 먼저 보존한다. `.claude/skills` 전체나 원본을 재귀 삭제하지 않는다. 다음 sync는 복사본을 다시 만든다.

공개 CLI에 스킬 자산을 묶고 다른 프로젝트에 설치·갱신·제거하는 단계는 후속 작업이다. 정확한 소유권·복구·형식 호환성을 제품 명령으로 검증하기 전까지 DEV-04를 종료하지 않는다.

## 탐색과 검증 근거

2026-09-13 공식 문서를 확인했다. Codex는 작업 위치부터 저장소 루트 사이의 `.agents/skills`를 탐색하고, Claude Code의 프로젝트 스킬 경로는 `.claude/skills`다. [Codex 스킬](https://learn.chatgpt.com/docs/build-skills), [Claude Code 스킬](https://code.claude.com/docs/en/skills).

파일이 존재하거나 check가 성공한 것은 현재 세션에서 스킬이 선택·실행됐다는 증거가 아니다. 새 세션의 스킬 목록에서 `tryce-workflow`를 확인하고 필요하면 명시적으로 호출한다. 탐색되지 않으면 에이전트를 재시작해 확인한다. 자동 선택의 빈도와 실제 Claude 세션 실행은 이번 파일 검증에 포함하지 않는다.

스킬 형식 검증과 임시 폴더 테스트 5개가 통과했다. 생성·재실행·원본 수정 반영, 다른 스킬·사용자 수정본 보존, 중단 상태 재개, 잠금·손상 매니페스트 보존, junction 거부를 확인했다. CLI 본체의 동작과 지정 빌드는 변경하지 않았다.
