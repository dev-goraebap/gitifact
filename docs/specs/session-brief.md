# 세션 브리핑

`tryce brief`는 새 작업을 시작할 때 읽는 현재 프로젝트의 지도다. 설정·도입 기준선·Git 변경·프로토타입 기록과 문서 위치를 함께 보여준다. 이 명령이 작업의 우선순위나 요구사항 충족 여부를 판단하지는 않는다.

상태: 첫 개발용 구현 명세. 2026-09-13 사용자가 핵심 정보와 원문 참조, 생략 표시를 제공하는 방향을 승인했다. [제품 기준](../bref.md)의 brief 전체 목표 중 현재 구현된 자료만 연결한다. 영속 형식은 바꾸지 않는다.

## 명령

```sh
tryce brief
tryce brief --format text
tryce brief --all
```

JSON이 기본이며 text는 사람이 읽는 표현이다. 실행 위치의 checkout을 대상으로 한다. 하위 폴더에서도 같은 저장소 루트를 사용하고 linked worktree·submodule은 해당 checkout을 읽는다. 입력을 바꾸는 Git 환경변수, bare 저장소, Git 관리 디렉터리는 기존 status와 같이 거부한다.

초기화하지 않은 저장소에서도 Git 상태와 문서 위치를 보여준다. 설정 없음은 not-initialized, init-1의 기록 미활성화는 notes-not-enabled로 표시한다. HEAD나 index에 있는 설정이 작업 폴더에서 삭제된 경우는 초기화 전 상태가 아니라 오류다. 명령이 init이나 note enable을 대신 실행하지 않는다.

## 관측 범위

| 자료 | 출처와 제공 내용 |
| :--- | :--- |
| 프로젝트 | 작업 폴더의 `.tryce/config.json`, 형식·모드·기준선과 실제 기준선 검증 |
| Git | HEAD, staged·unstaged·untracked·conflicted 집계와 변경 경로 |
| 기록 | 작업 폴더의 note-1 기록, ID·종류·시각·작성 주체·본문·참조·정정 관계 |
| 문서 | 루트 AGENTS.md·README.md와 docs 아래 Markdown의 실제 파일 위치 |

문서 이름은 대소문자를 구분하지 않고 탐색한다. docs는 최대 깊이 8, 하위 항목 1,000개까지 탐색한다. 문서 본문과 링크는 따라 읽지 않는다. 경로가 없는 문서를 추천 경로로 만들어 넣지 않는다. 문서 트리의 링크·junction은 따라가지 않고 해당 자료의 오류로 표시한다. 하위 앱·패키지의 별도 AGENTS.md와 사용자 전역 지침·에이전트 스킬은 탐색 범위 밖이다.

프로젝트와 기록은 working-tree 자료다. Git 관측은 HEAD·index·작업 폴더를 구분하며 부분 staging을 집계에 보존한다. 기록이 목록에 있다는 사실만으로 커밋·승인·테스트 완료를 표시하지 않는다. 요구사항 상태, 작업 상태, 미결 질문 추출, 과거 이력 분석, 스킬 탐색은 unsupported에 명시한다. 본문에 물음표나 TODO가 있다는 이유로 미결 질문을 만들지 않는다.

`checks`는 항상 not-run / brief-is-observation-only다. 설정·기록의 스키마 검증과 기준선 확인은 조회의 전제이며 제품 check가 실행됐다는 의미는 아니다. 모드상 검사 비활성과 검사 통과도 추정하지 않는다.

## 기본 분량과 전체 조회

첫 출력 버전의 기본값은 다음과 같다. 전체 brief의 의미적 중요도나 전역 토큰 상한을 확정하는 정책은 아니다.

| 자료 | 기본 제공 | 추가 조회 |
| :--- | :--- | :--- |
| 기록 | 기록 시각 내림차순 20개, 본문 앞 240 Unicode 코드 포인트 | brief --all, note list, note show ID |
| Git 변경 | 현재 관측 순서의 20개 | brief --all, status |
| 문서 위치 | 지침·README 이후 docs 경로순 30개 | brief --all |

동일 시각의 기록은 ID 순서로 정렬한다. 최신 순서가 중요도나 판단의 유효성을 뜻하지 않는다. 각 목록은 total·included·omitted를 제공하고 본문에는 textTruncated를 표시한다. 원문 경로와 추가 조회 명령을 함께 제공한다. 오래된 제약이 기본 목록에서 빠질 수 있으므로 에이전트는 생략 수와 작업 범위를 확인하고 필요하면 전체 조회한다.

`--all`은 지원 범위 내에서 목록과 기록 본문을 생략하지 않는다. Git 어댑터의 출력 제한, note의 파일당 64 KiB·총 16 MiB·1,000개 제한, 문서 탐색 제한은 유지한다. 한도를 넘으면 일부를 전체 결과로 꾸미지 않고 오류로 표시한다. 따라서 all이 Git 전체 이력이나 모든 프로젝트 문서를 읽는다는 뜻은 아니다.

본문은 기계적으로 앞부분을 발췌한다. 에이전트의 요약이나 CLI가 판단한 핵심 문장으로 표현하지 않는다. Unicode 문자를 중간에서 자르지 않는다. text 출력은 경로·본문의 제어 문자 등을 escape해 터미널 출력과 구분한다.

## 정정 관계

원문의 references와 supersedes를 보존하고, 전체 기록에서 해당 ID를 정정 대상으로 삼은 ID들을 correctedBy로 계산한다. 기본 20개를 고른 뒤 관계를 계산하지 않는다. 후속 정정이 기본 목록에 빠졌더라도 원문에 그 ID를 표시한다.

정정 전 원문도 숨기지 않는다. 여러 후속 정정이 있으면 모두 표시하고 최신 시각 하나를 최종 결론으로 선택하지 않는다. 없는 참조·정정 순환·파일명과 ID 불일치는 note와 같은 규칙으로 거부한다.

## 일관성과 실패

Git 상태를 앞뒤로 관측하고, 정상적으로 읽은 설정 바이트·기록 지문·문서 목록을 다시 확인한다. 문서 본문은 관측하지 않으므로 문서 내용의 스냅샷은 제공하지 않는다. 확인 사이 외부 작업이 바뀌었다 되돌아오는 경우까지 막지 못하며 원자적 스냅샷이라고 표시하지 않는다.

Git 저장소·worktree·HEAD·변경 상태가 달라지면 REPOSITORY_CHANGED로 전체 보고서를 거부한다. 설정이 바뀌면 설정과 그 설정에 의존한 기록을 현재 결과로 제시하지 않는다. 기록이나 문서 목록의 변경·손상·조회 실패는 해당 자료에 오류로 표시하고, 독립적으로 확인한 Git 상태와 다른 자료는 보존한다.

알 수 없는 설정을 기본값이나 HEAD 설정으로 대체하지 않는다. 손상되거나 삭제된 기록, 잠금이 남아 읽는 시점이 불명확한 기록을 빈 목록으로 표시하지 않는다. 기준선을 확인할 수 없으면 프로젝트 자료를 오류로 표시한다. 외부 파일·프로세스·네트워크를 복구하려고 자동 변경하지 않는다.

파일·캐시·잠금·설정·index·refs·지침을 만들거나 수정하지 않는다. note 작업 잠금이 있으면 해당 기록의 PROJECT_BUSY를 알리고 잠금을 지우지 않는다. 개별 자료의 시각을 같게 만들거나 오류를 검사 성공으로 치환하지 않는다.

## 출력 계약 brief / 1

정상 결과는 `contract: brief`, `version: 1`, `ok: true`, report를 stdout·종료 코드 0으로 출력한다. 초기화 전 상태나 note 미활성화는 정상적으로 확인 가능한 상태이므로 그 자체로 실패가 아니다.

일부 자료를 확인하지 못했으면 `ok: false`, `error.code: INCOMPLETE_BRIEF`, 부분 report를 stderr·종료 코드 1로 출력한다. report의 project·notes·documents는 각각 available/data, not-available/reason, error/error 중 하나다. Git 관측 자체가 실패하거나 일관성이 깨지면 report는 null이며 구체적 오류를 제공한다. 기계 소비자는 stdout과 stderr를 구분해 읽고 ok를 확인한다. 옵션 오류는 Commander의 text 진단이다.

report는 관측 ID·시작/종료 시각·best-effort, 저장소·worktree 식별자, Git 상태, 자료별 상태, 조회 scope, checks, unsupported, followUp을 포함한다. 목록의 total은 해당 조회 범위의 개수이고 의미적 진단 개수가 아니다.

## 검증과 적용

고정 기록으로 정렬·본문 발췌·생략 개수·정정 관계를 검증하고, 임시 저장소에서 초기화 전 상태·init-1·prototype-1·오류·변경 중 조회·부분 결과·linked worktree·전체 파일 보존을 확인한다. 설치한 CLI로도 brief가 실행되는지 확인한다.

검증한 빌드를 지정한 뒤 우리 프로젝트에서 brief를 실행하고 AGENTS.md의 작업 시작 절차에 연결한다. 중요한 새 판단은 계속 note로 작성한다. brief 출력만으로 원문 지침을 읽었거나 요구사항 검사를 수행했다고 표시하지 않는다. DEV-02는 지원한 브리핑 범위에서만 축소하고 요구사항 검사 등 미지원 범위는 유지한다.
