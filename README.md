# tryce

에이전트와 함께 만드는 프로젝트의 요구사항과 결정 이력을 Git에 남기는 도구입니다.

tryce는 Claude Code, Codex 등 기존 개발 에이전트와 함께 사용하는 CLI를 지향합니다. 요구사항, 변경 이유, 구현 기록을 연결하고, 새 세션이 프로젝트의 맥락을 이어받을 수 있도록 돕습니다.

> 0.1.0은 초기 프로토타입입니다. 현재 지원 범위는 아래 프로젝트 상태를 참고하세요. 요구사항·승인·이력 검사 전체를 구현한 버전은 아닙니다.

## 설치와 시작

Node.js 24.x와 Git이 필요합니다. 현재 실행 검증 환경은 Windows입니다.

```sh
npm install -g @tryce/cli
```

사용할 Git 프로젝트에서 실행합니다.

```sh
tryce init --mode prototype
tryce note enable
tryce skills install --agent claude
tryce brief --format text
tryce browser
```

Codex를 사용하면 `--agent codex`를 지정합니다. browser가 출력한 로컬 URL을 열어 확인합니다. 자세한 동작과 제한은 [CLI 안내](apps/cli/README.md)를 참고하세요.

## 왜 tryce인가요?

코드를 읽으면 현재 동작은 알 수 있습니다. 하지만 요구사항을 바꾼 이유, 시도하다 포기한 접근, 다음 작업에서 확인해야 할 질문까지 복원하기는 어렵습니다.

tryce는 개발 과정에서 이런 정보를 남기려 합니다.

- **요구사항:** 무엇을 만들고 어떤 동작을 유지해야 하는지
- **결정과 이유:** 무엇을 바꾸거나 제외했고 그 이유가 무엇인지
- **구현 이력:** 어떤 커밋이 어떤 요구사항과 연결되는지
- **다음 작업의 맥락:** 진행 상황과 미결 질문, 이어서 읽을 문서가 무엇인지

기록은 프로젝트와 함께 Git에 보관합니다. 에이전트나 세션이 바뀌어도 같은 근거에서 작업을 이어가는 것이 목표입니다.

## 어떤 흐름으로 사용하나요?

1. **기준선을 정합니다.** 기존 프로젝트에 도입한 시점을 기록하고, 새 기능이나 변경하는 영역부터 요구사항을 정리합니다.
2. **에이전트와 계획을 작성합니다.** 요구사항, 설계, 작업을 구체화하고 결정한 이유를 남깁니다.
3. **변경을 기록합니다.** 구현 커밋을 요구사항에 연결합니다. 계획이 바뀌면 관련 문서와 코드도 함께 갱신합니다.
4. **다음 세션으로 이어갑니다.** 브리핑으로 현재 상태를 확인하고 필요한 문서와 질문부터 살펴봅니다.

프로토타입에서는 발견한 내용과 제약, 기각 이유를 먼저 기록하고 이후 spec으로 정리하는 흐름을 지원할 예정입니다.

## 개발 중인 기능

| 기능 | 역할 |
| :--- | :--- |
| 요구사항과 결정 기록 | 요구사항의 변경·대체·제외와 그 이유를 보관합니다. |
| 이력 검사 | 추적 없는 변경이나 기록의 구조적 불일치를 확인합니다. |
| 세션 브리핑 | 현재 작업, 미결 질문, 최근 결정과 참고할 문서를 제공합니다. |
| 스킬 현황 | 프로젝트와 사용자 환경의 스킬을 묶어 보여주고 에이전트별 탐색 상태를 구분합니다. |
| 읽기 전용 브라우저 | 요구사항, 변경 이력, 작업·커밋·테스트 연결을 살펴봅니다. |

## 설계 방향

**기존 작업 방식을 존중합니다.** 개인 개발자와 소규모 팀이 사용하던 에이전트, 브랜치, Git worktree 흐름 안에서 동작하도록 설계합니다.

**판단과 기록의 역할을 구분합니다.** 에이전트는 맥락을 해석하고 사용자와 대화합니다. CLI는 기록과 구조 검증을 담당하며, 커밋이 있다는 이유만으로 작업 완료를 단정하지 않습니다.

**관리하는 범위를 명확히 합니다.** tryce가 제공하는 스킬은 `.agents/skills`를 원본으로 관리하고 필요한 에이전트 경로에 동기화합니다. 사용자가 설치한 외부 스킬과 플러그인은 변경하지 않고 현황을 보여줍니다.

**업데이트와 프로젝트 전환을 분리합니다.** CLI 업데이트만으로 프로젝트 파일을 바꾸지 않습니다. 과거 이력의 의미를 보존하고, 형식 전환이 필요하면 변경 내용을 확인하고 복구할 수 있는 절차를 제공합니다.

## 프로젝트 상태

제품 기준과 주요 기록 규약을 정리하고 CLI·브라우저의 개발 환경을 구축했습니다. `init`으로 프로젝트 설정과 도입 기준선을 만들고, `note`로 프로토타입의 발견·제약·기각 이유를 남길 수 있습니다. `status`는 Git 변경을 조회하고 `browser`는 같은 정보를 로컬 화면에 표시합니다. `brief`는 설정·Git 상태·기록·문서 위치를 모아 새 세션에 전달합니다. `skills install/sync/remove`는 스킬 원본 설치와 로컬 복사본 관리를 지원합니다. 요구사항 기록·검사와 훅은 아직 지원하지 않습니다.

확정 사항과 남은 설계 항목은 [제품·설계 기준](docs/bref.md)에서 확인할 수 있습니다.

## 개발 환경

Node.js 24와 pnpm 10.33.0을 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm browser:install
pnpm check
pnpm cli browser
```

CLI 실행과 검증 범위는 [개발 환경](docs/development.md), 코드 구조는 [아키텍처 기준](docs/architecture/README.md)을 참고하세요.

개발용 `tryce-workflow` 스킬은 작업 시작의 brief 조회와 중요한 판단의 note 작성을 안내합니다. Codex는 원본을 읽고, Claude Code용 로컬 복사본은 `pnpm skills:sync`로 생성합니다. [스킬 연결](docs/specs/agent-skills.md)에서 사용·갱신 절차를 확인할 수 있습니다.

다른 프로젝트에 설치한 CLI에서는 `tryce skills install --agent claude`로 연결합니다. 이후 `tryce skills sync`로 복사본을 갱신하고 `tryce skills remove`로 로컬 복사본을 제거합니다. 원본과 사용자 수정 보존 범위는 [프로젝트 스킬 배포](docs/specs/skill-distribution.md)를 참고하세요.
