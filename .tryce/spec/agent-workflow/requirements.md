# 에이전트 작업 흐름 요구사항

## 제품 대화에서 요구사항 식별
<!-- tryce-req: R-wqv343j4kd -->

사용자는 방법론이나 기록 명령을 배우지 않고 제품 개발에 집중한다. 에이전트가 대화에서 제품 동작과 제약을 식별해 기록하며 CLI가 다른 앱의 대화를 감시하지 않는다.

### 수용 조건

1. 조건: 사용자가 기능이나 제품 제약을 요청합니다.
   기대 동작: 에이전트는 관련 명세를 정리합니다. 단순 함수 이름 변경·푸시 같은 작업 지시는 제품 요구사항으로 등록하지 않습니다.

새 기능을 정리할 때 에이전트는 요구사항을 바탕으로 구현 설계도 함께 작성한다. 기존 문서를 읽고 필요한 부분을 갱신하며 사용자가 요구사항만 요청한 경우는 따른다.

## 필요한 질문과 점진적 정리
<!-- tryce-req: R-7seqwcdwlq -->

초기 대화에서 대상 사용자·목적·핵심 흐름·실패 조건을 파악한다. 이미 설명한 내용을 반복 질문하거나 기록 승인 절차를 강제하지 않는다.

### 수용 조건

1. 조건: 제품 의미가 모호합니다.
   기대 동작: 결정에 필요한 질문을 하고 독립적인 작업은 진행합니다. 일반 유지보수에서는 변경하는 영역부터 정리합니다.

## 요청에 따른 기존 기능 도출
<!-- tryce-req: R-dbet7z7kpa -->

코드·테스트·문서·Git·대화에서 기존 요구사항을 도출할 수 있다. 특정 문서 폴더나 DDD 구조는 필수가 아니다.

### 수용 조건

1. 조건: 사용자가 기존 기능 정리를 요청합니다.
   기대 동작: 관측 동작과 사용자 의도를 구분하고 불확실한 내용은 질문합니다. 조사·미조사 범위를 알리며 승인이나 구현 완료를 소급하지 않습니다.
