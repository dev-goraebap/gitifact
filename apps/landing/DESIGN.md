# Gitifact 랜딩페이지 설계

이 페이지는 Gitifact를 처음 보는 사람이 에이전트와 계속 개발할 때 무엇이 남고, 나중에 무엇을 다시 볼 수 있는지 이해하도록 돕는다. 내용의 기준은 소개 원본 `packages/intro/<lang>/intro.md`(루트 README)이고, 제품 기록의 원본은 `.gitifact/spec/`이다.

- 첫 화면: 제품이 무슨 동작을 하는지, 코드가 왜 바뀌었는지가 코드와 같은 커밋으로 Git에 남는다는 점을 보여 주고, 소개와 같은 시작 프롬프트를 둔다.
- 해결하려는 문제: 소개의 “그냥 git log를 찾아보면 안 되나요?” 질문들(현재 동작, 버린 대안, 파일 이동 뒤 이력, 기록 누락)을 짧게 옮긴다.
- 대표 흐름: 방문자가 네 단계를 스크롤하며 대화에서 요구사항 도출, 기능별 요구사항·설계(`specs new`), 작업을 마친 뒤 에이전트의 커밋 제안과 허락 뒤의 커밋, 읽기 전용 브라우저를 본다. 넓은 화면에서는 오른쪽 고정 장면이 현재 단계로 바뀌고, 위로 스크롤하면 이전 단계로 돌아간다.
- 문서와 기록: 요구사항·설계와 결정기록 두 종류를 카드와 참조 관계도로 보여 준다. 설계의 `sources`는 근거로 삼은 저장소 문서(ID)나 외부 자료를 가리킬 수 있다.
- 아키텍처: `AGENTS.md`의 GITIFACT 블록이 언제 어떤 명령을 쓸지 알리고, 에이전트는 저장소의 실행기(`.gitifact/bin/cli.mjs`)로 `config.json`의 `cli` 버전을 사용자 캐시에 받아 실행한다. `.gitifact/spec/`과 `.gitifact/records/`는 Git 저장소에 있고, 커밋된 문서와 변경 이유는 트레일러로 Git 이력에 연결된다. 브라우저는 읽기 전용이다.
- 시각 방향: 짙은 녹흑 바탕, 연한 초록 포인트, 큰 한글 제목과 작은 고정폭 메타데이터. 제품의 파일·관계·시간을 선과 카드의 이동으로 표현한다. 움직임은 이해를 돕는 단계 전환에 집중한다.
- 상태: 현재 단계는 스크롤 위치로 정해지는 페이지 내부 상태이며 저장하지 않는다. 자동 재생은 없다. 줄임 동작 설정에서는 애니메이션과 전환 시간을 거의 0으로 줄이고 부드러운 스크롤을 끈다.
- 한계: 이 페이지의 스토리·도식은 설명용 예시이며 실제 프로젝트 데이터를 읽지 않는다. 실제 현황은 로컬 `gitifact browser`에서 본다.
