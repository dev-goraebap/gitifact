해결하려는 문제

코드는 Git에 남지만,
“왜 그렇게 만들었는가”는 대화창과 함께 사라집니다.

  • 세션 단절: 대화창이 닫히면 에이전트는 작성자의 의도와 구현 배경을 코드만 보고 다시 추론해야 합니다.
  • Git diff의 한계: 줄과 파일 단위로만 추적하므로, 문서 제목이 바뀌거나 위치가 이동하면 기존 맥락과의 연결이 끊어집니다.
  • 문서화의 피로: 별도의 문서 도구나 번거로운 관리 절차는 빠르고 유연하게 시도하는 개발 흐름을 가로막습니다.

참조 관계 규칙

화살표는 참조 방향을 나타냅니다. 프로젝트 지침은 개별 명세를 참조하지 않으며, 결정기록은 대상 문서를 가리키지만 문서는 결정기록의 존재에 종속되지 않습니다. 작성자와 작성 시점은 파일 본문이 아닌 Git 커밋 메타데이터로부터 파악합니다.

제목이 바뀌거나 경로가 이동해도 동일한 문서로 추적됩니다

일반 Git diff에서는 파일 삭제와 신규 생성으로 분리되는 변경도, CLI가 발급한 고유 ID가 유지되는 한 하나의 연속된 문서 이력으로 보존됩니다. 디렉터리 이동만으로 소속 기능이 자연스럽게 변경됩니다.

## 맥락

동일 고객이 두 개의 다른 이메일로 같은 요청을 남겨 수요가 이중 집계되었다. 이메일 기준 병합 시 동일인 식별이 불가능하다.

## 결정

동일 계정의 중복 요청을 단일 항목으로 집계한다. 세부 메시지 맥락은 병합된 요청 하위에 보존한다.

## 검토한 대안

- 이메일 주소 기준 병합 (다중 이메일 사용 고객을 개별 인입으로 오인할 위험)

작성 시점

기존 요구사항의 변경·삭제, 여러 대안 중 선택이 발생할 때 작성합니다. 단순 오타 수정이나 신규 문서 추가 시에는 불필요합니다.

일관된 형식

80자 이내의 명사형 제목과 섹션당 500자 이내의 분량을 권장합니다. 모든 기록은 동일한 3단 구조(맥락 · 결정 · 검토한 대안)를 유지합니다.

불변성

한 번 커밋된 기록은 수정하거나 삭제하지 않습니다. 새로운 결정이 내려지면 새 기록을 추가하며, 기존 기록 변조 시 RECORD_ALTERED로 커밋이 거부됩니다.

원자적 묶음

하나의 결정과 관련된 명세, 코드, 테스트, 결정기록을 단일 커밋으로 묶어 함께 보존합니다.

전체 구조

진입점(CLI/서버) — 도메인 규칙(Core) — 인프라 경계(Adapters)

CLI 명령과 로컬 서버는 입력을 검증하고 Core 유스케이스를 호출합니다. Core는 Git·파일 시스템·시스템 시간에 직접 의존하지 않고 추상화된 Port 인터페이스를 통해 통신하며, 인프라 세부사항은 Adapter 계층에서 구현합니다. 블록을 선택하여 세부 역할을 확인하세요.

    단일 진실 원천: 파일과 Git

    모든 데이터의 원본은 Git 이력과 Markdown 파일입니다. 캐시는 검색·조회를 돕는 파생물이며 삭제 시 언제든 안전하게 재생성됩니다.

    일관된 단일 검증 로직

    문서 및 기록 형식 검증 규칙은 Core 한 곳에 정의되어, docs check와 changes commit이 동일한 검증 파이프라인을 공유합니다.

    기계 가독형 오류 코드

    모든 오류는 언어 설정과 무관하게 표준화된 code를 반환하므로, 에이전트가 문자열 파싱 없이 정확히 분기할 수 있습니다.

    표시 언어와 저장 규약의 분리

    안내 문구는 한국어와 영어를 지원하지만, 저장 규약, ID 체계, JSON 데이터 스키마는 언어 설정에 영향받지 않는 독립 표준을 유지합니다.

    점진적 도입과 범위

    기존 프로젝트에도 부담 없이, 오늘부터 시작할 수 있습니다.

    기존 프로젝트

    과거 이력을 전부 정리할 필요 없이, 유지보수나 신규 기능이 추가되는 영역부터 점진적으로 정리합니다. 필요 시 에이전트에게 기존 코드를 분석하여 요구사항 초안을 도출하도록 요청할 수 있습니다.

    신규 프로젝트

    아이디어를 나누는 첫 대화부터 자연스럽게 시작합니다. 제품을 구체화해 나가는 동안 요구사항과 구현 설계가 함께 정리됩니다.

    적용 범위

    단일 저장소(단일 프로젝트 또는 모노레포) 기반의 제품 개발을 전제로 합니다. 도구의 복잡성을 낮추고 본질에 집중하기 위해 다중 저장소 간 연계는 범위에서 제외합니다.
