## 운영 지침

### 진입 페이지 README.md

제품이 무엇이고 누구를 위한 것인지, 원칙, 범위 밖을 적고 나머지 페이지로 가는 링크를 둔다. 기술 구조나 개별 요구사항의 세부는 다른 페이지와 기능 명세의 몫이므로 여기에 반복하지 않는다. 없으면 브라우저는 위키가 비어 있다고 보여 준다. 사용자가 원하면 대화에서 파악한 내용으로 첫 페이지를 만든다. `init`은 위키를 만들지 않는다.

### 나머지 페이지

폴더 구조는 정하지 않는다. 목적별로 나누고 페이지는 필요할 때 만든다.

| 목적 | 예 |
| --- | --- |
| 왜·누구를 위해 | README.md |
| 어떻게 만드는가 | architecture.md, data-flow.md |
| 지킬 규칙 | conventions/code-style.md, conventions/naming.md |
| 공통 어휘·결정 | glossary.md, decisions/ |

한 페이지는 한 주제만 다룬다. 결정과 이유를 쓰고 날짜별 작업 기록은 두지 않는다. 기능별 동작은 명세에 두고 위키에 반복하지 않는다.

### 에이전트 행동

- 요구사항·설계를 쓰기 전에 README.md와 작업 영역에 맞는 페이지를 읽는다. 어떤 페이지가 관련되는지는 폴더·제목으로 판단한다. 별도 포함 규칙은 두지 않는다.
- 대화에서 기준이 새로 생기거나 바뀌면 해당 페이지를 고치자고 제안한다. 사용자가 동의하면 `spec save`로 저장하고 커밋 때 이유를 붙인다.
- 기존 폴더 안에 페이지를 더하는 것은 진행하고 알린다. 새 최상위 폴더나 README.md의 구조 변경은 사용자와 정한 뒤 한다.
- 요청이 README.md의 범위 밖이거나 원칙과 어긋나면 진행 전에 알린다. 규칙 페이지와 어긋나는 설계는 문서를 먼저 고칠지 사용자와 정한다.
